## 壊れている箇所（重大度順）

### B-1【最重大】再クロールの結果が、見ている画面とは別のサイトに書き込まれる

**症状**
`/sites/demomart/changes` で「再クロール」を押すと、クロール自体は成功するが、成果物が `output/127.0.0.1:8766/` に書かれる。demomart の変更一覧は**何度押しても永久に「基準なし」のまま**。ユーザーから見ると「押しても何も起きないボタン」であり、同時に一覧の別サイトが勝手に更新される。

**再現手順**
1. `/sites/demomart/changes` を開く（「比較の基準となる前回のクロールがありません」と表示）
2. 右上「再クロール」をクリック
3. 完了を待ってから drift を確認する

**証拠**
- クリック前後の mtime: `output/demomart/report.json` = `Aug 30 18:38:42`（**不変**） / `output/127.0.0.1:8766/report.json` = `Aug 30 18:46:16` → `Aug 30 18:49:46`（**更新**）
- `GET /api/ta2/drift?domain=demomart` → `{"baseline_at":"","current_at":"","items":[],"reason":"比較の基準となる前回のクロールがありません"}`
- `GET /api/ta2/drift?domain=127.0.0.1%3A8766` → `{"baseline_at":"2026-08-30T18:46:16","current_at":"2026-08-30T18:49:46","items":[]}` ← **demomart で押した操作の結果がここに入っている**
- スクリーンショット: `.playwright-mcp/20-recrawl-start.png` `21-recrawl-end.png`（「クロール中…」のまま、その後も基準なし）

**推定原因**
`web/routes/ta2.py:765-784` `api_ta2_recrawl()` は `domain`（= `demomart`）を `start_crawl_job(domain, url, …)` に渡すが、実際の出力先を決めるのはクローラ CLI 側で、**URL のホスト名から作り直している**:

- `src/main.py:1572-1573`
  ```python
  domain = _domain_name(str(args.url))
  out_dir = Path(args.output) / domain
  ```
  （同じパターンが `src/main.py:402, 446, 488, 516, 541, 589` にもある）

`start_crawl_job` は `--output <テナントルート>` しか渡さないため（`web/services/job_queue.py:139-140`）、呼び出し側の `domain` ラベルは出力先に一切効かない。ディレクトリ名 ≠ ホスト名のサイト（エイリアス）はすべてこの経路で壊れる。

**副次的な壊れ方（同一原因）**
`output/demomart/` には `site.json` と `snapshots/` と `drift_summary.json` が**存在しない**。一方 `output/demomart/runs/20260830-184946/` にはクロール成果物（`meta.json` `report.json` 等）が残っており、成果物が 2 か所に割れている。

### B-3【中】全画面で恒常的にコンソールエラー（405 HEAD /api/ta2/tests/resync）

**症状**
ホーム・仕様・テスト・変更・定期実行・報告・チームの**全 7 画面 × 両解像度 = 14 回すべて**でコンソールに `Failed to load resource: the server responded with a status of 405 (METHOD NOT ALLOWED)` が出る。DevTools を開いた買い手・情シスに「常時エラーが出る製品」と見える。

**証拠**
`.playwright-mcp/r3.json` の各画面 `errs` / `net` に `405 HEAD /api/ta2/tests/resync`。`r2.json` `r4.json` `r6.json` `r7.json` でも再現。

**推定原因**
- `static/js/ta2/ws-resync.js:19-23` がルート存在確認に `fetch(URL_RESYNC, { method: 'HEAD' })` を使い、`res.status !== 404` で「実装あり」と判定する
- `web/routes/ta2.py:324` は `@bp.post("/api/ta2/tests/resync")` で **POST のみ**許可 → HEAD は 405

判定ロジック自体は 405 ≠ 404 なので偶然「実装あり」になりボタンは出る（機能は動く）が、毎ページで無害でないログを撒く。存在確認を HEAD 以外（例: 既存の一覧 API の応答に機能フラグを載せる）に変えるか、ルートに HEAD を許可する必要がある。
