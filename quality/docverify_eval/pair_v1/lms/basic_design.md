# 社内研修 学習管理システム 基本設計書
## 1 概要
### 1.1 目的
本書は、社内研修 学習管理システム要件定義書の内容を実現する基本設計を定める。

### 1.2 システム構成
- 利用者はブラウザから Web アプリケーションへ接続する。
- Web アプリケーションは社内サーバ上で稼働し、データベースに受講情報を保存する。
- 認証は社内のシングルサインオンに委ねる。
- 動画教材は社内の配信サーバから配信する。
### 1.3 利用者と権限
| 利用者 | 主な権限 |
| --- | --- |
| 受講者 | コース検索、申込、視聴、テスト受験、履歴閲覧 |
| 上長 | 部下の受講状況の閲覧 |
| 管理者 | コース管理、修了証の再発行、受講履歴の出力 |

## 2 画面設計
### 2.1 画面一覧
| 画面ID | 画面名 | 利用者 |
| --- | --- | --- |
| SCR-01 | コース一覧 | 受講者 |
| SCR-02 | コース詳細・申込 | 受講者 |
| SCR-03 | 教材視聴 | 受講者 |
| SCR-04 | 確認テスト | 受講者 |
| SCR-05 | 受講履歴 | 受講者 |
| SCR-06 | 部下の受講状況 | 上長 |
| SCR-07 | コース管理 | 管理者 |
| SCR-08 | 受講履歴出力 | 管理者 |
| SCR-09 | 受講アンケート | 受講者 |
| SCR-10 | 受講者ランキング | 受講者 |

### 2.2 コース一覧(SCR-01)
- 検索条件は、コース名(部分一致)と受講区分とする。
- 検索結果は1ページ20件で表示し、ページ送りを設ける。
- 各行にコース名、受講区分、開講日、定員、申込状況を表示する。
### 2.3 コース詳細・申込(SCR-02)
- コースの概要と開講日、受講期限を表示する。
- 「申込」ボタンは、開講日の3営業日前の日付を過ぎると無効にする。
- 「取消」ボタンは、開講日の前日の日付を過ぎると無効にする。
- 定員に達している場合は、「待機で申込」ボタンを表示する。
### 2.4 教材視聴(SCR-03)
- 動画プレーヤーに再生位置のバーを表示する。
- 画面を開き直したときは、前回に停止した位置から再生を始める。
- 視聴済みになった動画には、完了の印を表示する。
### 2.5 確認テスト(SCR-04)
- 全ての動画教材が視聴済みのときだけ、「テスト開始」ボタンを有効にする。
- 結果画面に得点、合格点、合否、残りの受験回数を表示する。
### 2.6 受講履歴(SCR-05)と部下の受講状況(SCR-06)
- SCR-05 は、ログインした受講者の履歴を新しい順に表示する。
- SCR-06 は、上長の部下を一覧で表示し、コースごとの受講状況コードを並べる。
### 2.7 コース管理(SCR-07)
- 入力項目は、コース名、受講区分、開講日、定員、受講期限、教材とする。
- コース名は全角50文字以内で入力させる。
- 登録済みコースは一覧から選び、編集する。
### 2.8 受講履歴出力(SCR-08)
- 出力期間と受講区分を指定し、「CSV出力」ボタンで出力する。
### 2.9 受講アンケート(SCR-09)
- 修了した受講者に、修了後の画面から案内する。
- 回答画面に氏名や社員番号を表示しない。
### 2.10 受講者ランキング(SCR-10)
- 修了したコース数の多い順に、受講者の上位20名を表示する。
- 順位は月初に集計し直す。
## 3 機能設計
### 3.1 コース検索(REQ-001)
- 検索条件を受け取り、公開中のコースを抽出する。
- 並び順は開講日の昇順とする。
### 3.2 コース登録・編集(REQ-003)
- 管理者だけが実行できる。
- 開講日は登録日以降の日付に限る。
- 編集の内容は保存と同時に一覧へ反映する。
### 3.3 受講申込
- 申込は、開講日の3営業日前の日付の23時59分まで受け付ける。
- 営業日は、会社の休業日カレンダーに登録された休業日を除いた日とする。
- 受付時に受講状況コードを10(申込済)にする。
### 3.4 待機と繰り上げ
- 申込時に定員に達している場合は、受講状況コードを20(待機)で登録する。
- 取消で空きが出たときは、待機の申込を申込日時の古い順に並べ、先頭から繰り上げる。
- 繰り上げた受講者へメールで通知する。
### 3.5 申込の取消(REQ-011)
- 取消は、開講日の前日の日付の23時59分まで受け付ける。
- 取消した申込の受講状況コードを90(取消)にする。
### 3.6 申込内容の変更通知
- 申込内容が変更されたときは、変更から5分以内に、管理者の共有メールアドレスへ変更前後の内容を送る。
### 3.7 動画の視聴管理(REQ-005)
- プレーヤーは10秒ごとに再生位置を保存する。
- 動画の再生割合が80%以上になった時点で、その動画を視聴済みにする。
- 再生位置の保存値は、再開時の開始位置に使う。
### 3.8 確認テスト(REQ-006)
- 受験できるのは、受講する全ての動画教材が視聴済みの受講者に限る。
- 受験回数は1コースにつき5回までとし、超える受験は拒否する。
- 得点を受講区分マスタの合格点と比べ、合否を判定する。
### 3.9 修了判定と修了証(REQ-007)
- 得点が合格点以上のとき、受講状況コードを40(修了)にする。
- 修了と同時に、修了証をPDFで生成し、受講者がダウンロードできるようにする。
- 管理者は、受講履歴から修了証の再発行を指示できる。再発行した修了証明書には、再発行日を記載する。
### 3.10 受講アンケート
- 回答は、受講者を特定する項目を保存せずに記録する。
- 集計は、コース単位の件数と選択肢別の割合で行う。
### 3.11 期限通知(REQ-008)
- 毎日午前9時に、受講期限が7日後のコースを抽出する。
- 受講状況コードが40(修了)でない受講者へ、メールを送る。
### 3.12 受講状況の閲覧(REQ-009、REQ-012)
- 上長は、人事マスタで自分を上長とする社員の受講状況を閲覧できる。
- 受講者は、自分の履歴だけを閲覧できる。
### 3.13 受講履歴の出力(REQ-010)
- 管理者が指定した期間と受講区分の履歴を、CSVファイルとして出力する。
- 文字コードは UTF-8(BOM 付き)とし、1行目に項目名を出力する。
### 3.14 受講者ランキング
- 修了のコース数を受講者ごとに数え、多い順に並べる。
- 同数のときは、直近の修了日が新しい受講者を上位にする。
### 3.15 社員情報の取り込み
- 毎日午前2時に、人事マスタから社員番号、氏名、所属部署、上長の社員番号を取り込む。
## 4 データ設計
### 4.1 受講区分マスタ
| 区分コード | 区分名 | 合格点 |
| --- | --- | --- |
| NEW | 新入社員 | 70 |
| GEN | 一般社員 | 80 |
| MGR | 管理職 | 75 |

### 4.2 研修コース(t_course)
| 項目名 | 型 | 桁 | 必須 | コード値 |
| --- | --- | --- | --- | --- |
| course_id | 数値 | 10 | 必須 | 連番 |
| course_name | 文字列 | 全角100 | 必須 |  |
| level_code | 文字列 | 3 | 必須 | NEW、GEN、MGR |
| start_date | 日付 | 8 | 必須 |  |
| capacity | 数値 | 4 | 必須 |  |
| due_date | 日付 | 8 | 必須 |  |
| published_flag | 文字列 | 1 | 必須 | 0:非公開、1:公開 |

### 4.3 受講申込(t_entry)
| 項目名 | 型 | 桁 | 必須 | コード値 |
| --- | --- | --- | --- | --- |
| entry_id | 数値 | 12 | 必須 | 連番 |
| course_id | 数値 | 10 | 必須 |  |
| employee_no | 文字列 | 8 | 必須 |  |
| status_code | 文字列 | 2 | 必須 | 10:申込済、20:待機、30:受講中、40:修了、90:取消 |
| entry_at | 日時 | 14 | 必須 |  |
| best_score | 数値 | 3 | 任意 |  |
| test_count | 数値 | 1 | 必須 |  |

### 4.4 データの保持
- 受講申込と受講結果は、削除せずに保持する。
- 監査ログは、記録から1年を過ぎたものを月次で削除する。
## 5 外部インタフェース
### 5.1 インタフェース一覧
| 連携先 | 方式 | 頻度 | 内容 |
| --- | --- | --- | --- |
| 人事マスタ | ファイル連携 | 1日1回 | 社員番号、氏名、所属部署、上長 |
| 社内SSO | SAML 2.0 | ログイン時 | 利用者の認証 |
| 社内メールサーバ | SMTP | 随時 | 期限通知、繰り上げ通知、変更通知 |

### 5.2 連携の失敗時
- 人事マスタの取り込みに失敗したときは、前回の取り込み結果を使い続け、管理者へメールで知らせる。
- メールの送信に失敗したときは、10分後に1回だけ再送する。
## 6 非機能設計
### 6.1 性能
- コース一覧と受講履歴の検索には、course_id と employee_no にインデックスを設ける。
- 負荷試験は同時接続500ユーザーで実施し、95パーセンタイルで3秒以内を確認する。
### 6.2 可用性
- Web アプリケーションは2台で冗長化し、稼働率は月間99.5%以上を目標とする。計画停止は稼働率の計算から除く。
### 6.3 セキュリティ
- 受講申込、取消、テスト受験、修了証発行の操作ログを監査ログとして記録する。
- 通信はすべて TLS で暗号化する。
- 修了証のPDFと受講履歴のCSVは、社外のサービスへ送らない。
### 6.4 バックアップ
- データベースの全体バックアップを毎日午前3時に取得し、30世代を保管する。
### 6.5 動作環境
- 対応ブラウザは、Chrome と Edge の最新2世代とする。
- 受講期限と開講日の判定は、日本時間の暦日で行う。
### 6.6 使いやすさ
- 全画面で共通のレイアウトとメニューを用いる。
