# 保険金請求受付システム 要件定義書

## 1 目的・範囲

### 1.1 目的

本システムは、保険契約者や被保険者からの保険金の請求を受け付ける業務を、紙と電話による運用から画面による運用へ置き換える。
受付担当者が請求内容を漏れなく登録し、不備を早期に発見し、審査システムへ確実に引き渡すことを目的とする。

### 1.2 範囲

- 範囲に含むもの: 請求の登録、添付書類の登録、不備の記録と通知、受付票の出力、状況の照会、請求の検索、取消、操作履歴の記録
- 範囲に含まないもの: 保険金の査定、支払の計算、契約内容の変更、保険料の収納

### 1.3 利用者

- 受付担当者: 請求の登録と照会を行う。コールセンターと事務センターに在籍する
- 上長: 受付担当者の業務を監督し、取消を承認する

### 1.4 前提

- 請求の受付は平日の日中に行い、夜間と休日の受付は対象としない
- 請求者との連絡手段は、電話とメールとする
- 紙の書類は、受付担当者がスキャンして添付する

## 2 用語

| 用語 | 意味 |
| --- | --- |
| 請求者 | 保険金を請求する人。契約者、被保険者、またはその代理人 |
| 被保険者 | 保険の対象となる人 |
| 保険証券番号 | 契約を特定する数字10桁の番号 |
| 受付番号 | 請求1件を特定するため、受付時に付ける番号 |
| 受付担当者 | 請求を登録する社内の担当者 |
| 上長 | 受付担当者を監督し、取消を承認する社内の責任者 |
| 不備 | 請求に必要な書類や記載が足りない、または誤っている状態 |
| 不備通知 | 不備の内容を請求者へ知らせる連絡 |
| 受付票 | 受け付けた請求の内容を記載した帳票 |
| 審査システム | 受け付けた請求を審査する既存の社内システム |

## 3 機能要件

### 3.1 請求の登録

- REQ-001 受付担当者は、請求者からの保険金の請求を新規に登録できること。
- REQ-002 登録するとき、保険証券番号で契約を照会し、契約が有効でない場合は登録を拒否すること。
- REQ-003 請求区分は、入院、通院、死亡、後遺障害の4区分から1つを選択すること。
- 事故日が契約の保険期間の外にある場合は、登録を拒否すること。
- REQ-004 登録に成功したときは、受付番号を自動で付けること。形式は「CL」、西暦4桁、連番6桁とする。
- REQ-005 請求者の氏名（カナ）、生年月日、電話番号を必須入力とすること。

### 3.2 添付書類

- REQ-006 診断書や領収書などの添付書類を、請求1件につき最大10点まで登録できること。
- 添付できるファイルは、PDF、JPEG、PNGの3形式とし、1点あたり5MB以内とすること。

### 3.3 不備対応

- REQ-007 受付担当者は、書類に不備があるとき、不備の内容を記録できること。
- 不備を記録した場合は、不備通知を速やかに請求者へ送付すること。

### 3.4 受付後の処理

- REQ-008 受け付けた請求を、審査システムへ連携すること。
- 請求内容の訂正は、審査システムへ連携する前に限り可能とすること。
- REQ-009 受付票をPDFで出力できること。
- 受付が完了したときは、請求者へ受付完了メールを送信すること。
- 同じ被保険者、同じ事故日、同じ請求区分の組み合わせで既に受け付けた請求がある場合は、二重請求の疑いとして警告を表示すること。

### 3.5 照会・取消・権限

- REQ-010 受付番号を指定して、請求の状況を照会できること。状況は表1の4種とする。

表1 請求の状況

| 状況 | 状況コード | 意味 |
| --- | --- | --- |
| 受付中 | 01 | 登録が完了し、不備が無い |
| 不備対応中 | 02 | 不備が記録され、解消を待っている |
| 審査待ち | 03 | 審査システムへ連携済み |
| 取消 | 09 | 取消が承認された |

- 取消は、上長が承認した場合に限り実行できること。
- REQ-011 受付日、請求区分、状況を条件に、請求を検索して一覧で表示できること。
- 操作の権限は表2のとおりとする。

表2 操作の権限

| 操作 | 受付担当者 | 上長 |
| --- | --- | --- |
| 登録 | 可 | 可 |
| 訂正 | 可 | 可 |
| 取消の承認 | 不可 | 可 |
| 照会 | 可 | 可 |

- REQ-012 登録、訂正、取消の操作について、操作の履歴を記録すること。

## 4 非機能要件

### 4.1 可用性

- REQ-013 平日の8時から20時までの稼働率を99.5%以上とすること。

### 4.2 セキュリティ

- REQ-014 通信はTLS1.2以上で暗号化し、保存する個人情報も暗号化すること。

### 4.3 保存

- REQ-015 受付データは10年間保存すること。
- 操作履歴は3年間保存すること。

### 4.4 性能・操作性

- REQ-016 同時に50人が利用できること。
- 画面は使いやすく、十分な応答性能を有すること。

## 5 制約

- 契約の照会は、既存の契約管理システムが提供する照会機能を使うこと。
- 審査システムは既存のものを使い、本システムからは請求の連携だけを行うこと。
- 利用者の端末は社内に設置したパソコンとし、Webブラウザで利用すること。
- 本書の内容は架空のものであり、実在の保険商品や会社とは関係が無い。
