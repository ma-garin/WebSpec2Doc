画面解析の範囲指定 — デザイン案

対象: ステップ1「解析対象 URL」（templates/partials/view-generate.html:30-53）。バックエンドは既に depth / max_pages 対応済みのため、変更は画面と wizard.js:373 のみ。

推奨は案A。 「1画面のみ」が1クリックで押せ、深さ指定も同じ場所で完結し、既定を安全側（標準）に置けるため。 案B は深さしか変えられず「1画面のみ」を max_pages で表現できない。案C は常時2入力が出て、数値の意味を知らない利用者に判断を強いる。

現状（比較用）

現状 — 範囲を指定する手段が無い

⏱ 目安: 1画面あたり約2〜3秒（10画面で30秒前後）

実際には depth=5 / max_pages=300 が固定で渡る → 300画面・約15分30秒。利用者は止める以外に手が無い。

案A（推奨）— プリセット＋カスタム

案A
解析する範囲
この1画面のみ 1画面 / 約3秒 標準 深さ2 / 最大30画面 / 約1分 広め 深さ5 / 最大300画面 / 約15分 カスタム
見込み: 最大30画面・約1分（1画面2.4秒の実測値から算出）

「カスタム」を選んだときだけ数値入力を表示。プリセット選択中は入力欄を畳んで、数値を読まずに決められるようにする。

案B — 深さスライダー＋1画面チェック

案B

見込み: 深さ2・最大30画面・約1分

最大ページ数を出さないぶん簡潔。ただし深さ2でもリンクが多いサイトでは画面数が読めず、上限を止められない。

案C — 数値2つを常時表示

案C
解析する範囲
見込み: 最大30画面・約1分

実装は最小。ステップ2「自動で辿る」の既存UI（#crawl-depth / #max-pages）と見た目が揃う。

あわせて決めていただきたいこと

既定値を depth=5 / max_pages=300 のまま残すか、depth=2 / max_pages=30（＝API既定値）へ下げるか。
  • 下げる場合: 初回の待ちが約15分 → 約1分になる。ただし「以前は全部拾えていたのに拾わなくなった」と見える可能性がある
  • 残す場合: 挙動は変わらないが、範囲指定を足しても既定のままEnterした人は15分待つ
推奨は下げる。300画面を既定にする根拠が実装側に無く（wizard.js:373 のハードコード）、API側の既定は 2/30 のため、そちらに揃うほうが一貫する。
