# 月極駐車場 契約・請求管理システム 要件定義書

## 1. 目的・範囲

### 1.1 目的

- 月極駐車場を運営する管理会社が、契約と毎月の請求を一元管理し、契約の更新漏れと請求漏れを無くす。
- 入金の確認作業を自動化し、経理担当者の月次の事務作業時間を現状の半分以下にする。
- 滞納の発生から督促までの流れを統一し、担当者による対応のばらつきを無くす。

### 1.2 範囲

- 対象: 区画の登録、契約の締結・更新・解約、月額使用料の請求、入金消込、滞納の督促。
- 対象外: 入出庫ゲートの制御、契約者向けスマートフォンアプリ、会計システムへの仕訳連携。
- システム利用者: 管理者と経理担当者。契約者はシステムへログインしない。

### 1.3 想定する規模

- 管理する区画は最大 2,500 区画とする。
- 同時に有効な契約は最大 2,000 件とする。
- システム利用者は 10 人以下とし、同時に操作するのは 5 人以下とする。
- 請求は月 1 回とし、毎月 1 日を請求日とする。
- 契約者の数は最大 2,000 人とする。

### 1.4 関係者

| 役割 | 担当 | 主な関わり |
|---|---|---|
| 管理者 | 管理会社の担当者 | 区画・契約・督促の運用 |
| 経理担当者 | 管理会社の経理 | 請求の確認と入金消込 |
| 契約者 | 区画を借りる個人または法人 | 書類の受領と銀行振込 |
| 情報システム担当 | 管理会社の情報システム部門 | 稼働環境の維持 |

## 2. 用語

| 用語 | 意味 |
|---|---|
| 区画 | 駐車場内で貸し出す 1 台分の駐車スペース |
| 契約者 | 区画を借りる個人または法人 |
| 月額使用料 | 契約者が毎月支払う区画の利用料金（税込） |
| 請求書 | 月額使用料を契約者へ通知する書類 |
| 入金消込 | 入金明細を請求書と突き合わせて入金済みにする処理 |
| 滞納 | 支払期限の翌日になっても入金が確認できない状態 |
| 保証金 | 契約の締結時に契約者が預ける金銭 |
| 更新案内 | 契約の満了前に更新の意思を確認する案内状 |

- 本書で使う用語は、基本設計書でも同じ語を使う。
- 金額は特に断りが無い限り税込とし、消費税率は 10% とする。

## 3. 機能要件

- 要件 ID が付いた項目と付いていない項目がある。いずれも同じ重みで扱う。

### 3.1 区画と契約

- REQ-001 管理者は区画を登録できること。区画には区画番号・区画種別・月額使用料・状態（空き・契約中・停止中）を持たせる。
- REQ-002 区画種別は平置き・機械式・大型の 3 種とし、月額使用料の標準額は次の表のとおりとする。

| 区画種別 | 標準の月額使用料 | 車両の上限高 |
|---|---|---|
| 平置き | 12,000円 | 2.0m |
| 機械式 | 9,000円 | 1.55m |
| 大型 | 18,000円 | 2.5m |

- REQ-003 管理者は契約者を登録でき、氏名または法人名・住所・電話番号・メールアドレスを保持する。
- 管理者は空きの区画に対して契約を新規に締結でき、契約開始日は登録日の翌日以降とする。
- 1 つの区画に同時に有効な契約は 1 件までとし、期間が重なる契約は登録できないこと。
- REQ-004 契約期間は原則 1 年とし、契約満了日の 60 日前に更新案内を契約者へ郵送する。
- REQ-005 契約を更新するとき、管理者は新しい月額使用料を設定できる。変更後の月額使用料は更新後の契約期間の初日から適用する。
- 契約者は解約希望日の 30 日前までに申し出ることで解約でき、解約日は月末とする。
- REQ-006 契約の締結時に、契約者は月額使用料の 2 か月分の保証金を預け、管理者は預かった保証金の額を記録する。
- REQ-007 解約時には、保証金から未払いの月額使用料を差し引いた額を返還額として算出し、返還の実績を記録する。

### 3.2 請求と入金

- REQ-008 毎月 1 日に、有効な契約すべての請求書を自動で作成する。請求書には請求番号・契約者・区画・請求金額・支払期限を記載する。
- 請求書の支払期限は請求月の末日とする。
- REQ-009 管理者は作成済みの請求書を PDF で出力でき、郵送用の宛名ラベルも出力できる。
- REQ-010 経理担当者は銀行の入金明細ファイル（CSV）を取り込み、請求書と照合して入金消込を行える。
- 入金額が請求金額に満たない場合は一部入金として記録し、残額は同じ請求書の未払額として残す。
- REQ-011 入金消込で請求書と一致しなかった入金明細は未照合一覧に表示し、経理担当者が手作業で請求書に紐付けられる。

### 3.3 督促と照会

- REQ-012 支払期限の翌日に入金が確認できない請求書は滞納とし、次の表の段階に従って督促を行う。

| 段階 | 経過日数 | 対応 |
|---|---|---|
| 1 | 期限の翌日から 7 日 | 督促メールを送付 |
| 2 | 8 日から 29 日 | 督促状を郵送 |
| 3 | 30 日以上 | 契約解除の検討を管理者へ通知 |

- 督促に応じない契約者について、必要に応じて保証人等へ適切に連絡する。
- REQ-013 管理者は契約一覧と滞納一覧を画面で検索でき、結果を CSV で出力できる。
- REQ-014 契約・請求・入金に関する操作は、操作日時・操作者・対象を操作履歴として記録する。

## 4. 非機能要件

### 4.1 性能

- REQ-015 請求書の一括作成は、契約 2,000 件に対して 5 分以内に完了すること。
- REQ-016 入金明細 1,000 行の取込と照合は、30 秒以内に完了すること。

### 4.2 セキュリティ

- REQ-017 ログインはシステム利用者ごとの ID とパスワードで行い、契約者情報を変更できるのは管理者のみとすること。

### 4.3 使いやすさ

- 画面は使いやすく、誰でも直感的に操作できること。

### 4.4 可用性と保守

- 保存するデータは毎日 1 回バックアップし、障害時は前日の状態まで復旧できること。
- 稼働時間は平日の 8 時から 20 時とし、この時間帯の可用性は 99.5% 以上とすること。

## 5. 制約

- システム利用者の端末は Windows 11 上の Edge または Chrome の最新版とする。
- 初期の契約データは既存の Excel 台帳から移行する。移行作業は本システムの範囲に含めない。
- 消費税率は 10% とし、月額使用料は税込金額で保持する。
- 月額使用料の支払方法は銀行振込のみとする。
