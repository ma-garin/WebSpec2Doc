## 勝つための示唆
1. リンクは「候補＋根拠（該当箇所の引用）＋信頼度」で出し、確定は人（根拠: 2511.02434 は F1 0.81〜0.87 止まり＝残りの誤りは人が拾う必要がある）。
2. 「完全率」を単一の数値として断定表示しない。算出方法（分母＝上流要件数、対応判定の閾値）を明示し、区間または「要確認」件数を併記（根拠: 2604.16383 は LLM の完全性判定が偶然水準に近い例。ドメインは異なる）。
3. 埋め込み検索で候補を絞り、LLM で判定する 2 段にし、判定は項目単位で再現可能に（根拠: 2509.20149 は LLM 拡張＋エンコーダ改良で大幅向上と主張、2601.11688 は階層化でコスト 8 割減と主張）。
4. 自動の網羅指標（TF-IDF・埋め込み）だけを品質根拠にしない。人手評価と乖離しうる（根拠: 2607.01980 で自動 94.3% 対 92.9% の差は小さく、専門家の Completeness は 4.31 対 3.50 と差が大きい）。
5. 日本語・要件→基本設計→テストの 3 段での精度は公開根拠が見つからなかったため、自社ベンチマーク（実顧客文書の匿名化サンプルで人手正解を作成）を持ち、数値を自前で出す（根拠: 上記全論文が英語またはコード対象。日本語は未確認）。

## 引用してはいけない数値
- 2509.20149 の「+28.59% F1」: 相対/絶対の別、ベースライン、P/R が abstract から不明。本文未確認。
