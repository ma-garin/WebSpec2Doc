## 1. はじめに

### 1.1 本システムでできること

WebSpec2Doc は、**Webサイトの URL を入力するだけで、そのサイトの仕様書とテスト設計資料を自動生成する**ツールです。具体的には次を自動で作成します。

- 画面一覧・画面遷移図（どんな画面がいくつあり、どうつながっているか）
- 入力項目仕様（フォームのフィールド・型・必須可否）
- スクリーンショット付きレポート（HTML/PDF）
- テスト観点・テストケース（品質観点、境界値、ペアワイズ、状態遷移など）
- AutoRun による自動テスト実行と、検収提出用の実施証跡
- 前回との仕様差分（仕様ドリフト）の検知

これらは3つの独立したシステムとして提供されます。どのシステムを使うかは、ログイン後の「システム選択」画面（4章）で選びます。

| システム | 何をするか |
|---|---|
| System 01 ドキュメント作成 | URLから画面仕様書・遷移図・項目定義を生成する（本書5章） |
| System 02 AutoRun | クロールからテスト設計・実行・証跡作成までを自動で行う（本書6章） |
| System 03 CLIモード | 画面を持たず、端末（コマンドライン）から同じ機能を使う。CI・定期実行向け |

### 1.2 対象読者

- QA担当者・テスト設計担当者（画面仕様の把握、テストケース作成）
- 開発者（実装済み画面の仕様確認、AutoRunでの回帰確認）
- プロジェクト管理者（テスト計画・進捗の把握）
- システム管理者（9章「管理者向け操作」を参照）

### 1.3 前提知識

プログラミングの知識は不要です。画面の指示に沿って URL を入力し、ボタンを押すだけで基本的な操作が完結します。ただし、System 03「CLIモード」を使う場合はコマンドライン操作の基礎知識が必要です。本書は画面操作を中心に扱い、CLIモードの詳細はシステム選択画面から遷移する案内ページ（画面ID: SC-12）、および `docs/userguide.md` の「CLIで使う」章を参照してください。

### 1.4 動作環境

- 本製品は **PC（デスクトップ・ノートPC）専用** です。モバイル・タブレットでの利用は想定されておらず、対応する表示・操作は存在しません。
- 操作は Web ブラウザから行います。対応ブラウザの正式な一覧は本書執筆時点で **未確認** です。
- 対象サイトを解析するには、そのサイトへの HTTP/HTTPS 到達性が必要です。社内ネットワーク限定のサイトを解析する場合は、WebSpec2Doc 自体を同じネットワーク内（または到達可能な環境）で稼働させる必要があります。具体的なネットワーク要件・推奨スペックは **未確認** のため、運用手順書 `WS2D-OP-001` を参照してください。
- ローカル・プライベートアドレス（`localhost` 等）を解析対象にする場合は、8章の設定で明示的に許可する必要があります（既定では SSRF 対策により拒否されます）。

## 2. 用語の説明

本システムを操作するうえで最低限必要な用語のみ、ここに掲載します。より詳しい用語集は `WS2D-GL-001_用語集.md` を参照してください。

| 用語 | 説明 |
|---|---|
| サイト | 解析対象として登録した1つのWebシステム。URL（ドメイン）で識別されます |
| ワークスペース（テナント） | 成果物・実行履歴・観点セットをチーム／プロジェクト単位で分離する作業単位。ログイン後に選択します |
| 利用者ログイン | **WebSpec2Doc自体**にログインすること。次の「ログイン」とは別の概念です |
| ログイン（対象サイトへの） | WebSpec2Docが**解析対象サイト**へ自動ログインすること。パスワードは即破棄され保存されません |
| 画面分析（ページ解析） | クロール本番の前に、対象サイトの到達ページ一覧を軽く先読みする工程 |
| オートクローリング | 起点URLからリンクをたどり、到達ページを自動収集すること（本ツールの基本動作） |
| 再クロール | 登録済みサイトを、保存済み設定で取り直すこと。前回との差分検知の起点になります |
| 仕様ドリフト | 前回クロール時と今回とで、画面・フォーム・遷移などが変化していること |
| 観点（viewpoint） | テスト設計における着眼点・確認すべき性質の単位 |
| テストケース | 観点を、前提条件・手順・期待結果まで具体化した実行可能な単位 |
| ロール | 利用者の権限区分。「一般」と「管理者」の2種類（ワークスペースごとに設定） |
| AutoRun | クロールからテスト設計・実行・証跡作成までを通しで自動実行する機能 |
| メンバーシップ | 利用者とワークスペースの所属関係。所属ごとにロールを持ちます |

## 3. 画面共通の操作

すべての画面（ログイン後）は、左の**サイドバー**と上部の**トップバー**、中央の**コンテンツ領域**から構成されます。

- **サイドバー**: 機能（ダッシュボード、サイトを追加、AutoRun、実行履歴、品質観点、観点管理、設定 など）を切り替えるナビゲーションです。
- **トップバー**: 現在位置（パンくず）、**クイック検索**（キーボードの `⌘K`。画面・サイトを横断して検索）、テーマ切替（ライト/ダーク）、認証が有効な場合はログイン中ユーザーのアバターを表示します。
- **エラー表示の見方**: 通信エラーや対象なしの場合、画面には「空の状態」「読み込み中（ローディング）」「エラー＋再試行」のいずれかが統一した見た目で表示されます。エラー表示の多くには「再試行」の導線が付きます。「測って結果が0件だった」場合と「そもそも測る対象がない」場合は見た目上区別されます。
- **処理中の表示**: クロールなど時間のかかる処理は、進捗が段階的に（例: 受付→ページ取得→解析→結果整理）画面上にリアルタイム表示されます。処理中に画面を離れて戻っても、直前の実行状態が正しく引き継がれます。
- **ログアウト**: 各画面のトップバー（またはシステム選択・テナント選択などの認証系画面の上部）にある「**ログアウト**」ボタンから行います。

## 4. 初回セットアップ

初めて利用する際は、次の順に進みます。**アカウント作成 → ログイン → ユーザー選択 → テナント選択 → システム選択**。この順序は固定されており、システム選択画面に到達するまでは他の画面（ダッシュボード等）には入れません。

### 4.1 アカウントを作る

#### 4.1.1 組織で最初の利用者になる場合（画面ID: SC-02、`/auth/setup`）

まだ誰もアカウントを作成していない場合にのみ表示される画面です。

1. ブラウザで WebSpec2Doc の URL を開くと、見出し「**初期セットアップ**」の画面が表示される
2. 「**ワークスペース名（組織・チーム名）**」「**表示名**」「**メールアドレス**」を入力する
3. 「**パスワード**」を入力する（10文字以上。メールアドレスと同一のものは使用不可、と画面上にヒントが表示される）
4. 「**パスワード（確認）**」に同じパスワードを再入力する
5. 「**ワークスペースを作成**」ボタンを押す
6. 次に表示されるのは4.3の「ユーザー選択」画面

#### 4.1.2 既存の組織に2人目以降として参加する場合（画面ID: SC-03、`/auth/signup`）

1. ログイン画面（4.2）の「新規登録」リンクから遷移すると、見出し「**アカウントを作成**」の画面が表示される
2. 「**表示名**」「**メールアドレス**」「**パスワード**」（10文字以上）を入力する
3. 「**作成してログイン**」ボタンを押す
4. 画面には「作成した時点では、どのテナントにも所属していません。管理者がテナントに追加すると作業を開始できます。」という案内が表示される
5. 自分のメールアドレスを管理者に伝え、ワークスペースへの追加を依頼する（9章「管理者向け操作」参照）

### 4.2 ログイン（画面ID: SC-01、`/auth/login`）

1. 見出し「**おかえりなさい**」の画面が表示される
2. 「**メールアドレス**」「**パスワード**」を入力する
3. 「**ログイン**」ボタンを押す
4. 認証に失敗すると「**ログインできませんでした**」というエラーが表示される。繰り返し失敗するとロックアウトされる場合がある（具体的な回数・解除方法は **未確認**。運用手順書 `WS2D-OP-001` を参照）
5. 成功すると、次に表示されるのは4.3の「ユーザー選択」画面

### 4.3 ユーザー選択（画面ID: SC-04、`/auth/user`、STEP 1/3）

1. 見出し「**どのユーザーとして使いますか？**」が表示される
2. 自分自身のアカウントは「**ログイン中のアカウント**」バッジ付きで一番上に表示される
3. 切替可能な他の利用者（パスワード未設定の利用者に限る）がいる場合、「**切り替えて使う**」という区切りの下に一覧表示される。パスワードを設定した利用者へは切り替えできない旨が画面下部に注記される
4. 使いたいユーザーをクリックすると、次は4.4の「テナント選択」画面へ進む

### 4.4 テナント選択（画面ID: SC-05、`/auth/tenant`、STEP 2/3）

1. 見出し「**どのテナントで作業しますか？**」が表示される
2. 所属しているワークスペースがカード形式で並ぶ。各カードには「**メンバー N 人**」「**開く →**」が表示され、現在選択中のテナントには「**選択中**」の表示が付く
3. どのワークスペースにも所属していない場合は「**まだどのテナントにも所属していません。**」というメッセージと、自分のメールアドレスを管理者に伝えるよう促す案内が表示される
4. 使いたいテナントのカードをクリックすると、次は4.5の「システム選択」画面へ進む
5. 管理者ロールを持つ利用者には、画面下部に管理画面（`/admin/console`）への案内リンクが追加表示される

### 4.5 システム選択（画面ID: SC-07、`/systems`）

1. 見出し「**どのシステムを使いますか？**」が表示される。3枚のカードが並ぶ
2. **System 01「ドキュメント作成」**: 「URLを渡すと、画面仕様書・遷移図・項目定義を生成します。認証・対象範囲・前回差分にも対応。」カード末尾の「**ドキュメント作成を開く →**」を押すとダッシュボードへ進む（5章）
3. **System 02「AutoRun」**（「独立システム」バッジ付き）: 「ベテランQAとして、受領から実行完了レポートの納品まで。」カード末尾の「**AutoRunを開く →**」を押すとAutoRun画面へ進む（6章）
4. **System 03「CLIモード」**（「画面なし」バッジ付き）: 「同じ機能を端末から。ブラウザを開かずに解析・AutoRun・テスト実行まで回せます。」カード末尾の「**CLIの使い方を見る →**」を押すと案内ページ（画面ID: SC-12）へ進む
5. いつでもこの画面に戻ってシステムを切り替えられる。共通なのはログインとアカウントだけで、各システムの入口・世界観・ナビゲーションは独立している

### 4.6 ログアウト

各画面のトップバー（または認証系画面上部）にある「**ログアウト**」ボタンを押すと、セッションが終了しログイン画面（4.2）に戻ります。

## 5. ドキュメント作成の操作手順（System 01）

### 5.1 対象サイト登録・クロール設定

1. ダッシュボード（ホーム画面）で「**+ サイトを追加**」をクリックする
2. URL入力欄にクロール対象の URL を入力する（例: `https://example.com`）
3. 「**画面分析**」ボタンを押す
4. 分析が完了すると「**N 件の画面を検出しました（経過時間）**」と表示される
5. 「**次へ →**」をクリックして条件設定へ進む

### 5.2 条件設定

- **画面の選択**: 取得する画面にチェックを入れる（デフォルトは全選択）。不要な画面はチェックを外す
- **ログインが必要なサイトの場合**: 「要ログイン」バッジが付いた画面が画面リスト下部にグループ表示される。各画面の直下に、その画面専用の ID/PASSWORD 入力フォームが自動表示されるので、**ID**（ユーザーID・メールアドレス）と **PASSWORD** を入力して「**ログイン**」を押す。パスワードはセッション確立後に即破棄される（保存されない）。複数の認証エリアがある場合は画面ごとに個別入力する
- **その他の設定項目**: クロールする階層の深さ・最大ページ数・並列数などを必要に応じて調整する（既定値のままでも実行可能）
- 「**前回との差分を出力**」にチェックを入れると仕様ドリフト検知が有効になる
- 「**解析開始**」をクリックすると実行に進む

### 5.3 実行・進捗確認

- クロールの進捗が4段階（受付 → ページ取得 → 解析 → 結果整理）でリアルタイム表示される
- ライブプレビューで取得中の画面を確認できる
- 完了すると「**レポートを見る →**」ボタンが実行時間付きで表示される
- ボタンを押すと結果画面（画面ID: SC-10、実行結果ページ）に進む

### 5.4 結果の見方（8つのタブ）

| タブ | 内容 |
|---|---|
| 概要 | 画面インベントリ一覧（画面ID・タイトル・URL・フォーム数・入力項目数・遷移先） |
| 画面別仕様 | スクリーンショット（クリックで全画面表示）＋フォームカード＋テスト条件 |
| 入力項目・テスト条件 | 全フィールドのテスト条件マトリクス（画面/型/必須でフィルタ・検索・CSV書き出し） |
| 設計 | テスト設計技法の推奨マトリクス（同値分割/境界値分析/決定表/状態遷移/分類木/PW法 等） |
| 技法詳細 | 各画面・各技法の機械導出サンプル値の詳細カード |
| 画面遷移図 | UML遷移図を3種類（シーケンス図/コミュニケーション図/アクティビティ図）のサブタブで表示 |
| 遷移表 | ISTQB標準フォーマットの画面遷移表（イベント列にリンク先URLパスを表示） |
| 履歴・差分 | クロール履歴と任意2時点の仕様ドリフト比較 |

### 5.5 出力形式

各成果物カードの「**プレビュー**」ボタンでアプリ内モーダル表示ができます（別ウィンドウは開きません）。モーダルは「**✕ 閉じる**」・背景クリック・Escapeキーで閉じます。あえて別タブで開く場合は「**↗ 新規タブ**」を押します。

ヘッダーの「**↓ エクスポート**」から、以下の形式でいつでも出力できます。

| 形式 | 内容 |
|---|---|
| HTMLレポート | 画面別仕様・テスト条件・スクリーンショット付き |
| PDF | HTMLレポートの印刷・配布用PDF版 |
| JSON | 全データの構造化JSON（自動化・CI連携用） |
| Excel | `spec.xlsx`（テスト管理表への転記用） |
| Markdown | `screens.md`（画面一覧）／`forms.md`（フォーム） |
| 遷移図（Mermaid） | `transition.mmd` |
| 差分レポート | `diff_report.html` |
| ZIP | 生成物一式をまとめてダウンロード |

### 5.6 再クロール（仕様ドリフト検知）

ダッシュボードの「**再クロール**」ボタンを押すと、前回の取得対象・設定を自動復元してステップ2（条件設定）から再開できます。設定を確認・変更してから「解析開始」を押し、完了後は「履歴・差分」タブで前回との差分（追加/削除された画面・変更されたフォーム）を確認できます。

## 6. AutoRun の操作手順（System 02）

左メニューの「**AutoRun**」を開き、生成モードを選びます。

### 6.1 生成モード

| モード | 何を根拠にテストを作るか | 使いどころ |
|---|---|---|
| URL駆動（既定） | 実際に観測した画面 | 仕様書が無い・現物から起こしたい |
| 文書駆動 | 要件・仕様文書 × 観測した画面 | 仕様書があり、書かれた要件を漏れなく試したい |

### 6.2 URL駆動モードの手順

1. 生成モードで「**URL駆動**」を選ぶ（既定で選択済み）
2. 「**対象URL**」を入力する
3. 必要であれば「**先に到達確認**」ボタンで対象サイトへの到達性を事前確認する
4. 「**入力検証も観測する**」にチェックを入れると、フォームへ値を入れて検証メッセージだけを観測できる（**送信は一切しない**。値を入れる直前から通信を遮断するため、入力値が外部へ出ることもない）
5. 「**開始**」を押すと承認モーダルが開き、実行が始まる

### 6.3 文書駆動モードの手順

1. 生成モードで「**文書駆動**」を選ぶ
2. **対象URL** を入力する（先に入れないと文書をアップロードできない）
3. **要件・仕様文書** を追加する（複数可）
4. **パス選定基準** を選ぶ — 全画面を通る（頂点網羅）／全遷移を通る（エッジ網羅）／全経路パターンを通る（プライムパス）／指定画面まで到達、の4種類。プライムパスは、ループを含む画面遷移を有限のテスト経路で漏れなく踏む基準（エッジ網羅より強い）
5. 必要なら「**入力検証も観測する**」にチェック
6. 「**開始**」を押す

実行後、承認モーダルに「文書要件数 / 対応画面数 / 選定パス数 / カバー率」が表示されます。文書に書かれていても実際の画面で見つからなかった要件は、突合できなかったものとして残ります（ツールは推測で埋めません）。未突合の要件には、テキスト類似度による候補画面が根拠語つきで提示されます（自動リンクはせず、採用は人が判断します）。要件・仕様文書は **Gherkin形式（`.feature`）** で用意すると抽出精度が上がります（`docs/templates/requirements-template.feature` が雛形。日本語・英語の両方に対応）。

### 6.4 段階承認（目的 → 計画 → 観点 → 設計 → ケース）

AutoRun は実行前に、次の順で段階的に内容を確定させながら進みます。段階の名称・順序・生成物は実装済みのパイプラインに基づく実測ですが、**各段階の承認ボタンの正確な画面文言までは、本書執筆時点では未確認**です（画面詳細の実測は今回の調査範囲外のため）。

1. **目的**: 何を確認するテストなのか（テスト目的）を確定する
2. **計画**: どの範囲・どの技法で臨むかのテスト計画を確定する
3. **観点**: 適用する観点（品質特性・ISTQB技法など）を確定する
4. **設計**: 基本設計・詳細設計（画面・機能をどう組み合わせてケース化するか）を確定する
5. **ケース**: 実行可能なテストケース（QualityForward準拠の10列構成）を確定する

各段階では、その時点までに生成された内容を確認し、必要なら追加提案（差分提案）を取り込んだうえで次へ進みます。承認前の内容は実行に反映されません。

### 6.5 生成される主な成果物

| ファイル | 内容 |
|---|---|
| `document_mbt.json` | 要件と画面を結んだモデル・選定パス（文書駆動時） |
| `manual_procedures.md` / `.xlsx` | 手動テスト手順書（画面キャプチャ付き） |
| `test_data.json` / `.csv` | 実測の入力制約から導いたテストデータ |
| `pairwise_cases.json` | 選択肢の組合せを2因子網羅で圧縮したケース |
| `metamorphic_checks.json` | オラクル不在でも成り立つべき検証関係の候補 |
| `validation_observations.json` | 入力検証の観測結果（観測時のみ） |
| `evidence_pack.md` / `.html` | 検収提出用の実施証跡パック |

## 8. 設定

左メニューの「**設定**」には次のタブがあります（一部は管理者ロールのみ表示）。

### 8.1 APIキー

テストケース生成・観点生成に使う LLM を選びます。設定は `.env` に保存され、ブラウザには保存されません。

- LLM接続先を「**OpenAI**」「**Ollama（ローカル）**」から選ぶ
- OpenAI: APIキー・組織ID（任意）・プロジェクトID（任意）・モデル（`gpt-5.4-mini`など6種類から選択）
- Ollama: ベースURL・モデル一覧から選択（APIキー不要。ローカルのOllama起動が前提）
- 「**保存**」「**疎通確認**」ボタンで設定・接続を確認する

### 8.2 解析の既定値

このブラウザに保存され、生成ウィザードの初期値として反映されます。階層数、最大ページ数、並列数（1/2/4推奨/8最大）、1テストケースあたりの想定分数、URL履歴の保持件数、認証セッション（`auth.json`）のパスなどを設定します。「**ローカル/ステージング環境の解析を許可**」トグルは、`localhost` やプライベートIPへの解析を許可するもので、SSRF保護をバイパスするため信頼できる環境でのみ有効化するよう画面上に注意書きがあります。

### 8.3 通知

仕様ドリフトを検知した際にSlackチャンネルへ通知するための Webhook URL（`SLACK_WEBHOOK_URL`）を設定します。取得方法は Slack API のドキュメントへのリンクが画面に用意されています。

### 8.4 運用監視

サイトごとに実行可能な曜日・時間帯、失敗時の再試行、通知先を設定します。

- 実行周期（無効/毎日/毎週/毎月）、タイムゾーン、時間帯（開始・終了。終了が開始より前なら日跨ぎ扱い）、実行曜日、再試行回数、初回バックオフ秒数
- 通知チャネル（Slack / Microsoft Teams Workflows / Webhook / Email）、差分表示件数、通知テンプレート（Jinja2形式。`site_url`/`added_pages`等の変数が使用可能）
- CIで仕様ドリフトをゲートするコマンド例と終了コード一覧（0: 初回・差分なし／1: 仕様ドリフトあり／2: 取得・認証エラー）。同梱テンプレートは `.github/workflows/spec-drift.yml`
- 「**操作ツアーを再表示**」ボタンで、初回に表示される4ステップの案内をいつでも再表示できる

### 8.5 データ管理（管理者ロールのみ）

出力データ・運用データの容量表示、保持設定（無制限/世代数/期間）、サイト別のデータ容量一覧、バックアップ／リストア手順への導線があります。`output/` と `instance/` は必ず同じ時点の対として保存・復旧する必要がある旨が案内されます。

### 8.6 監査ログ（管理者ロールのみ）

ログイン成否、メンバー変更、設定変更、保持GC、レポート出力などの管理操作ログを、操作種別・結果・キーワードで絞り込んで確認できます。

### 8.7 テスト設計

レポートの「設計 → 技法詳細」で使う技法とパラメータを調整します。境界値分析(BVA)／デシジョンテーブル(DT)／ペアワイズ(PW)／状態遷移(ST)の使用有無、境界値オフセット、ペアワイズ強度（2-way/3-way）、状態遷移のNスイッチ（0/1）、DTの最大条件数、テスト値カタログ（JSON形式）を設定します。設定は `instance/test_design_settings.json` に保存されます。

## 9. 管理者向け操作

管理者ロールを持つ利用者のみが行える操作です。ロールはテナントごとに設定されます。

### 9.1 マイページ（画面ID: SC-06、`/auth/account`）

全利用者が到達できる画面ですが、管理者には追加のセクションが表示されます。

- **プロフィール**: 表示名・メールアドレス・ロール・選択中のテナント・所属テナント一覧・最終ログイン日時を確認する
- **パスワード変更**: 現在のパスワードと新しいパスワードを入力し「**変更する**」を押す
- **メンバー管理**（管理者のみ）: 名前・メール・ロール・状態・最終ログインの一覧表。各行の「**無効化**」/「**有効化**」ボタンでアカウント状態を切り替える（無効化すると既存セッションも失効する）
- **メンバーを追加**（管理者のみ）: 表示名・メールアドレス・初期パスワード（任意）・ロール（一般/管理者）を入力し「**追加**」を押す
- **APIトークン**（管理者のみ）: CI/CDなどからREST API（`/api/v1`）を呼び出すためのワークスペース単位トークンを発行する。トークン名を入力し「**発行する**」を押すと、トークン文字列が一度だけ表示される。不要になったトークンは「**失効させる**」で無効化する（取り消し不可）

### 9.2 管理者コンソール（画面ID: SC-08、`/admin/console`）

管理者専用の画面です（管理者以外がアクセスするとシステム選択画面へリダイレクトされます）。

- **テナント管理**: 「テナント名」「slug（省略時は名前から自動生成）」を入力し「**作成**」を押す。一覧表でテナントごとのメンバー数・作成日を確認できる
- **ユーザー管理**: 「表示名」「メールアドレス/ログインID」「所属テナント」「ロール（一般/管理者）」「パスワード（任意。空欄ならパスワードなしユーザーとして作成）」を入力し「**作成**」を押す
- **所属編集**: ユーザー一覧から対象を選ぶと所属編集ダイアログが開き、複数テナントへの所属・ロールをまとめて保存できる

### 9.3 ロールと権限の考え方

ロールは「一般」「管理者」の2種類で、**テナントごとに**設定されます（同じ利用者でもワークスペースによってロールが異なる場合があります）。管理者ロールは、管理者コンソールとテナント内管理API（マイページのメンバー管理・APIトークン発行）の両方の操作権限を持ちます。

## 10. よくある質問（FAQ）

**Q1. プログラミングの知識は必要ですか？**
不要です。画面の指示に沿ってURLを入力し、ボタンを押すだけで操作できます。ただしCLIモード（System 03）を使う場合はコマンドライン操作の知識が必要です。

**Q2. モバイル（スマートフォン・タブレット）でも使えますか？**
使えません。本製品はPC専用として設計されており、モバイル・タブレット向けの表示や操作には対応していません。

**Q3. ログインが必要な対象サイトも解析できますか？**
はい。「画面分析」実行後、認証が必要な画面は「要ログイン」バッジ付きで画面リスト下部にグループ表示されます。専用フォームにID/PASSWORDを入力して「ログイン」を押してください。これは解析対象サイトへのログインであり、WebSpec2Doc自体への利用者ログインとは別物です。

**Q4. 対象サイトに入力したID/PASSWORDは保存されますか？**
パスワードはセッション確立後に即破棄され、保存されません。保存されるのはログイン後のセッション状態（`auth.json`）のみです。

**Q5. テナント（ワークスペース）とは何ですか？なぜ選ぶ必要があるのですか？**
成果物・実行履歴・観点セットをチームやプロジェクト単位で分離する作業単位です。同じ利用者が複数のワークスペースに所属していても、成果物が混ざりません。

**Q6. テナント選択画面に何も表示されません。**
どのワークスペースにも所属していない状態です。画面に表示される自分のメールアドレスを管理者に伝え、管理者コンソールまたはマイページの「メンバー管理」からテナントに追加してもらってください。

**Q7. 「切り替えて使う」に他の利用者が出てくるのはなぜですか？**
パスワードを設定していない利用者（社内モック運用向け）は、ユーザー選択画面から切り替えて動作確認できます。パスワードを設定した利用者へは切り替えられず、ログインし直す必要があります。

**Q8. 品質観点は追加料金がかかりますか？**
標準のローカル生成ではかかりません。外部LLM/APIは呼び出さず、`report.json`と同梱のQA観点CSVだけで生成します。

**Q9. 品質観点画面に対象サイトが出ません。**
先に「+ サイトを追加」からサイトを解析し、`report.json` を生成してください。

**Q10. 文書駆動モードで文書をアップロードできません。**
先に「対象URL」を入力してください。文書はサイト単位で保管するため、URLが未入力だとアップロード先が決まりません。

**Q11. 文書駆動で「文書要件のうち一部が対応画面なし」と出ます。**
文書に書かれていても、実際にクロールした画面の中に該当が見つからなかった要件です。ツールは推測で埋めないため、未実装・別画面・クロール未到達のいずれかを人が判断してください。

**Q12. 「入力検証も観測する」は本番サイトで安全ですか？**
フォームに値を入れて検証メッセージを読むだけで、送信（submit・クリック・Enter）は一切行いません。

**Q13. 検収用の報告書がほしいのですが。**
AutoRun完了後に `qa_process/evidence_pack.html` が生成されます。ブラウザの印刷機能でPDF化できます。

**Q14. APIトークンは何に使いますか？**
CI/CDなどからREST API（`/api/v1`）を呼び出す際の認証に使います。マイページの「APIトークン」からAuthorization: Bearer形式のトークンを発行できます。トークン文字列は発行直後の一度しか表示されないため、必ず控えてください。

## 11. 困ったときは（トラブルシューティング）

| # | 症状 | 原因 | 対処 |
|---|---|---|---|
| 1 | 利用者ログインができない | パスワード誤り、または繰り返し失敗によるロックアウト | パスワードを確認する。ロックアウトの疑いがある場合は時間を置くか、管理者にアカウント状態の確認を依頼する |
| 2 | テナント選択画面に何も表示されない | どのワークスペースにも未所属 | 画面に表示されるメールアドレスを管理者に伝え、管理者コンソールから追加してもらう |
| 3 | 管理者コンソールに入れず、システム選択に戻される | ロールが「一般」で管理者権限がない | 管理者にロール変更を依頼する |
| 4 | 対象サイトのログインが必要な画面が取得できない | 認証情報未入力、またはログインURLの認識ずれ | 「画面分析」後に表示される「要ログイン」バッジ付き画面のID/PASSWORD欄に入力し「ログイン」を押す |
| 5 | SSL証明書エラーが表示される（`robots.txt`取得失敗） | 実行環境のPythonが証明書ストアを参照できていない | `pip install certifi` を実行する。クロール自体は継続するため致命的ではない |
| 6 | ページがクロールされない・少ない | 深さ(depth)不足、対象がJavaScriptで生成されるリンク | 深さの設定を増やす。取得できないサイトは対象URLを絞る |
| 7 | タイムアウトエラーが頻発する | 重いページ・低速なサーバー | 最大ページ数を減らす、深さを減らす |
| 8 | 画面遷移図（Mermaid）が表示されない | `report.html`表示時にオフラインでCDN読込に失敗 | オンライン環境で開くか、`transition.mmd` を Mermaid Live Editor に貼り付ける |
| 9 | Excelファイルが開けない | `openpyxl` が未インストール（開発環境） | `pip install openpyxl` を実行する |
| 10 | 品質観点画面に対象サイトが出ない | `report.json` が未生成 | 先に「+ サイトを追加」からサイトを解析する |
| 11 | 文書駆動モードで文書をアップロードできない | 対象URLが未入力 | 先に対象URLを入力する |
| 12 | 画面分析（discover）がタイムアウトする | 想定時間（180秒）を超過 | 対象URLを絞る、または手動URL入力モードを使う |
| 13 | 実行結果ページ・レポートで成果物が見つからない | 該当実行がまだ生成中、または対象ドメインの実行がない | 実行履歴一覧から該当の実行を選び直す。生成中の場合は完了を待つ |
| 14 | `greenlet` のビルドが失敗する（CLI/開発環境） | Python 3.13 は非対応 | `python3.12` で仮想環境を作り直す |

## 12. 問い合わせ先

問い合わせ先は本書時点で **要設定** です（社内展開時に導入組織側で定めてください）。

問い合わせる際は、次の情報を準備すると対応が早くなります。

- 発生日時
- 操作していた画面ID（本書に記載の SC-xx。例: SC-07 システム選択）
- 対象サイトのURL（ドキュメント作成・AutoRunの場合）
- 所属テナント（ワークスペース）名
- エラーメッセージの全文（表示されている場合）
- 実行結果ページのURL（`/runs/<domain>/<run_id>` の形式。分かる場合）
- 発生時に行った操作の手順（再現手順）
