# バッチ/ETL/データ検証/API 試験の商用ツール調査

調査日 2026-10-15。WebSearch 15 回・WebFetch 9 回（Informatica DVO の docs は 403 で取得不可、検索スニペットのみ）。
区分: 【実証】公式ドキュメント本文で確認 / 【主張】ベンダーのマーケ・プレス / 【レビュー】G2・PeerSpot 等の利用者投稿（n 小）。

## 要約（10 行以内）
1. 共通機能: ソース対ターゲット比較（件数・集計・行/列・チェックサム）、ノーコード/ウィザードでのテスト作成、スケジューラ、CI 連携（Jenkins/Azure DevOps/GitHub Actions 等）、HTML/PDF 等のレポート。
2. DB 前後比較・差分・プロファイリングは ETL 系（QuerySurge/iCEDQ/Datagaps/RightData/BiG EVAL/Tosca DI/DVO）が強い。API 系（SOAtest/ReadyAPI/Katalon/Postman/mabl）は DB 検証が付属程度で、JDBC は「データソース」止まりが多い。
3. AI は「マッピング表→SQL テスト生成」（QuerySurge）、「自然言語→API テスト」（SOAtest/ReadyAPI/Postman）、「異常検知」（iCEDQ）、「ML ルール提案」（RightData）に限られる。
4. 空白（今回の調査範囲で確認できず）: 要件・設計書・ジョブ定義から**テスト観点とケースを導出**する機能。ジョブネット起動・業務日付操作・再実行/中断復旧など**バッチ固有の試験設計**。
5. 空白: テストデータ生成・マスキング（Tonic/Datprof/Delphix）と、検証ツール（比較・API）が**別製品**で、ケース設計→データ準備→実行→証跡が一気通貫でつながる商用品は確認できなかった。
6. 空白: 日本の商用ツールは検索で確認できず（国内事例・日本語サポートとも未確認）。日本の SIer 納品物（テスト仕様書・エビデンス）への出力対応も確認できず。
7. 利用者不満は学習曲線・SQL 習熟前提（QuerySurge）、大量データ性能（QuerySurge/RightData）、JSON/REST を比較元にできない（QuerySurge 試用者）、ルールのバージョン管理不足（iCEDQ）、サポート（ReadyAPI）。
8. 差別化余地（推論）: 設計書→観点→ケース→データ→実行→証跡を AI エージェントが繋ぎ、人間は合意と判定だけを行う構成。外部結合（相手先ファイル/API のスタブ・差替）と環境切替を含める。

## 5. 取り込み要素の優先案（A-6: 上記調査に基づく）
1. 設計書/マッピング/ジョブ定義 → 比較ケース・SQL の自動生成と人の承認（QuerySurge の延長。観点まで広げるのが差別化）。
2. 比較の型の分類（集計・集合・値＝DVO）と、プレスクリーニング→照合→プロファイリングの順序（Tosca DI）を網羅基準にする。
3. 要件 ID ↔ ケース ↔ 結果の追跡（Tosca DI のみが持つ）を受け入れ判定の根拠にする。
4. 外部結合は相手先をスタブ化（SOAtest/Virtualize）。DB 状態の準備と事後検証を同一シナリオに（mabl の UI+API 連鎖の考え方）。
5. 失敗時の原因要約（mabl）と、AI 提案を採用/修正/破棄で選ぶ UI（RightData）。
6. JSON/REST/ファイルもソースに含める（QuerySurge の不満点の回避）。
