# レンズ5: 視覚・複雑性

## 指摘一覧

### F5-1 [深刻度: 致命] 段階承認画面に操作要素が42個あり、うち青塗りCTAが4個で視線誘導が成立していない
- 場所: 05-stages.png / AutoRun 段階承認画面（STEP 1 テスト目的）全体
- 事実: `dom-stage1.json` の `visibleButtons` は **39個**。加えて要確認チェックボックス1個、ログの「自動スクロール」「開発者向け詳細を表示」チェックボックス2個で、**1画面あたり操作要素 42個**（うちサイドバー18個、本文24個）。視認できる範囲に塗りつぶし青ボタンが「新規解析」「承認して次へ」「QAアシスタント」の**3個**、加えて薄青の「確定する」で計**4個**が同時に発色している。
- 原則: 視覚的複雑性（Reinecke et al. 2013／要素数が第一印象を悪化させる）＋ Nielsen「Aesthetic and Minimalist Design」
- 影響: 最初の1秒で「次にどこを押すか」が決まらない。強調色が4か所に分散しているため、視線が最初に落ちる先がランダム化し、理解までの時間が要素数に比例して伸びる。

### F5-2 [深刻度: 致命] 前進用CTAが「承認して次へ」「確定する」の2個あり、同一画面で競合している
- 場所: 05-stages.png / ヘッダー右上（承認して次へ）と要確認カード右下（確定する）
- 事実: 同一目的（この段階を承認して先へ進める）のCTAが**2個**。垂直距離は約 357px（y≈104 と y≈461）で、両者は同時に視野に入る。片方は有効な濃青、もう片方は無効の薄青という**異なる状態**で並置されている。
- 原則: 視覚的複雑性（同一目的CTAの重複）＋ 典型性（Tuch et al. 2012／一般的なウィザードUIは前進CTAを1つに集約する）
- 影響: 「押せる方（承認して次へ）」と「押せない方（確定する）」が同色系で並ぶため、どちらが正規の導線か判別に往復が発生する。ウィザードの典型形から外れており、初見の予測が外れる。

### F5-3 [深刻度: 高] 同一画面に未確認件数が「4件」「0/1件」の2系統あり、数字が一致していない
- 場所: 05-stages.png / ヘッダー帯（STEP 1 テスト目的 — 未確認 4 件／未確認が 4 件あります）と要確認カード（要確認 0 / 1 件／未確認が 1 件あります）
- 事実: 同一ビューポート内に未確認カウンタの表示が**4か所**（ヘッダー左「未確認 4 件」、ヘッダー右赤字「未確認が 4 件あります」、カード見出し「要確認 0 / 1 件」、カード下部「未確認が 1 件あります」）。示す数値は **4 と 1 の2系統**。
- 原則: 視覚的複雑性（冗長な情報の反復）＋ Nielsen「Consistency and Standards」
- 影響: 同じ語（未確認）が異なる数値で4回出るため、読み手は数値を照合する作業を強いられる。ヘッダーの赤字は最も強い視覚的警告でありながら、カード内の実タスク数（1件）と一致しないため、警告としての信頼が落ちる。

### F5-4 [深刻度: 高] 固定表示のQAアシスタントボタンが本文コンテンツに重なり、文字を欠損させている
- 場所: 03-autorun.png 右下（「実行・納品」カードの11行目「レポート納品＋回帰・ドリフト検知」）／05-stages.png 右下
- 事実: `.autorun-chat-fab` は `position: fixed; right: 22px; bottom: 22px;`（`static/css/components.css:938-942`）で、本文側に下部退避パディングがない。03-autorun.png では11行目のテキスト末尾がボタンに**実際に覆われて読めない**（「…ドリフト検知」の右端が欠落）。重なりは**2画面**で確認。
- 原則: 要素の重なり・見切れ（Nielsen「Visibility of System Status」を阻害）
- 影響: 「全11ステップ何をやるか」という初訪問者が最も読む要約リストの最終行が欠ける。ページ最下部に近い情報ほど恒常的に隠れるため、スクロールしても回復しない。

### F5-5 [深刻度: 高] 初回起動時、オンボーディングのポップオーバーがAutoRunカードを完全に覆っている
- 場所: 01-entry.png / ホーム画面のツアー1/4「1. 対象サイトを入力」
- 事実: ポップオーバー（概ね x=300-660, y=262-412）が、AutoRunエントリカード（x≈564-782, y≈303-361）と**面積で重なっており**、カードのタイトルは「…m」、説明は「…スト実行まで全自動」しか可視でない。AutoRunへの唯一の視覚的入口が初回表示で**ほぼ100%隠蔽**されている。
- 原則: 要素の重なり／典型性（オンボーディングは説明対象を隠さない位置に出るのが通例）
- 影響: 「AutoRunという機能が存在する」という第一印象そのものが初回セッションで発生しない。ツアーを閉じるまで機能の存在に気づけない。

### F5-6 [深刻度: 中] 「アシスタントに相談」への入口が同一画面に6個ある
- 場所: 05-stages.png / 要確認カード内1個、テスト目的カード4枚に各1個（計4個）、右下固定FAB「QAアシスタント」1個
- 事実: `dom-stage1.json` 中「アシスタントに相談」が**5個**、加えて「QAアシスタント」FABが1個で、同一機能への入口が**6個**。うち5個は「修正」ボタンと2個1組で並び、**ボタンペアが5組**反復する。
- 原則: 視覚的複雑性（同一目的CTAの重複）
- 影響: カード1枚あたり操作要素が2個に増え、4枚並ぶと本文中央部が8個のボタンで埋まる。カードの内容（テスト目的の文章）よりボタンの反復パターンの方が視覚的に目立ち、読ませたい本文から視線が逸れる。

### F5-7 [深刻度: 中] 進捗の表現が3系統・段階数が「8」「11」「6」と食い違っている
- 場所: サイドバー進捗リスト（05-stages.png）／本文パイプライン（05-stages.png 下部・04-running.png 上部）／AutoRun受付画面の3カード（03-autorun.png 下部）
- 事実: 進捗を示すビジュアルが**3系統**同居。(a) サイドバー縦リスト = **8段階**（1テスト目的〜8Playwright自動化、本文「STEP 1 / 8」と一致）、(b) 03-autorun.png の「見立て／設計／実行・納品」3カード = 通し番号 **1〜11の11段階**、(c) 本文下部の横並びパイプライン = 仕様書生成／QA成果物／スクリプト生成／承認／テスト実行／完了の**6段階**。
- 原則: 典型性（Tuch et al. 2012）＋ Nielsen「Consistency and Standards」
- 影響: 「今どこにいるか」を読み取るのに3つの尺度を突き合わせる必要がある。段階数が3通りある時点で、どのインジケータを信じるかの判断が毎回発生し、進捗把握という最も頻繁な読み取り動作が遅くなる。

### F5-8 [深刻度: 中] 「生成モード」で同じ説明文が2か所に重複表示されている
- 場所: 03-autorun.png / 生成モードセクション
- 事実: 青バッジ「URL駆動を選択中 — 実測した画面からテストを生成します。」と、直下のラジオ「URL駆動」の副文「実測した画面からテストを生成」が**同一内容**。垂直距離約 38px。同じ文が**2回**、うち1回は最も彩度の高い青地バッジとして表示されている。
- 原則: 視覚的複雑性（冗長要素）
- 影響: 選択済み状態はラジオのドット表示で既に伝わっており、バッジは情報を追加せず密度だけ上げる。彩度の高いバッジがフォームの最上部にあるため、実際に入力すべき「対象URL」より先に視線を奪う。

### F5-9 [深刻度: 中] ホーム画面に「新規解析」ラベルのボタンが3個、開始系CTAが計5個ある
- 場所: 02-home.png / サイドバー上部の青ボタン、サイドバーメニュー項目、解析履歴セクション右上
- 事実: 「新規解析」という**同一ラベル**のボタンが**3個**（うち塗りつぶし青が2個）。加えて同じ「解析を開始する」目的のCTAとして「解析を始める」「サンプルURLで試す」があり、開始系CTAは計**5個**。01-entry.png ではさらに「同梱デモで試す」が加わり、デモ起動という同一目的のCTAが**2個**同時表示される。
- 原則: 視覚的複雑性（同一目的CTAの重複）
- 影響: 同じラベルが3か所に散らばると、押した結果が同じなのか違うのかを毎回確認する必要が出る。第一印象として「入口が多い＝どれが正解かわからない」という迷いを生む。

### F5-10 [深刻度: 低] 非活性表示に `opacity: .45` が使われており、コントラスト比が確保されていない
- 場所: 04-running.png / パイプラインの未到達ステップ、およびページャ
- 事実: `static/css/components.css:468` に `.autorun-phase-item.is-locked { opacity: .45; }`、`:2026` に `.pager-btn:disabled { opacity: .45; }`。二次テキスト色（既に本文より低コントラスト）へ 0.45 を乗算しており、**背景に対する実効コントラストは 4.5:1 を下回る可能性が高い**（実測値は未計測）。
- 原則: コントラスト不足（WCAG 2.1 SC 1.4.3）
- 影響: 04-running.png では未到達ステップのラベルがほぼ判読できず、「全体で何段階あり、あといくつ残っているか」という進捗の外形が読めない。実行中の待ち時間の見通しが立たない。

### F5-11 [深刻度: 低] サイドバーに「テストケース」項目が2個あり、階層の異なる別物として並んでいる
- 場所: 05-stages.png / サイドバー「進捗」グループ内の「7 テストケース」と、その直下の独立項目「テストケース」
- 事実: `dom-stage1.json` に「7 テストケース」と「テストケース」が**別項目として2個**存在。両者はインデントも罫線グループも異なるが、垂直距離は約 55px で隣接している。
- 原則: 典型性／Nielsen「Recognition Rather Than Recall」
- 影響: 同名項目が隣接すると、どちらがナビゲーションでどちらが進捗表示かをラベルだけでは判別できず、階層の視覚的手がかり（インデント量）に依存する。手がかりが弱いため誤クリックを誘発する。

## 見落としの自己申告

- ブラウザ実行が禁止だったため、**実測のコントラスト比・実寸ピクセル・要素バウンディングボックスは取得していない**。座標・距離は 1440×900 スクリーンショット上の目視読み取りであり、±10px 程度の誤差を含む。
- ダークモード（ヘッダーに月アイコンのトグルあり）でのレイアウト・コントラストは**一切確認していない**。`opacity: .45` の問題はダークモードで悪化する可能性があるが未検証。
- スクロールしないと見えない領域（05-stages.png の4枚目カード「基準の確立」以降、実行ログの全体、レポート画面）は**ビューポート外のため未評価**。カード4枚目のボタンが下端で切れているのは単なるスクロール境界か、レイアウト崩れかを判別できていない。
- ホバー・フォーカスリング・キーボードフォーカスの可視性は静止画では確認不能。
- サイドバー折りたたみ後のレイアウト、ウィンドウ幅を変えた際の折り返し挙動は未確認。
- 04-running.png はモーダル表示中のため、背後の実行中画面の要素数は正確に数えられていない（モーダルが遮蔽）。
- F5-7 の段階数の食い違いは「用語・仕様の妥当性」とも重なるが、本レビューでは**進捗インジケータの視覚的一貫性の問題としてのみ**扱った。仕様上どれが正なのかは担当外。
