## 1. デンソー NLP2025 Q9-5（本文確認済み）

出典: https://www.anlp.jp/proceedings/annual_meeting/2025/pdf_dir/Q9-5.pdf （言語処理学会第31回年次大会, 2025年3月, 鈴木・村瀬・水野・髙木・不破・塚原・中江, デンソー系3社）

| 項目 | 内容 |
|---|---|
| 目的 | 要求インスペクションの LLM 自動化可否 |
| 基準 | SRS 記述ガイドライン（不破2019） |
| モデル | GPT-4o（Azure OpenAI） |
| 前処理 | Azure AI Document Intelligence で Markdown 化 |
| 評価データ | 車載駆動系SW仕様書 73頁（要求52頁） |
| 追加データ | 別製品 111頁（要求85頁）、人手正解なし |
| 正解 | 過去の人手インスペクション結果 |
| 除外 | 図、入れ子の表（パース不能） |
| 指標 | 再現率（人手指摘の再現）、適合率（人手判定） |
| 規則数 | 6 ルール（4 品質特性） |

評価結果（表1。適合率 P / 再現率 R。画像から転記）:

| ルール | LLM単独 P/R | LLM+規則 P/R | 正解なし版 P |
|---|---|---|---|
| 簡潔な文 | 0.31 / 0.71 | 0.97 / 1.00 | 1.00 |
| 係り受け | 0.53 / 0.31 | 0.94 / 0.98 | 1.00 |
| 誤字脱字 | 0.47 / 0.30 | 0.78 / 0.47 | 0.79 |
| 完全な場合分け | 0.45 / 0.57 | 0.77 / 0.85 | 0.89 |
| 誤った記載場所 | 0.64 / 0.63 | 0.80 / 0.63 | 1.00 |
| 単一の要求 | 0.33 / 0.00 | 0.67 / 1.00 | 0.70 |

- 手法: 文抽出（節分割→文分割）→ 前処理 → LLM 検査 → 後処理 → 修正候補生成。無曖昧性は few-shot（違反例付き）。完全性・変更容易性・単独性は節単位、表構造メタ情報を few-shot table understanding 風に付与。
- 前処理の中身: 「簡潔な文」「係り受け」は GiNZA の解析結果を付与。「誤字脱字」は規則ベースで候補を先に絞り、LLM に判定させる。「場合分け・記載場所・単一要求」は仕様書フォーマットを LLM に推定させ、その情報を付与。
- 主張: LLM 単独では不十分。専門用語を誤字と判定する誤検出が多い。規則ベース前後処理や入力拡張で大きく改善。
- 誤字脱字は再現率が低い（0.47）が適合率は高く、人が見逃した例を拾えていると解釈している（著者の解釈。検証は本文に無い）。
- 限界（本文）: 図と入れ子表は対象外。単一製品・単一ドメイン（車載）。人手正解の件数、LLM 指摘の総数、試行回数、温度は本文に無い。
- 限界（調査者の所見）: 規則を足した条件の改善幅は、LLM 単独と「同じ入力」での比較ではない。前処理の寄与とプロンプト差を分離できない。n 不明のため 1.00 は信頼区間なしの値。
- 「正解なし版 P」は人手判定で、判定者の人数・基準は本文に無い。
- 当製品への示唆: ①LLM 単独で全文を判定させず、形態素・正規表現で候補を先に絞る設計が根拠になる。②ドメイン用語（専門語）を辞書として渡さないと誤字誤検出が出る。③表・入れ子表の構造崩れは評価対象から外れる前提で、スコープを明記すべき。

## 2. デンソー JSAI2025 3Win5-61（本文確認済み）

出典: https://www.jstage.jst.go.jp/article/pjsai/JSAI2025/0/JSAI2025_3Win561/_pdf/-char/en （人工知能学会全国大会 第39回, 2025, 水野・村瀬・不破・塚原・中江）。Q9-5 の続報。

| 項目 | 内容 |
|---|---|
| 目的 | メタモデル構造化で検査精度が上がるか |
| 手法 | 仕様書→知識グラフ（LLM抽出）→検査 |
| モデル | GPT-4o（2024-10-21版）、温度 0 |
| データ | Q9-5 と同じ 73頁の車載仕様書 |
| 条件 | ゼロショット（過去事例は与えない） |
| 比較 | LLM単体 / +表レイアウト / +KG |

評価結果（表1。再現率 R / 適合率 P）:

| ルール | 単体 R/P | +表配置 R/P | +KG R/P |
|---|---|---|---|
| 完全な場合分け | 0.00 / 0.30 | 0.50 / 0.29 | 0.75 / 0.65 |
| 誤った記載場所 | 0.11 / 0.16 | 0.79 / 0.46 | 0.90 / 0.82 |
| 単一の要求 | 0.50 / 0.41 | 0.59 / 0.54 | 0.68 / 0.60 |
| 機能要求の不足 | - / 0.51 | - / 0.78 | - / 0.88 |

- 内容品質（機能要求の不足）は人手の正解が無く、人手が「概要に対し詳細が足りない」等を指摘した箇所を代理正解とし、適合率のみ評価。
- 主張: 構造化で再現率・適合率とも向上。単一要求（文の意味理解が要る規則）は効果が限定的で、ドメイン知識の不足が原因と推測。
- 失敗例（本文）: LLM 単体は概要と詳細の区別を誤る。ID が飛ぶと「定義不足」と誤指摘。KG 化で解消。表が正しく Markdown 化されない場合は構造化も失敗。
- 注意: 同じ「完全な場合分け」の LLM 単体再現率が Q9-5 は 0.57、本論文は 0.00。プロンプト条件（Q9-5 は few-shot、本論文は最小限の説明のゼロショット）が違うためと推測されるが、本文に説明は無い。数値を条件抜きで引用してはならない。
- 限界: 単一仕様書、図は未対応、ゼロショットのみ、n 不明。
- 当製品への示唆: ①書式依存の誤検出は「構造を先に確定してから検査」で減る。表中心の仕様書では重要。②意味理解型の規則（単一要求、曖昧さの意味判定）は同じ LLM では伸びにくい。人手確認前提で出す。

## 3. 有賀・林・佐伯 IPSJ SIG SE179-4（本文確認済み）

出典: https://ipsj.ixsq.nii.ac.jp/record/90471/files/IPSJ-SE13179004.pdf （情報処理学会研究報告 Vol.2013-SE-179 No.4, 2013/3, 東京工業大学）。LLM ではなく構文解析ベース。

| 項目 | 内容 |
|---|---|
| 目的 | IEEE 830 品質特性の問題点を自動検出 |
| 手法 | 語句・構文・文間関係・構成の4分析 |
| 解析器 | CaboCha（係り受け）、日本語WordNet等の類義語 |
| 品質特性 | 6特性（α群12項目、β群2項目） |
| 検出評価データ | ワイン予約販売システム（14要求） |
| 正解 | 著者の1人が作成（問題点 53件） |
| 支援評価データ | 会議室予約、航空機予約（各20行） |
| 被験者 | 情報工学の学生 3名 |

評価結果:

| 指標 | 値 |
|---|---|
| 全体 適合率 | 0.66（53件中） |
| 全体 再現率 | 0.87 |
| 適合率 1.0 の項目 | 10項目中6（N/A 除く） |
| 再現率 0.9 以上 | 12項目中7 |
| 非あいまい性・追跡可能性 | 特に高い |
| β群 | 2項目とも正しく判定 |

- 被験者実験: 向上は 8 項目（非あいまい性 b-2/d/e、変更可能性 a-2/c、完全性 c-2、検証可能性 a、追跡可能性 c）。アンケートで非あいまい性・検証可能性・追跡可能性は被験者全員が 5 段階中 3 以上。それ以外は支援効果なし。「主語省略」は 3 人全員で悪化（主動詞のパターンしか無かったため）。
- 検出失敗: 括弧「（」「）」を含む文で構文解析が失敗。要求文が他の要求文に包含される重複は検出不可。
- 限界: 正解を著者 1 人が作成、例題 1 本、被験者 3 人、ネットワーク遅延で時間不足の可能性、2 仕様書の難易度差。論文自身も「実験結果の限りで」と限定。
- 当製品への示唆: ①構文・パターンの規則検出は、高い適合率で出せる項目と出せない項目が分かれる。項目別に精度を表示する根拠になる。②括弧・入れ子で解析が壊れる前処理上の弱点は、現在も日本語解析器で共通する（GiNZA でも要確認。未検証）。③指摘が増えると被験者に悪影響（誤検出の抑制コマンドを今後の課題としている）。

## 5. 当製品（docverify）への示唆（横断）

- 精度の根拠: 日本語の要求品質検査で「LLM 単独は不十分、規則ベース＋LLM が有効」は、国内の実車載事例（1 製品）と 2013 年の構文解析研究の両方で一致する。ただし両者とも単一ドメイン・小規模で、一般化は未検証。
- 指標は項目別に出す。全体値は項目間の差（0.00〜1.00）を隠す。
- 適合率と再現率を分けて報告する。誤検出（適合率低下）が利用者の信頼を下げる（有賀らの被験者実験での悪化例）。
- 評価の正解は人手インスペクション結果で、網羅性が保証されない。人が見逃した指摘を「誤検出」と数えてしまう問題を両論文とも別途人手判定で補っている。
- 日本語特有の課題として、助詞の曖昧さ、括弧・入れ子での解析失敗、専門用語の誤字誤判定が挙がる。
- 引用してはいけない数値: Q9-5 と JSAI 2025 の同一項目の数値を条件抜きで並べること（上記の矛盾）。有賀らの 0.66/0.87 を現代の LLM 手法の目標値にすること（例題 14 要求の著者作成正解）。
