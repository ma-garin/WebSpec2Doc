# AutoRun 使いにくさ — 5レンズ独立評価の突き合わせ（2026-07-26）

方法: 5名の評価者（レンズ）に**相互参照なし**で同一素材（スクリーンショット5枚＋DOMダンプ＋ソース）を渡し、独立に評価させた。私（レンズ0）の初回評価S1〜S8は各レンズに開示していない。
指摘総数: **52件**（レンズ1: 11／レンズ2: 8／レンズ3: 9／レンズ4: 13／レンズ5: 11）
個票: `docs/design/reviews/lens1〜5-*.md`

## 1. S1〜S8で十分だったか → **不十分だった**

| 判定 | 件数 | 内容 |
|---|---|---|
| S1〜S8と一致 | 6件相当 | 件数矛盾・二重表示・CTA競合・段階数不一致・アシスタント重複・FAB重なり・ツア―遮蔽 |
| **私が見落とした** | **多数** | 特に**異常系・時間切れ・コピーと実態の乖離**の領域が丸ごと抜けていた |

**最大の見落とし: 私は「段階1の表示」しか見ておらず、「時間が経つと何が起きるか」を一切見ていなかった。**

## 2. 3人以上が独立に挙げた指摘（＝確度が高い。最優先で直す）

| # | 指摘 | 挙げた人数 | 該当 |
|---|---|---|---|
| **C1** | **同一画面で未確認件数が「4件」と「0/1件」に割れている** | **4/5**（私＋L2＋L4＋L5） | S1・F2-1・F4-1・F5-3 |
| **C2** | **前進CTAが「承認して次へ」と「確定する」の2系統で競合。一方は活性・一方は非活性** | **4/5**（私＋L2＋L4＋L5） | S3・F2-3・F4-2・F5-2 |
| **C3** | **工程の段階数が画面ごとに11/8/6と食い違う** | **4/5**（私＋L1＋L4＋L5） | S4・F1-11・F4-3・F5-7 |
| **C4** | 「アシスタントに相談」の入口が同一画面に5〜6個 | 2/5（私＋L5） | S5・F5-6 |
| **C5** | QAアシスタントFABが本文に重なり文字が欠ける | 2/5（私＋L5） | S7・F5-4 |
| **C6** | 初回ツアーが操作対象を覆う | 2/5（私＋L5） | S8・F5-5 |
| **C7** | 「基準の確立」が2箇所に重複掲載 | 2/5（私＋L2） | S2・F2-6 |

C1〜C3は独立した4名が到達した。**評価者効果を考慮しても、ここは確実に問題である。**

## 3. 1人しか挙げなかったが、深刻度が致命・高のもの（＝見落とし領域）

**これらは「1人しか見つけていない」のではなく「1人しか見ていない領域」である。優先度を下げてはいけない。**

### 3-1. 承認ゲートが時間で無効化される（レンズ3）
- **F3-1 [致命] 段階承認は2時間で自動的に「未承認のまま」実行へ進み、その事実がログ1行しか出ない**
- F3-2 [高] ログイン待ちは30分後に無言でスキップされる。期限もスキップ結果も画面に出ない

→ **人間の承認を待つ設計なのに、待たずに進む経路が存在する。** AutoRunの中核思想（ベテランQAへの委任＋段階承認）と矛盾する。

### 3-2. コピーと実態の乖離（レンズ1）
- F1-1 [高] 「URLか仕様書を渡すだけ」と書いてあるが、**文書駆動でもURLは必須**
- F1-2 [高] 「全自動」と書かれているが、**開始後に人間の承認が必要なことが受付画面に一切書かれていない**
- F1-3 [高] 既定が**深さ10・最大500ページ**だが、その数値も所要時間の目安も折りたたみの中にしかない

→ 「全自動」を期待して開始した人が、段階1で承認を求められて止まる。**期待の裏切りは、UIの細部より強く「使いにくい」と感じさせる。**

### 3-3. 失敗が失敗として扱われない（レンズ3）
- F3-4 [高] **クロール0画面でも「失敗」にならず、空のまま後続フェーズへ進む**
- F3-5 [中] 生成失敗が「まだ生成されていません」という**未着手の空状態**として表示される
- F3-7 [中] **robots等でスキップした範囲が、結果側に「未検証」として集約されない**

→ F3-7 は本プロジェクトの明示方針「**不在は証明しない（未検証と明記する）**」に直接違反する。

### 3-4. 承認の実効範囲がラベルより広い（レンズ2）
- **F2-2 [致命] 「確定する」の実効範囲がラベルより広く、レビューキューに載る全段階を一括承認する**（コード読解による推論・**実機未検証**）
- F2-4 [高] 自動承認された3件が既定で畳まれ、中身を見ないまま承認が成立する
- F2-5 [高] STEPカード4件のうち出所バッジは1件のみ。残り3件が実測由来かAI生成か区別できない

→ F2-2 が事実なら**承認フローの前提が崩れる。最優先で実機検証すべき。**

### 3-5. 用語の氾濫（レンズ4）
- F4-7 [中] 対象を取得する行為に「解析／クロール／画面分析／観測／事前確認」の**5語**が混在
- F4-8 [中] 「確認」が**事前確認・要確認・未確認・確定の4用法**で衝突
- F4-5 [高] 実測画面数が**ログ7件・本文6画面**で食い違い、差の説明がない
- F4-6 [高] 「停止」が状態と操作の両方に使われ、**実際は待機中なのに「停止中」と表示**される

### 3-6. 視覚（レンズ5）
- F5-1 [致命] 段階承認画面に操作要素が**42個**、うち青塗りCTAが**4個**で視線誘導が成立していない
- F5-9 [中] ホームに「新規解析」ラベルのボタンが**3個**、開始系CTAが計**5個**
- F5-10 [低] 非活性表示が `opacity: .45` でコントラスト比未確保
- F5-11 [低] サイドバーに「テストケース」が**2個**

## 4. 直す順序（推奨）

1. **F2-2 と F3-1 の実機検証**（承認が実際に一括で通るか／2時間で自動前進するか）。**事実なら設計の作り直しが要るため、表示の修正より先。**
2. **C1・C2・C3**（件数矛盾・CTA競合・段階数）＝4名一致。表示修正で済み、効果が最も高い。
3. **F1-1・F1-2**（コピーと実態の一致）。文言修正のみで期待の裏切りが消える。
4. F3-4・F3-7（失敗と未検証の明示）。
5. C4〜C7、F4-7〜F4-8（重複と用語）。

## 5. この評価自体の限界

- 5名は**同一の静止画5枚とソース**を見ている。**同じ素材由来の見落としは5名とも共有する**（例: 段階2〜8、実行結果ページ、ダークモードは誰も見ていない）。人数を増やしても、素材が同じなら埋まらない。
- レンズ2・3の一部はコード読解による推論で、**実機未検証**と自己申告している。第4節の1で検証する。
- 一致件数は「同じ問題を指したか」を私が判定したもので、判定自体が主観である。
- Hertzum & Jacobsen（一致率5〜65%）の通り、**4/5が一致したC1〜C3は例外的に強い信号**であり、1/5の指摘が弱いという意味ではない。
