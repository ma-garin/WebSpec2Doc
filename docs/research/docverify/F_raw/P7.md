# P7 要件品質の評価用データセットとベンチマーク

注: 呼び出し上限 12 回のうち、Semantic Scholar と一部の arXiv 検索が HTTP 429 で失敗した。LLM4RE 評価方法論の SLR、ReqEval、PROMISE NFR 原典、ARTA のライセンス、日本語データは未確認。

## 結論（3 行）
1. 公開で再利用できる要件品質データは少ない。PURE（79 文書・CC BY 4.0）は注釈なし、Promise+ は分類ラベルで品質欠陥ではない。欠陥注釈付きの大きなデータは QuRE（2,111 件）と Veizaga ら（2,725 件）だが、ライセンスは未確認。
2. 最新の LLM 品質評価ベンチ（arXiv 2609.03230）は、最良モデルでも専門家指摘の中央値 47% しか検出できず誤検出 11%。「必要性・正しさ」はほぼ見逃す。精度公開は再現率と誤検出率の両方を出す形が妥当。
3. 取得できた abstract のいずれも注釈者数・kappa を報告していない（本文は未確認）。ここが商用で差別化できる空白。日本語の公開データは見つからなかった（未確認）。

## 勝つための示唆
1. 精度は「再現率＋誤検出率」を専門家基準付きで同時公開する。根拠: 2609.03230 が非対称（47%/11%）を中心結果にしている。
2. 評価セットは PURE（CC BY 4.0）の文を自社で注釈して派生版を公開する。根拠: PURE は注釈なしで商用再利用可能な唯一の大規模コーパス。派生物の再配布条件は CC BY 表示で足りるが、法務確認は未実施。
3. 注釈は 2 名以上の独立注釈＋kappa（欠陥種別ごと）を自前で取り公開する。根拠: 取得した abstract にはどれも一致度が無く、公開すれば信頼性で上回れる。標準値の根拠文献は今回未確認。
4. 欠陥を「機械検出可能（曖昧語等）」と「判断が要る（必要性・正しさ）」に分けて報告し、後者は人の判断支援と明示する。根拠: 2609.03230 と 2308.15057。
5. 日本語の注釈済み評価セットを自前で作り、公開データが無いことを訴求点にする（公開データ不在は検索範囲内の観察で、断定ではない）。
