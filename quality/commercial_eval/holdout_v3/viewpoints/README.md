# holdout_v3 / viewpoints

## 目的
画面の仕様からテスト観点（14カテゴリ）を作る機能の、最終判定用の評価データ。仕様は各画面の本文と入力欄の属性に書き、正解は人が読んで決めた。

## 規模
- 画面数: 28（site/x01.html〜x28.html、一覧は site/index.html）。業務は医療・教育・物流・行政・SaaS設定・金融・製造・人事・運用監視など。
- 外部CDNなし。静的HTMLと小さなインラインJSのみ。
- 仕様が単純な画面（必須観点が2個以下）: 7 画面（x04, x06, x08, x14, x19, x20, x26）。

## 判断基準
- 入力欄の属性（required / min / max / maxlength / pattern / type）、ボタン、本文の記述のどれかに根拠がある観点だけを付けた。根拠が無いものは付けていない。
- normal は表示や操作のある全画面に付けた。
- abnormal は、本文で無効な値（形式・種類の不正）を拒否すると読める場合のみ。範囲外は boundary。
- state_transition は画面内の業務状態の変化、または状態による操作の可否が書かれている場合のみ。画面間のリンク移動と、状態を表示するだけの画面は含めない。
- persistence は「保存した内容が再読み込み後に再表示される」記述がある場合のみ。「保存」ボタンや「保存しました」表示だけでは付けない。
- api は送信先（メソッドとパス）が書かれている、またはフォームの POST/GET 送信先がある場合。クライアント計算のみの画面は付けない。
- 各画面の根拠は expected.json の notes に要約した。

## 意図的な落とし穴
- 「状態」の語があるが状態遷移ではない: x06, x25。
- ボタンが多いが状態遷移が無い: x08, x20。
- 保存ボタンはあるが再表示の記述が無い（persistence を付けない）: x14。
- API記述が無いクライアント計算のみ: x07, x16（x26 は送信先なしと明記）。
- 単純画面（表示のみ・任意項目のみ）: x04, x06, x19, x20, x26 ほか。

## 限界
- 正解は作成者1人の読みで決めており、複数人の合意ではない。境界事例（abnormal と format の重なり、x25 の retry、x23 の条件付き必須）は判断が分かれうる。
- 画面数は28で、カテゴリによっては陽性が少なく、率の誤差が大きい。
- 画面はすべて日本語の静的HTMLで、実在のサーバーは無い。API の応答は検証できない。
- 14カテゴリ以外の観点（アクセシビリティ、性能、セキュリティ等）は評価していない。
