# System06 利用者の流れ

画面は `static/js/docassure.js`・`docassure-diff-panel.js`・`docassure-review-panel.js`。文言は実装のとおり。
画面は `templates/doc_verify.html`（ドキュメント検証）の中の「ドキュメント品質保証」パネル。

## 画面の骨格

- 見出し: 「ドキュメント品質保証」。右に「レポート（Markdown）」「指摘一覧（CSV）」「分析を実行」「閉じる (Esc)」。
- レポートの 2 リンクは分析済みのときだけ出る。
- タブ: 「ホーム」「要件一覧」「指摘一覧」「矛盾」「Trace」「意味差分」「AI レビュー」。後ろ 2 つは差分・レビューのパネルが読み込まれているときだけ出る。
- レビュー（検査）を開いていないときは「レビューを開いていません。一覧からレビューを選んでから開いてください。」と出て、実行できない。

## 1. 取り込み

- 文書は docverify の検査（レビュー）に取り込んだものが対象。専用の取り込み画面は無い。
- 「分析を実行」は本文なしで呼ぶため、検査の passages を 1 文書（D1）として分析する。複数文書の分析は API の `documents` 指定でのみ可能で、画面から指定する口は無い。
- 取り込みには権限 `import_doc`（author・moderator）が要る。
- 未分析の間は「まだ分析していません。「分析を実行」を押すと、文書が次の工程へ進める状態かを判定します。」と出る。

## 2. 分析

- 「分析を実行」を押すと「実行中…」になり、完了後に要件・指摘・矛盾・スコア・Trace を読み込む。
- 失敗時は「分析できませんでした。」＋「文書を取り込んでから、もう一度「分析を実行」を押してください。」。接続失敗は「サーバに接続できませんでした。少し待ってから「分析を実行」を押し直してください。」。
- ホームに「準備状態」「品質スコア」「件数」が出る。

### 準備状態の表示

| 内部値 | 画面の文言 |
|---|---|
| READY | 準備完了 |
| CONDITIONALLY_READY | 条件付きで準備完了 |
| BLOCKED | 進められない |
| REVIEWABLE | レビュー可能 |
| DRAFT | 下書き（評価不足） |

- 「なぜこの状態か」に reasons を出す。AI レビューは「ⓘ AI レビューは未実行です（決定論の分析のみ）。」と注記する。
- スコアは押すと「<名前> の根拠」ダイアログ。評価不能は「評価不能です。点数は付けていません」と出る。
- 件数欄: 「致命的な指摘」「高の指摘」「矛盾」「確認が必要な質問」「つながりの無い要件」。

## 3. 要件の確認

- 「要件一覧」: ID・要件・種別・テスト可能性・指摘数の表。行を押すと詳細が開く。
- 絞り込み: 「すべて」「矛盾あり」「AI 推論を含む」など。
- 詳細に主体・契機・条件・動作・期待結果などの項目と出所が出る（「原文に記載」「原文から導出」「推測（事実ではない）」）。
- テスト可能性: 「テストできる」「一部のみ」「テスト不可」「判定不能」。

## 4. 指摘の確認と判断

- 「指摘一覧」: 重大度・規則・要件・根拠・状態・判断の表。重大度は致命的・高・中・低・情報。
- 検出元の表示: 「規則」「規則＋AI」「人」。確度は「関連度」として出す。
- 各行に「理由」欄、「waiver の期限」欄、ボタン「採用」「却下」「waiver」。
- 理由が空だと「理由が空です。理由を入力してからもう一度押してください。」。
- waiver は理由と期限が要る（API で強制）。期限切れは「期限切れ。再度確認が必要」と出て指摘が再浮上する。
- 状態の文言: 候補・確定・却下・未確認・未解決・採用済み・解決済み・判断済み・免除（waiver）中。

## 5. 矛盾への決定

- 「矛盾」タブに候補ごとの根拠（原文引用）と質問「どちらが正しいですか？…」が出る。
- ボタン「判断を記録する」（conflict_decided）と「矛盾ではない」（rejected）。理由が必須。
- 記録するとサーバが全体を再分析し、スコア・準備状態に反映する。
- 失敗時は「記録できませんでした。…権限を確認してから、もう一度お試しください。」。権限 op は `finding_edit`（moderator・reviewer・scribe）。

## 6. 意味差分・AI レビュー

- 「意味差分」: 前の版との差を「意味の変化」と「原文の差分（生の差分）」で表示。Before（前の版）と After（今の版）を並べる。
- 前の版が無いと 404（画面は API の文言を出す）。
- 「AI レビュー」: 「AI レビューを実行」。送信先が OpenAI のときだけ「文書の一部を外部へ送ります」ダイアログが出て、「同意して送信」か「やめる」を選ぶ。
- 結果の各指摘に「採用する」「却下する」。AI が使えないときは「AI レビューは使えません（決定論の分析のみ）」。

## 7. レポート

- 「レポート（Markdown）」「指摘一覧（CSV）」を押すとダウンロード。JSON 形式は API のみ（画面に導線は無い）。
- 評価不能は数値にせず、レポートにもそのまま出る。

## 8. 再分析

- 文書を更新してから「分析を実行」を押す。人の判断（decisions）は引き継がれて再適用される。
- 直前の要件は `previous_requirements` として残り、意味差分・影響範囲・回帰の比較元になる。
- 期限切れの waiver は再分析で指摘が復活する。

## 画面に導線が無いもの

- baseline・feedback・policy・regression・alignment・テスト候補・影響範囲・書き換え提案・analyzers（状態遷移・判定表・CRUD・非機能）は API のみ。`static/js/docassure*.js` から呼んでいない。
