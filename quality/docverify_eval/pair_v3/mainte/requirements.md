# メンテログ 要件定義書

- 文書名: メンテログ 要件定義書
- 版: 1.0
- 作成日: 2026-10-01
- 作成者: 東和製作所 保全課

## 1 目的・範囲

東和製作所は、工場の設備の点検を紙の点検票で行っており、点検の漏れと故障の対応遅れが起きている。
メンテログは、設備の点検・故障報告・修繕を一つのシステムで管理する。

## 2 用語

| 用語 | 意味 |
|---|---|
| 設備 | 工場に設置された生産用の機械 |
| 作業員 | 点検と修繕を行う保全課の担当者 |
| 点検票 | 点検の項目と結果を記録する帳票 |
| 保全課長 | 保全課の責任者 |

## 3 機能要件

### 3.1 点検

- REQ-001: 設備ごとに、点検の周期（日・週・月）を登録できる。
- REQ-002: 点検予定日の 3 日前に、担当の作業員へ通知する。
- REQ-003: 作業員は、点検票に結果（正常・要対応）を入力し、写真を最大 5 枚添付できる。
- REQ-004: 要対応の結果が入力されたら、保全課長へメールで通知する。
- REQ-005: 点検の履歴は 5 年間保存する。
- 期限が近い点検は、目立つように表示する。

### 3.2 故障と修繕

- REQ-006: 設備の故障は、設備・発生日時・症状を入力して報告できる。
- REQ-007: 修繕の依頼は、次の表の優先度で対応期限を決める。

| 優先度 | 状況 | 対応期限 |
|---|---|---|
| 高 | 設備が停止している | 当日 |
| 中 | 性能が低下している | 3 営業日以内 |
| 低 | 軽微な不具合 | 14 日以内 |

- REQ-008: 修繕の状態は、未着手・作業中・完了で管理する。
- REQ-009: 設備の稼働停止時間を月別に集計し、CSV ファイルで出力できる。
- 保全課長は、修繕費の実績を設備ごとに確認できる。

## 4 非機能要件

- REQ-010: 点検票の保存は、1 件あたり 2 秒以内に完了する。
- REQ-011: 保全課長は Web ブラウザから、承認と集計の画面を利用できる。
- 点検票の入力画面は、現場で使いやすいこと。

## 5 制約

- 工場の構内の端末からのみ利用できる。
- 本書に記載のない機能は、本システムの対象に含めない。
