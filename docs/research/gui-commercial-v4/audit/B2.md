## 続き 3（権限テスト・03 の穴・重なり）
### 権限判定が正規の実行者を塞がないか
- ロールは admin / member の 2 つだけ（auth_store）。画面の「テスト自動化」は管理者だけに出る（pages._may_use_testlab、/systems のカードも role="admin"）。API を同じ判定にしたので、画面で実行できる人（管理者）は塞がない。「テナントの編集権限者」というロールは存在しない。
- 既存テスト 341 件 PASS（test_write_api_permission / ta2 系 / auth 系 / auto_run 系 / ui_contract）。
- 追加: tests/test_testlab_autorun_permission.py 4 件 PASS（認証オン: 一般 403・管理者は通る／認証オフは制限なし／AutoRun ジョブの本人・管理者だけが操作／別テナントは非表示）。

### 03 の穴（実確認で発見）
- 一般ユーザーが、管理者が起動したジョブの中止・状態・レポートを job_id だけで操作・閲覧できた。ジョブ一覧は全テナントのものが見えた。
- 直した（web/routes/auto_run.py）: 起動時にテナントと起動者を記録。読み取りは同テナントのみ、中止・承認・入力送信は起動者か管理者のみ（他人は 403、他テナントは 404）、ジョブ一覧は同テナントのみ。
- AutoRun の起動そのものは全ロールに開放（system_registry の設計どおり）。画面でも一般ユーザーに「開始」が出ることを確認。変更しない。
- 未確認: 起動前から残る旧ジョブ（記録なし）は認証オン時に非表示になる。サーバ再起動で消える一時データのため許容。

### 重なりの原因と修正
- 再現: 幅 1280 以下（縦積みレイアウト）で、完了後に作業列が縮み、はみ出した「静的候補の探索」が下の成果物カードに重なった。
- 修正: components.css の 1280px 以下で作業列・レールを flex: 0 0 auto / min-height: auto にした。完了直後の実画面で重なり 0 を確認。
