ジョブ

対象 URL を投入すると、サーバでクロールを実行します。状態・結果・証跡（誰がいつ投入したか）をこの画面で確かめられます。

1. 投入する

対象 URL と範囲を選んで投入します。同じサイトのジョブが動いている間は投入できません。

2. 状態と結果

ジョブはサーバのメモリに保持します。サーバを再起動すると一覧から消えます（成果物は残ります）。

選択中のジョブ

一覧からジョブを選ぶと、結果と証跡を表示します。

3. 定期クロールの設定

既にある設定の確認と停止だけができます。新しい定期実行はこの画面では作りません。停止は管理者のみです。

4. 端末で実行するコマンド

条件を選ぶと、端末に貼り付けるコマンドを作ります。この画面では実行しません。

終了コード

CI から成否を判定できるように揃えてあります。ci gate も同じ規約で、基準を超えると 1 で落ちます。

コード意味
0正常終了（ci gate は合格）
1完了したが失敗を含む（テスト失敗・ドリフト検出・ci gate の不合格）
2実行エラー（対象に到達できない・設定不備など）
130中止（タイムアウト・シグナル）

知っておくこと

  • ログインが必要な画面は、--login-user / --login-pass を渡さない限りスキップします。 その場合は成果物に「未ログイン範囲のみ」と記録されます。スキップさせたくないときは --require-login を付けると、資格情報が無いときに中止します。
  • 段階承認は CLI では人が判断できないため自動で通します。何を自動で通したかは実行結果に必ず出ます。
  • ローカル・社内の URL（127.0.0.1・社内 IP・社内ホスト名）は、安全のため既定で解析しません。対象にするときは環境変数 WEBSPEC2DOC_ALLOW_LOCAL=1 を付けて実行します。
  • doc に --json を付けると、標準出力は最後の結果 JSON（exit_code・output・ok）だけになり、進み具合のログは標準エラーに出ます。
開発者向けの説明
  • CLI は Flask のリクエストコンテキストを使いません。GUI を起動する必要はありません。
  • 入口は src/cli.py。--json を付けると機械可読の結果を標準出力に出します。
  • CI では ci gate --junit-xml out.xml で JUnit XML を書き出せます。GITHUB_STEP_SUMMARY が設定されていれば要約も追記します。
  • 許容値は --max-failed（テスト失敗数）・--max-added / --max-removed（画面の増減）で調整します。
