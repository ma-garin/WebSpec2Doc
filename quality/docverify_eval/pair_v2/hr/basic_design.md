# 人事評価システム 基本設計書
## 1. 概要
### 1.1 設計方針
- 要件定義書の機能を、Webアプリケーション、リレーショナルデータベース、メール送信の3要素で実現する。
- 認証は既存の社内認証基盤（SSO）に委ね、本システムはパスワードを保持しない。
- 社員情報は人事システムの社員マスタを日次で取り込み、本システムでは更新しない。

### 1.2 システム構成
- Webアプリケーション: 利用者の操作を受け付け、業務ルールを検査する
- データベース: 目標、評価、面談記録、操作ログを保存する
- メール送信: 通知と催促のメールを送る
- 稼働環境: 国内リージョンのクラウド

### 1.3 利用者と権限
| 利用者 | 主な操作 |
|---|---|
| 被評価者 | 目標登録、提出、自己評価、結果の照会 |
| 評価者 | 目標の承認・差戻し、評価、面談記録 |
| 承認者 | 評価結果の最終承認・差戻し |
| 人事担当者 | 期間設定、評価者変更、CSV出力、締切後の編集解除 |

## 2. 画面設計
### 2.1 画面一覧
| 画面ID | 画面名 | 利用者 | 概要 |
|---|---|---|---|
| SCR-01 | 目標登録 | 被評価者 | 目標の登録・編集・提出 |
| SCR-02 | 目標承認 | 評価者 | 提出された目標の承認・差戻し |
| SCR-03 | 自己評価 | 被評価者 | 目標ごとの点数とコメント入力 |
| SCR-04 | 評価入力 | 評価者 | 目標ごとの点数とコメント入力、面談記録 |
| SCR-05 | 最終承認 | 承認者 | 評価結果の確認と最終承認 |
| SCR-06 | 評価結果照会 | 被評価者 | 通知された評価結果と過去の結果の照会 |
| SCR-07 | 進捗一覧 | 評価者・人事担当者 | 目標と評価の一覧、絞り込み |
| SCR-08 | 運用管理 | 人事担当者 | 期間設定、評価者変更、CSV出力 |

### 2.2 画面遷移
- ログイン後は、利用者の権限に応じた最初の画面（被評価者は SCR-01、評価者は SCR-02、承認者は SCR-05、人事担当者は SCR-08）を表示する。
- 目標を提出すると、SCR-01 は読み取り専用の表示に切り替わる。
- 差戻しされた目標は、SCR-01 の一覧に差戻しの印とコメントを表示する。

### 2.3 画面共通事項
- 入力項目の横に、記入例を示すヘルプ文言を表示する。
- 必須項目には印を付け、未入力のまま保存しようとすると項目の下にエラーを表示する。
- 一覧は1ページ50件で表示し、ページ送りを設ける。
- 保存や提出に失敗したときは、画面上部に原因と次の操作を表示する。

## 3. 機能設計
### 3.1 目標登録（REQ-001, REQ-002）
- 被評価者は、評価期間の開始日から10日以内に目標を登録できる。
- 1評価期間の目標は3件以上5件以下とし、範囲外の件数では提出できない。
- 目標ごとに名称と内容を入力する。
- ウェイトは目標ごとに整数で入力する。合計が100でない場合は提出をエラーとする。

### 3.2 目標の提出と承認（REQ-003, REQ-004）
- 被評価者が提出すると、目標の状態を「提出済」にし、被評価者の編集を禁止する。
- 評価者は SCR-02 で目標を承認または差戻しする。承認すると状態は「承認済」になる。
- 差戻しの場合、コメントが未入力なら保存できない。状態は「差戻し」になる。
- 差戻された目標は、被評価者が修正して再提出できる。

### 3.3 評価ピリオドの管理
- 人事担当者は評価ピリオドごとに、目標登録の締切日と評価の締切日を設定する。
- 上期は4月1日から9月30日、下期は10月1日から翌年3月31日とする。

### 3.4 目標の変更申請（REQ-005）
- 承認済みの目標を変更する場合、被評価者は SCR-01 から変更申請を出す。
- 評価者が承認した時点で、変更内容を目標に反映する。承認されるまでは元の内容を保持する。

### 3.5 提出状況の確認
- 評価者は SCR-07 で、担当する被評価者の目標の提出状況を一覧で確認できる。

### 3.6 自己評価と評価者評価（REQ-006, REQ-007）
- 被評価者は SCR-03 で、目標ごとに1から5の点数とコメントを入力する。
- 評価者は SCR-04 で、被評価者の自己評価を表示したうえで、目標ごとに1から5の点数とコメントを入力する。
- 点数は整数のみ受け付け、範囲外の値はエラーとする。

### 3.7 総合評価ランクの判定（REQ-008）
- 評価者が評価を提出すると、評価者の点数とウェイトから加重平均を算出する。
- 加重平均は、点数にウェイトを掛けて合計し、100で割った値とする。
- 総合ランクは、加重平均を次の表に当てはめて自動で判定する。

| 総合評価ランク | 加重平均 |
|---|---|
| S | 4.5以上 |
| A | 3.0以上4.5未満 |
| B | 2.5以上3.0未満 |
| C | 1.5以上2.5未満 |
| D | 1.5未満 |

### 3.8 締切後の編集禁止
- 評価の締切日を過ぎた評価は、編集と提出を禁止する。
- 人事担当者が SCR-08 で解除した評価だけが、再び編集できる。

### 3.9 最終承認と通知（REQ-009, REQ-010）
- 承認者は SCR-05 で評価結果を確認し、最終承認または差戻しを選ぶ。
- 差戻しの場合は評価者へ戻り、評価者が再度評価を提出する。
- 最終承認が確定してから5分以内に、被評価者へ結果通知メールを送信する。

### 3.10 面談記録（REQ-011）
- 評価者は SCR-04 で、面談の実施日と要旨を記録する。
- 要旨は2000文字までとする。

### 3.11 評価結果の照会（REQ-013）
- 被評価者は SCR-06 で、過去5期分の総合評価ランクと目標ごとの点数を照会できる。

### 3.12 催促メール
- 人事担当者が指定した提出期限の2営業日前に、未提出の被評価者と評価者へ催促メールを送信する。
- 催促メールの対象は、状態が「下書き」または「差戻し」のまま残っている目標と評価とする。

### 3.13 CSV出力
- 人事担当者は SCR-08 で、評価期間を指定して評価結果をCSVファイルで出力できる。
- 文字コードは UTF-8（BOM付き）とする。

### 3.14 評価者の変更
- 人事担当者は SCR-08 で、組織変更に伴い被評価者の評価者を変更できる。
- 変更後の評価者は、変更前に入力された目標と評価を引き続き参照できる。

### 3.15 一覧の絞り込み
- 人事担当者は SCR-07 で、目標と評価の一覧を部署・評価期間・状態で絞り込める。

### 3.16 評価結果通知書のPDF出力
- 被評価者は SCR-06 から、評価結果通知書をPDFファイルでダウンロードできる。
- 通知書には、総合評価ランクと目標ごとの点数を記載する。

## 5. 外部インタフェース
| 連携先 | 方式 | 頻度 | 内容 |
|---|---|---|---|
| 社内認証基盤 | SAML 2.0 | ログイン時 | 利用者の認証と社員IDの取得 |
| 人事システム | CSVファイル連携 | 毎日1回 | 社員マスタ（所属・役職・評価者）の取り込み |
| メールサーバ | SMTP | 随時 | 結果通知と催促のメール送信 |

- 人事システムとの連携ファイルは、前日分の差分ではなく全件とする。
- 連携に失敗した場合は、前日の社員マスタをそのまま使い、人事担当者へ失敗を通知する。

## 6. 非機能設計
### 6.1 性能（REQ-014）
- 一覧画面は、同時利用者300名の条件で3秒以内に表示する。

### 6.2 可用性（REQ-015）
- 稼働時間は平日の7時から22時とし、この時間帯の稼働率を99.5%以上とする。

### 6.3 セキュリティ（REQ-016）
- 評価データは、本人・担当の評価者・承認者・人事担当者だけが閲覧できるよう、権限ごとに参照範囲を制限する。
- 通信はTLS1.2以上で暗号化する。

### 6.4 監査ログ
- 評価の登録・変更・承認の操作ログを記録し、3年間保存する。

### 6.5 操作性
- 画面の構成と文言は全画面で統一し、入力項目にはヘルプ文言を表示する。

### 6.6 バックアップ
- データのバックアップを毎日1回取得し、5世代を保持する。
