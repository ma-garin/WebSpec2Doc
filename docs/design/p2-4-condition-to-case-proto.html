現物確認: 画面別設計の条件表は No / テスト条件 / 由来した要素 / 導出技法 の4列（static/js/view-design.js）。 テストケース表には既にフィルタ機構（TCG.filters）があり、 絞り込みの仕組みは作らずに済みます。 ただし条件とケースは独立に生成されており、両者を結ぶ安定 ID はまだありません （それを入れるのが P2-5）。本案は ID を使わず、画面＋由来した要素で絞り込みます。

実装前に決めたいこと

Q1. 安定 ID が無い状態での絞り込みキーは「画面＋由来した要素」でよいですか。
条件とケースは独立生成のため厳密な対応は取れません。取りこぼし（本来該当するのに出ない）や 過剰一致（関係ないケースが出る）が起こりえます。厳密化は P2-5 の condition_id 導入待ちです。 この不確かさを、絞り込みバーに一言（例: 「由来が一致するケースを表示しています」）添える案にしています。
Q2. 件数バッジ（ケース N件 / 0件は赤）を出しますか。
「設計したのにケースが無い条件」が見つかるので入れたいのですが、 Q1 の取りこぼしがあると0件表示が誤報になりえます。出さない選択もあります。
Q3. 逆向き（ケース → 条件）の導線も要りますか。
本案には入れていません。プランの受入は条件→ケースの一方向のみです。
