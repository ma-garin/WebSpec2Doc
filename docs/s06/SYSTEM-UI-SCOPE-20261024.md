## 共通UI

- System01〜09・01app・指揮・共通設定に、共通のコンテキストバーとページヘッダーを配置した。
- topbar-title、topbar-actionsのDOM IDを維持し、既存の画面切替・タイトル・操作更新を共通ヘッダーで受ける。
- 主要入口12件で共有ヘッダーが1つ存在することを確認。通常幅でy=44px・高さ68px、タイトル22px。ページ自体の縦横スクロールは0。
- 文書検証だけのページヘッダー、案件一覧と設定の例外を共通ヘッダーへ統合した。本文の見出しカードは説明・フォーム・操作を保持する。
- 指揮の閉じたdetailsの本文を非表示にし、長い内容はmain内でスクロールできるようにした。開発用の表示状態シミュレーターは利用画面から外した。
- 見切れ検査: 主要入口12件×2幅で2件を発見。指揮の2件を修正し、同画面2幅の再検証で0件。他の11入口は初回0件。

## 複数文書レビュー

- 新規レビューの既定を、文書の種類・数を2つに限定しない「複数文書レビュー」へ変更した。既存の2文書対比は別の選択肢として維持する。
- 既存の通常inspectionとtier/documentsへ接続し、Markdown・Word・Excelを複数登録し、文書の分類・関係を確認する画面へ進む。
- 通常レビューを案件一覧へ含め、登録後に見失わないようにした。アップロード失敗時は同じ作成済みレビューへ再送し、部分成功を黙って完了にしない。
- 3文書（要件・API設計・テスト仕様）の実API取込でadded=3、rejected=0。そのレビューを案件一覧から開き、画面に要件1・設計1・テスト1が表示されることを確認。
- 試験専用レビューはデータ領域から /tmp/ws2d-ui-evidence/smoke-review-5c0d2356ae24 へ退避し、既存案件は変更していない。
- 一般レビューで存在しないpair情報を読み、[object Object]を出す不具合を修正。構造化エラーはmessageを表示する。

## 制約と未検証

- 複数取込APIの対応形式はmd/docx/xlsx。PDF/txtはこの経路では未対応。2文書対比では従来どおりmd/txt。
- 登録できることは、あらゆる文書間の意味的矛盾を自動検出できることを意味しない。分類・検査・追跡の能力は既存実装の範囲。
- ブラウザツールのfileChooser.setFilesがNot allowedで拒否されたため、新規作成からの実ファイル投入の通しは未検証。実API取込と取込後の画面表示を分けて確認した。
- 全Systemの通常以外の各状態・深い画面・商用品質8点以上は未判定。設定画像1枚の独立8.2点を全体評価に使わない。
- pytest・verify-uiは実行許可の回答待ち。未コミット・未push。共有UI変更を正式ゲート未実行のままマージしない。
