## 勝つための示唆
1. 文書単位・文書間の検査: 各社は個々の要件文の採点が中心（Jama・Codebeamer）。要件定義書と基本設計書の対応漏れ・矛盾・追加過多を検出し、章・文の位置を示す。根拠=Jama・Codebeamer・Visure の各項目。
2. 判定の根拠と偽陽性対策: 指摘ごとに原文引用・規則名・理由を出し、却下を学習しない設定または確認 UI を持つ。LLM の偽陽性が高い研究結果があるため、「却下でき、却下理由が残る」ことを必須にする。根拠=学術項目。
3. 日本語の検査規則と測定の公開: 日本語の曖昧語・主語欠落・係り受けの曖昧さに対応し、自前の検証データで適合率・再現率を自社が公開する（競合は未公開）。根拠=Jama（言語未記載）、Codebeamer（独英のみ）、公開精度なし。
4. 検査結果からテスト観点・テスト案を出す: システム/結合テスト担当向けに、同値・境界・異常系の観点を要件文とセットで出し、抜けを可視化。Codebeamer は高レベル要件向けと明記しているため、基本設計の詳細も扱える点で差が付く。根拠=Codebeamer・Visure の各項目。
5. 価格の透明性と単体利用: 競合は別売・見積制で ALM 本体が前提。ALM 不要で文書を取り込めば即使える価格表の公開と、MCP/API でエージェントから呼べる形を用意。根拠=Jama 価格、Visure・Polarion の MCP 訴求。
