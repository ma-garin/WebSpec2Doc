## 原因分析と修正

### B（API）

開発用セット（#310 の評価セット、#312 の holdout）の FN / FP を、修正前の状態で分類した。

| 区分 | 原因 | 件数 |
|---|---|---|
| FN | ベース URL の定数（連結・テンプレートを含む） | 4 |
| FN | ヘルパー関数経由の呼び出し（REA が呼び出し位置を出さない） | 2 |
| FP | 解決できないベース URL を落として、後ろの path だけを候補にした | 2 |
| FP | 到達しないコード（if (false) の中・return の後） | 3 |
| FP | 外部オリジンへの呼び出し | 3 |
| 0 件だった区分 | 文字列連結・テンプレートだけ（定数なし）・相対 URL・XMLHttpRequest・method 指定・path パラメータ・未使用の文字列・コメント・テストデータ・URL に似た文字列 | — |

失効した v3・v4 で見つかった追加の原因: REA が出さない XMLHttpRequest の直接呼び出し、本体が式のアロー関数のヘルパー、関数内の局所変数に組み立てた URL、`api(path)` 型のヘルパーの判定漏れ。

修正（`src/reverse_analysis/api_resolve.py`）: 静的な文字列定数を有界に解決する。同じファイルの宣言を優先し、無ければ入力全体で 1 つだけの宣言を使う。多段の定数も、循環しない範囲で解決する。ヘルパー関数は 3 段まで追う。method は options・XHR#open の引数・ヘルパーの引数から読み、options の無い fetch は GET、動的な値は UNKNOWN にする。構文上到達しないコードの候補は外し、その件数を診断に出す。外部オリジンには origin を付けて、このサイトの API と区別する。JS は実行しない。再代入される変数と、2 つ以上ある宣言は解決しない。先頭（ベース URL）が分からなければ path を出さない。どこからも呼ばれない関数は、HTML のイベント属性から呼ばれうるので外さない。`this.x` のようなプロパティの参照は解決しない（v5 で FN 2 件）。
