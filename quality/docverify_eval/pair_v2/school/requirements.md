# 学校 出欠・成績管理システム 要件定義書

## 1 目的・範囲

### 1.1 目的

本書は、架空の「みどり丘中学校」における出欠・成績管理システム（以下、本システム）の要件を定める。
紙の出席簿と手作業の成績集計をなくし、教員の入力負荷と集計誤りを減らすことを目的とする。

### 1.2 範囲

- 対象利用者は、担任教員、教科担当教員、教務主任、事務職員、保護者とする。
- 対象業務は、日々の出欠登録、欠課時数の集計、定期テストの成績入力、学期末評定の算出、通知表の出力とする。
- 時間割の作成、給食費の徴収、入学者の選抜は範囲外とする。

## 2 用語

| 用語 | 意味 |
| --- | --- |
| 出欠登録 | 授業日ごとに生徒の出欠区分を記録すること |
| 出欠区分 | 出席、欠席、遅刻、早退、公欠、忌引のいずれか |
| 欠課時数 | 生徒が授業を欠いた時間の累計（単位は時間） |
| 担任教員 | 学級を受け持つ教員 |
| 教科担当教員 | 教科の授業と成績を受け持つ教員 |
| 保護者 | 生徒の法定代理人として登録された者 |
| 定期テスト | 学期ごとに実施する筆記試験（中間・期末の2回） |
| 評定 | 学期末に教科ごとに付ける 1 から 5 の段階評価 |
| 通知表 | 学期末評定と出欠の状況を保護者に知らせる帳票 |
| 学期 | 1 年を三つに分けた期間（4月から7月、9月から12月、1月から3月） |

## 3 機能要件

### 3.1 出欠管理

- REQ-001 担任教員は、授業日ごとに自学級の全生徒の出欠登録を行えること。

- REQ-002 出欠区分は、用語表に示した6種から選択できること。

- 遅刻が3回に達した場合、欠席1回として欠課時数の集計に換算すること。

- REQ-003 教科担当教員は、授業ごとに欠課した生徒と欠課時数を登録できること。

- 出欠登録の修正は、登録日から14日以内であれば担任教員が行えること。14日を超える修正は教務主任の承認を要すること。

- REQ-004 教務主任は、欠席が連続3日に達した生徒の一覧を毎日確認できること。

- REQ-005 欠席が連続3日に達した生徒の保護者に、欠席連絡のメールを自動送信すること。

- REQ-011 欠課時数が年間の総授業時数の3分の1を超えた生徒を、警告対象として表示すること。

- REQ-013 教務主任は、学級ごとの出席率を月次で集計し、一覧で確認できること。

### 3.2 成績管理

- 教科担当教員は、定期テストの得点を生徒ごとに入力できること。得点は0以上100以下の整数とすること。

- REQ-006 得点の入力は、CSVファイルの取り込みでも行えること。

- 点数から評定への換算は、次の表のとおりとすること。

| 点数 | 評定 |
| --- | --- |
| 90から100 | 5 |
| 80から89 | 4 |
| 70から79 | 3 |
| 60から69 | 2 |
| 0から59 | 1 |

- REQ-007 学期末評定は、2回の定期テスト得点の平均を換算表に当てはめて自動算出すること。

- REQ-008 教科担当教員は、自動算出した評定を手動で修正できること。修正時は理由の入力を必須とすること。

- 評定を確定した後は、教科担当教員は変更できないこと。確定後の変更は教務主任のみが行えること。

### 3.3 通知表

- REQ-009 担任教員は、生徒ごとの通知表をPDFで出力できること。

- REQ-010 通知表には、学期末評定、欠課時数、出欠区分ごとの回数を記載すること。

### 3.4 閲覧と在籍

- REQ-012 保護者は、自分の子の出欠状況と評定を閲覧できること。出欠登録の内容は、速やかに閲覧画面へ反映すること。

- 保護者は、自分の子以外の生徒の情報を閲覧できないこと。

- 事務職員は、生徒の転出入に応じて、在籍情報を登録・変更できること。

## 4 非機能要件

- REQ-014 性能: 1学級40名の出欠登録は、一括登録の操作から3秒以内に完了すること。

- REQ-015 可用性: 授業日の7時から18時の間は利用でき、月間稼働率は99.5%以上とすること。

- セキュリティ: 無操作の状態が30分続いた場合、自動的にログアウトすること。

- REQ-016 監査: 出欠と成績の変更履歴を、変更者・日時・変更前後の値とともに5年間保存すること。

- 使いやすさ: 操作画面は、教員が迷わず使いやすいものであること。

- REQ-017 バックアップ: データを日次でバックアップし、30日分を保存すること。

## 5 制約

### 5.1 技術上の制約

- 利用者は校内の端末のブラウザから操作する。専用ソフトのインストールは求めない。

- 利用者の認証は、学校の統合認証基盤を利用する。

- 個人情報は校内の管理された環境に保存し、校外へ持ち出さない。

### 5.2 運用上の制約

- 本システムの利用開始は新年度の4月1日とする。

- 年度が替わった後も、前年度の成績は閲覧できる状態で保存する。

- 保守は教務部が窓口となり、利用者からの問い合わせを受け付ける。

### 5.3 前提

- 生徒と保護者の登録情報は、事務職員が年度初めまでに整える。

- 校内の通信環境は、授業日の全時間帯で利用できる。
