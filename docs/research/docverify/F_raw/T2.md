## 本ツールのトレーサビリティ機能への要件
1. 完全率と妥当性を別指標で出す。根拠: Jama LTE が「カバレッジ（完全性）」と「suspect（品質）」を分け、経路ごとに割合と件数を出す。
2. リンクは AI が候補提示し、人が承認する。承認前後を区別して保存する。根拠: Visure が提案＋人の承認を推奨。完全自動確定は誤リンクで完全率を偽る恐れ（この懸念は推論）。
3. ID の無い文書を前提にする。見出し・表の行・段落に本ツール側で安定 ID を付与し、版が変わっても追従する。根拠: 調べた商用ツールは構造化アイテム前提で、ID 無し文書の扱いは確認できなかった。ここが差別化余地（推論）。
4. 文書の版更新時に、変更箇所に紐づくリンクを suspect として列挙し、確認・解除の履歴を残す。トリガーは項目単位で絞れるようにする。根拠: DOORS Next（再インポートで suspect 化）、ModernRequirements/easeRequirements の項目単位トリガー。
5. 表示はマトリクス（行=要件、列=設計）と、層ごとの割合ダイアグラムの 2 種。孤立・欠落を一覧で出す。根拠: ReqView/Visure の RTM、Jama LTE のダイアグラム。
