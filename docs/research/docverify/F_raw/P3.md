# P3 複数の要件・設計文書間の矛盾・不整合・重複の検出（NLI・LLM・形式化、2023〜2026）

注意: 検索 API が 429（レート制限）で大半失敗した。収集できたのは下記のみ。網羅的ではない。範囲は「部分調査」。

## 結論（3 行）
1. 要件の矛盾・重複検出は NLI／LLM／分類器で研究されているが、abstract で確認できた数値は少なく、日本語の要件定義書×基本設計書を対象にした精度は未確認。
2. 2 つの文章から矛盾節を「見つけて対応づける」課題は難しい（最良モデルで矛盾 F1 48.58%）。判定だけなら易しく、抽出・対応づけが律速。
3. 商用では全自動判定でなく「候補提示＋根拠節の対置表示＋人の判断」が現実的。精度は自前の日本語評価セットで測る必要がある。

## 勝つための示唆
1. 判定でなく「矛盾候補の対置表示」を主機能にする。節の対応づけが律速（発見 3）。両文書の該当箇所を並べ、根拠節を引用で示す。
2. 文書全体を LLM に投げず、項目・文単位に分割して候補ペアを絞ってから NLI／LLM 判定する（発見 6 の設計、発見 3 の対応づけ難度）。
3. 誤検出率を抑える設計（信頼度表示・除外学習・人の確定）を入れる。小型モデルは妨害文で誤検出が多い（発見 4）。
4. 自前の日本語・要件×基本設計の評価セット（矛盾・重複・欠落の注入）を作り、適合率・再現率を製品指標として開示する。公開数値は他ドメインで流用不可（発見 3・4）。
5. 領域特化の微調整や専用分類器は小型モデルで効く可能性（発見 3: +15〜28%、発見 2）。ただし要件文書での再現は未確認なので検証が前提。

## 引用してはいけない数値
- 矛盾 F1 48.58%・重複 61.13%（発見 3）: 物語文書での値。要件文書の精度として使わない。
- 小型モデル 33.2% 等（発見 4）: ハードウェア仕様ベンチで、要件の整合確認の精度ではない。
- PassionNet の「F1 13% 差」: 単位（ポイントか相対）と絶対値が未確認。
- 「NLI が LLM に勝つ」（発見 1）: 数値・モデル名・データが abstract にない。
- 74.4%（発見 6）: 要約の一貫性判定で、2021 年・範囲外。
