# ステイノート 基本設計書

- 文書名: ステイノート 基本設計書
- 版: 1.0
- 作成日: 2026-10-05
- 入力文書: ステイノート 要件定義書 1.0

## 1 概要

### 1.1 システム構成

ステイノートは、Web ブラウザから利用する宿泊予約システムである。構成要素は次の 4 つとする。

- Web アプリケーション: 画面表示と業務処理を担当する
- データベース: 予約・在庫・仮押さえの情報を保存する
- 決済代行サービス: クレジットカードの決済を担当する（外部サービス）
- メール送信サーバ: 確認メールとリマインドメールを送信する（外部サービス）

### 1.3 設計方針

- 画面は PC のブラウザ向けに設計し、スマートフォン向けの画面は作らない
- 画面の言語は日本語のみとする
- 要件定義書の要件 ID を引用した設計は、見出しまたは表の中に要件 ID を示す

### 2.1 画面一覧

|---|---|---|---|
| S01 | 空室検索 | 宿泊者 | REQ-001, REQ-002 |
| S02 | 客室選択・申込 | 宿泊者 | REQ-003, REQ-004 |
| S03 | 決済方法選択 | 宿泊者 | REQ-006 |

### 2.2 画面項目

- S01 空室検索: チェックイン日、チェックアウト日、人数を入力する。結果には客室タイプ、空室数、1 泊あたりの料金を一覧で表示する。
- S02 客室選択・申込: 客室タイプと室数（1〜3）を選び、宿泊者名・電話番号・メールアドレス（すべて必須）を入力する。
- S02 備考欄: 備考は複数行で入力し、入力文字数を欄の下に表示する。
- S03 決済方法選択: クレジットカードまたは現地払いを選ぶ。
- S04 予約完了: 予約番号と予約内容を表示し、確認メールを送信したことを伝える。
- S05 予約照会: 予約番号とメールアドレスを入力すると、予約内容と状態を表示する。
- S06 宿泊日変更: 新しいチェックイン日とチェックアウト日を入力する。
- S07 キャンセル確認: 予約内容と、算出した取消手数料の金額を表示する。
- S08 予約一覧: 宿泊日と状態で絞り込み、予約番号・宿泊者名・宿泊日・客室タイプ・状態を表示する。日別の客室稼働率を CSV ファイルでダウンロードするボタンを置く。
- S09 在庫管理: 施設と客室タイプを選び、日別の在庫数を登録・変更する。

## 3 機能設計

### 3.1 空室検索（REQ-001, REQ-002）

- チェックアウト日がチェックイン日より後であることを検証する
- 指定期間の全日で残数が申込室数以上の客室タイプを、空室ありとして返す
- 空室数は、期間内の日別残数の最小値とする。残数は、在庫数から確定予約の室数と有効な仮押さえの室数を引いて求める
- 料金は、客室タイプマスタの 1 泊料金を表示する

### 3.2 予約申込（REQ-003, REQ-004）

- 1 回の申込で選択できる客室は最大 3 室とする
- 宿泊者名・電話番号・メールアドレスが未入力の場合は申込を受け付けず、項目の直下にエラーを表示する
- 備考は 200 文字以内で受け付ける

### 3.3 仮押さえ

- 申込時に、選択した客室を仮押さえテーブルへ登録する。有効期間は 30 分間とする
- 有効期限を過ぎた仮押さえは、1 分間隔のジョブで削除し、残数に戻す

### 3.4 決済（REQ-006）

- クレジットカード: 決済代行サービスへ決済を依頼し、成功した場合に予約を確定する
- 現地払い: 決済を行わず、申込の完了時点で予約を確定する
- カード番号は本システムに保存しない

### 3.5 予約番号の採番と確認メール

- 予約の確定時に予約番号を採番する。予約番号は英数字 10 桁のランダム文字列とし、既存の予約番号と重複した場合は再採番する
- 確認メールは、予約確定時に送信キューへ登録し、メール送信ジョブが 1 分間隔で送信する

### 3.6 予約照会

- 予約番号とメールアドレスの両方が一致した予約だけを表示する

### 3.7 宿泊日変更（REQ-008）

- 変更できるのは、チェックイン日の 1 日前までとする
- 変更後の期間に空室がない場合は、変更を受け付けない

### 3.8 キャンセル（REQ-009）

- 状態を「キャンセル」に更新し、客室を残数に戻す
- キャンセル料は、チェックイン日までの日数に応じて次の表で算出する

| 区分 | キャンセル日 | キャンセル料 |
|---|---|---|
| A | 宿泊日の8日前まで | 無料 |
| B | 7日前〜4日前 | 宿泊料金の20% |
| C | 3日前〜前日 | 宿泊料金の30% |
| D | 当日・無連絡不泊 | 宿泊料金の100% |

### 3.9 リマインドメール（REQ-010）

- 毎日 10:00 に起動するジョブが、翌日がチェックイン日で状態が「確定」の予約を抽出し、リマインドメールを送信する

### 3.10 管理者機能

- 予約一覧: 宿泊日と状態を条件に絞り込んで表示する
- 在庫管理（REQ-011）: 施設ごと・客室タイプごと・日ごとの在庫数を登録・変更する
- 予約の状態は「確定」「キャンセル」「宿泊済」の 3 つとする
- 稼働率出力（REQ-012）: 日別の客室稼働率を CSV ファイルで出力する。客室稼働率は、確定および宿泊済の室数を在庫数で割って求める

### 3.11 ポイント付与

- 状態を「宿泊済」に更新した時点で、宿泊金額の 1% を会員ポイントとして付与する

## 5 外部インタフェース

| 連携先 | 方式 | 用途 |
|---|---|---|
| 決済代行サービス | HTTPS(REST) | クレジットカードの決済依頼 |
| メール送信サーバ | SMTP | 確認メール・リマインドメールの送信 |

- 決済代行サービスの呼び出しがエラーになった場合は、予約を確定せず、S03 にエラーを表示して決済方法を選び直せるようにする
- メール送信が失敗した場合は、送信ジョブが次の起動時に再送する

## 6 非機能設計

### 6.1 性能（REQ-013）

- 空室検索は、在庫テーブルの (facility_code, room_type_code, stay_date) に複合インデックスを設定する。同時接続 100 件の条件で 95 パーセンタイル 3 秒以内を満たすことを、性能試験で確認する

### 6.2 可用性（REQ-014）

- Web アプリケーションとデータベースを 2 系統で構成し、月間の可用性 99.5% 以上を満たす

### 6.3 セキュリティ

- guest_name、phone、email は AES-256 で暗号化して保存する
- 管理者の操作ログを 1 年間保存する

### 6.4 対応ブラウザ（REQ-016）

- Chrome、Edge、Safari の最新版と 1 つ前の版を動作確認の対象とする

### 6.5 操作性

- 入力項目には入力例を表示し、入力エラーは該当項目の直下に表示する
