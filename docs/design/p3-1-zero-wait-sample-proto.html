P3-1 ゼロ待ちサンプル — デザイン案

初回の利用者に、解析を待たずにレポートの価値を先に見せるための導線です。実画面（ホーム／ダッシュボード）の枠の中で提示します。

現物確認の結果（重要）: 既存の「サンプルURLで試す」は URL 入力欄に https://example.com を書き込むだけで、解析は始まりません（static/js/core.js:191）。 「同梱デモで試す」は http://127.0.0.1:8766/ を使うため、利用者が別途 make demo を起動している必要があります。 つまり現状、待ち時間ゼロでレポートを見る手段は存在しません。本案はそこを埋めるものです。

案A: ヒーロー行の「サンプルURLで試す」を置き換える（推奨）

既存ボタンは実質「文字を入れるだけ」で価値が薄いため、同じ位置を本物のサンプルレポートへ差し替えます。ボタンが増えず、視線の流れも変わりません。

案の比較

観点案A（置き換え・推奨）案B（追加）
ボタン数増えない（既存を差し替え）1つ増える
既存の「サンプルURLで試す」無くなるそのまま残る
誤解のリスク低い。「サンプル」が1つに収束する「サンプルURLで試す」「サンプルレポートを見る」「同梱デモで試す」の3つが並び、違いが分かりにくい
空状態からの導線履歴が空のときにも出す（2箇所）オンボーディングカードのみ
オンボーディング接続ステップ表は変えないステップ 0 を足す（3ステップ→4項目になり、見出し「あと3ステップ」と食い違う）

実装前に決めたいこと

Q1. サンプルレポートの中身は、同梱デモサイト（DemoMart・8画面）の事前生成結果でよいですか。
これを demo/sample_report/ にコミットして同梱し、クロールせずに読み込みます。スクリーンショット込みで数MB程度になる見込みです。
Q2. サンプルを開いた後、利用者はどこへ戻りますか。
案: レポート上部に「これはサンプルです」の帯を出し、「自分のサイトを解析する」ボタンでホームへ戻す。サンプルは履歴に残さない（自分の解析結果と混ざらないようにする）。
Q3. 表示するのはレポート全体ですか、一部ですか。
案: 通常のレポート画面をそのまま使う（概要・画面仕様・テスト設計・遷移図すべて）。「一部だけ」にすると価値が伝わりにくいため、全部見せる想定です。
