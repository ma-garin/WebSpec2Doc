# ドキュメント検証のUI更新

対象: 案件一覧・新規作成・対検査・設定。利用画面: localhost:8766/docverify。

## 変更

- 案件一覧では検索と案件を開く操作を優先。案件名は2行まで表示し、工程は現在の工程だけを表示する。
- 「新しいレビュー」で入力ダイアログを開く。レビュー名・要件定義書・基本設計書を指定して対検査へ進む。キャンセル・Esc・背景クリックで閉じ、起点へフォーカスを戻す。
- 対検査は文書の箇条書きと表を整形する。原文はHTMLとして扱わずエスケープし、指摘の引用箇所への強調を維持する。
- 3ペインを広げ、文書タイトルと版を分離。指摘はタイトルを優先し、詳細は選択時に展開する。判定帯をコンパクトにし、本文の高さを確保する。
- 設定の区分ナビ・フォーム・履歴の余白と文字階層を統一する。

## 確認結果

- 8766で一覧から対検査へ移動、指摘選択で文書2箇所の引用強調、検索0件と解除、新規作成の入力不足・キャンセル・Esc・フォーカス復帰を確認。
- 1366×768、1920×1080、1024×660で一覧／対検査を確認。ページの縦横スクロール量はいずれも0。
- check_clipping: 見切れ0件（8画面×2幅）。JS構文確認・git diff --check成功。
- 文書整形の単発検証: PASS=8 / FAIL=0（箇条書き、表、引用強調、HTML無効化、空入力）。
- ブラウザのコンソールエラー0件。スクリーンショットは /tmp/ws2d-ui-evidence/ に保存。
- pytest・verify-uiは実行許可待ち。新規レビューの実ファイル取り込み完了、通信失敗・競合、ダーク表示は未検証。

## 文言変更

| 変更前 | 変更後 | 理由 |
|---|---|---|
| レビュー名で絞り込む | レビューを検索 | 一覧での操作を短く示す |
| 常時表示の作成フォーム | 新しいレビューのダイアログ | 一覧閲覧と入力の目的を分ける |
| 工程5段の小さいチップ | 現在の工程 | 表の可読性を優先する |
