# 勤怠管理システム 要件定義書

| 項目 | 内容 |
|---|---|
| 文書名 | 勤怠管理システム 要件定義書 |
| 版 | 1.0 |
| 作成日 | 2026-10-01 |

## 1 目的・範囲

### 1.1 目的

当社の従業員の出退勤、休暇、時間外労働の実績を電子化し、月次の給与計算に使える勤怠データを確定することを目的とする。
紙の出勤簿と表計算ソフトによる集計を廃止し、集計の手作業を無くす。

### 1.2 範囲

- 対象利用者: 従業員、上長、勤怠管理者、経理担当
- 対象業務: 打刻、打刻修正、勤務区分の判定、休暇、月次締め、勤怠データの出力
- 対象外: 給与計算、シフト作成、人事評価

### 1.3 前提

- 従業員は全員、社内ネットワークに接続した端末から利用する。
- 従業員情報は人事部門が管理し、本システムでは参照だけを行う。
- 法定労働時間は 1 日 8 時間、週 40 時間とする。

## 2 用語

| 用語 | 意味 |
|---|---|
| 従業員 | 当社に雇用され、勤怠を記録する者 |
| 上長 | 従業員の直属の管理職 |
| 勤怠管理者 | 人事部門で勤怠全体を管理する担当者 |
| 経理担当 | 月次締めを実行する経理部門の担当者 |
| 打刻 | 出勤または退勤の時刻を記録すること |
| 打刻漏れ | 出勤の打刻があり退勤の打刻が無い状態 |
| 月次締め | 月ごとの勤怠データを確定し、編集を禁止する処理 |
| 勤務区分 | 勤務を割増率の違いで分類した区分 |
| 有給休暇 | 賃金が支払われる年次の休暇 |
| 時間外労働 | 法定労働時間を超える労働 |
| 深夜労働 | 22:00 から翌 5:00 までの労働 |
| 法定休日 | 毎週日曜日 |

## 3 機能要件

### 3.1 打刻

**REQ-001** 従業員は、Web 画面から出勤と退勤の打刻を行える。
- 背景: 紙の出勤簿を廃止し、打刻時刻を電子的に確定する。

**REQ-002** 打刻は 1 日に最大 4 組（出勤と退勤の組）まで登録できる。
- 背景: 中抜けや分割勤務を記録する。

打刻漏れが発生した場合、システムは従業員へ速やかに通知する。
- 背景: 打刻漏れの放置を防ぐ。

**REQ-003** 従業員は打刻の修正を申請でき、申請は打刻日の翌営業日から 3 営業日以内に限る。承認は直属の上長が行う。
- 背景: 打刻漏れや誤打刻を事後に正す。

### 3.2 勤務時間の区分

**REQ-004** システムは、勤務を次の表の勤務区分に分類し、割増率を適用する。

| 勤務区分 | 条件 | 割増率 |
|---|---|---|
| 通常勤務 | 法定労働時間内の勤務 | 0% |
| 時間外労働 | 1 日 8 時間を超える勤務 | 25% |
| 深夜労働 | 22:00 から翌 5:00 の勤務 | 25% |
| 法定休日労働 | 法定休日の勤務 | 35% |

休憩時間は、勤務時間が 6 時間を超える場合に 45 分、8 時間を超える場合に 60 分を自動で控除する。
- 背景: 休憩の手入力を無くす。

システムは、遅刻、早退、欠勤を勤怠一覧で区別して表示する。
- 背景: 勤怠状況の確認を容易にする。

法定休日に勤務した場合、従業員は振替休日を登録できる。
- 背景: 法定休日労働の代わりに休みを取得する運用に対応する。

### 3.3 勤怠の確認

従業員は、自分の月次勤怠一覧を月単位で確認できる。
- 背景: 自分の勤務実績を締め前に点検する。

**REQ-005** 上長は、配下の従業員の当日の勤怠状況を一覧で確認できる。
- 背景: 出勤状況を把握する。

**REQ-006** 従業員の時間外労働が月 45 時間を超えた場合、システムは上長にメールで通知する。
- 背景: 長時間労働を早期に把握する。

### 3.4 休暇

**REQ-007** 従業員は有給休暇を申請でき、直属の上長が承認する。
- 背景: 休暇の取得を記録に残す。

有給休暇の残日数は、休暇の申請画面に表示する。
- 背景: 残日数を確認したうえで申請できるようにする。

### 3.5 月次締めと出力

**REQ-008** 経理担当が月次締めを実行すると、その月の勤怠データを確定し、以後の編集を禁止する。
- 背景: 給与計算の元データを固定する。

**REQ-009** 勤怠管理者は、月次の勤怠データを CSV ファイルで出力できる。文字コードは UTF-8 とする。
- 背景: 給与計算システムへの受け渡しに使う。

### 3.6 共通

**REQ-010** 利用者は、社員番号（8 桁）とパスワードでログインする。
- 背景: 本人確認を行う。

**REQ-011** システムは、打刻、申請、承認の操作履歴を記録し、3 年間保持する。
- 背景: 事後の確認に備える。

## 4 非機能要件

### 4.1 性能・可用性・セキュリティ

**REQ-012** 主要画面の表示は、95 パーセンタイルで 3 秒以内とする。
- 背景: 始業時の打刻の待ち時間を抑える。

**REQ-013** システムの稼働率は月間 99.5% 以上とする。計画停止は除く。
- 背景: 打刻の受付を止めない。

**REQ-014** パスワードは 8 文字以上で英字と数字を含める。連続 5 回ログインに失敗したアカウントは 30 分間ロックする。
- 背景: 不正ログインを防ぐ。

**REQ-015** データベースは毎日 1 回バックアップを取得し、30 世代を保持する。
- 背景: 障害時に復旧できるようにする。

### 4.2 容量・操作性

システムは、同時に 300 ユーザーがアクセスできる。
- 背景: 始業時と終業時にアクセスが集中する。

画面は使いやすいこと。
- 背景: 利用者に研修を行わなくても操作できるようにする。

## 5 制約

- 利用できるブラウザは、Chrome と Edge のそれぞれ最新 2 版とする。
- 利用は社内ネットワークに限り、インターネットからは接続しない。
- 労働基準法に定める労働時間と割増賃金の規定に準拠する。
- 稼働開始は 2027 年 4 月 1 日とする。
- 保守の問い合わせ対応は平日の 9:00 から 18:00 とする。
