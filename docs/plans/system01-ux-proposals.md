# System 01 使い勝手の改善提案（2026-10-12）

根拠は 2 つ。①Chrome 拡張で主要導線を実機で通した結果（デモサイト `127.0.0.1:8770`、認証オフ 8766）②外部調査 `docs/research/ux-ideas-2026-10.md`。
想定ユーザーはコードを書かない QA（`webspec2doc-target-user`）。

## 1. 実機で通した導線と観測

| 段 | 観測 | 判定 |
|---|---|---|
| URL 入力→画面解析 | 約 2 秒で「8 画面を検出・1 ログイン必要」。ログイン案内が同じ画面に出る | 良い |
| 条件設定 | 画面ごとのチェックで対象を選べる。robots 除外の `admin.html` が**同じ URL で 2 行**出る | 欠陥（軽微） |
| 実行 | 4 段の手順・残り時間・除外件数・停止ボタン・ライブのスクショあり。完了まで 9 秒 | 良い |
| 実行ログ | `INFO:crawler.politeness:...`・`WARNING:crawler.page_crawler:...` の**ロガー名つき生ログ**がそのまま出る | 内部表現の露出 |
| 完了 | モーダル「生成完了」。下部バーの「レポートを見る」で遷移すると**モーダルがレポート画面に残る** | 欠陥（中） |
| レポート | 8 タブ、エクスポートは HTML/PDF/JSON/Excel/Markdown/Mermaid＋ZIP | 良い |
| 1 段目の画面 | URL 入力の直下に「操作を記録」「Selenium IDE 取り込み」が大きく並び、主導線（URL→解析）より目立つ | 情報の優先度 |
| 既存サイト | demomart のヘッダ「差分あり」と、履歴タブの「前回から変更はありません」が食い違う（前回の棚卸しで検出） | 要調査 |

未確認: 解析の失敗（到達不能 URL・タイムアウト）・中止後の途中結果・ログイン後の再解析。

## 2. 提案（推奨順）

判断軸: 効果（想定ユーザーの迷い・誤解を減らす量）／コスト／取り消しやすさ。

| # | 施策 | 効果 | コスト | 根拠 |
|---|---|---|---|---|
| P1 | 完了モーダルを遷移時に閉じる。下部バーとモーダルの「レポートを見る」を 1 つの処理に寄せる | 高（毎回の完了で当たる） | 小 | 実機 |
| P2 | 実行ログを「利用者向けの文」と「詳細（開発者向け）」に分け、既定は前者。ロガー名・レベル接頭辞を出さない。ログ自体は常時表示のまま | 高 | 小〜中 | 実機・規約「実装語を出さない」・メモリ「ログは常時表示」 |
| P3 | 除外 URL の重複を除く | 中 | 小 | 実機 |
| P4 | 1 段目を「URL→解析」だけにし、記録・取り込みは「別の作り方」として折り畳まない副導線（タブ等）へ移す | 高（初回の迷い） | 中 | 実機・調査 #10（最短導線） |
| P5 | 「差分あり」バッジの比較対象を表示に出す（例「前々回比で差分あり」）か、履歴タブと同じ基準に揃える | 中（誤解の防止） | 小〜中（原因調査込み） | 実機 |
| P6 | 生成物に「根拠（取得元 URL・画面）」と「AI 推定／実測」の区別を表示する | 高（成果物の信頼） | 中 | 調査 #8 |
| P7 | 再解析時に前回との差分を並べ、採用・却下を選べるようにする（下書き→確定） | 中 | 大 | 調査 #6・#7 |
| P8 | 中止時に「保存済みの途中結果」を明示してレポートへ進めるようにする | 中 | 中 | 調査 #4。中止は未確認 |
| P9 | 画面を閉じても解析を続け、完了をアプリ内通知で知らせる | 中（長いサイトで効く） | 大 | 調査 #5 |

推奨: P1〜P3 を先に 1 本の PR で直す（小コスト・取り消し容易・放置すると毎回目に入る）。次に P4・P5 を HTML 案で承認を取ってから実装（メモリ「実装前にデザイン承認」）。P6 以降は仕様化してから。
