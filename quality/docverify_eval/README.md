# System 06 精度評価セット（ja_v1）

規則ベースの自動検出（`web/services/docverify/checks.py`）の精度を測るための日本語要求文。
測定は `venv/bin/python scripts/docverify_eval.py`、結果は `result.json`、表示は精度ページ（SCR-06-10）。

## ファイル

| ファイル | 内容 |
|---|---|
| `ja_v1.jsonl` | 1 行 1 文。`id`・`text`・`labels`（正解の規則 ID の集合。空は欠陥なし）・`method`・`role`・`base` |
| `result.json` | 測定結果。手で書き換えない（スクリプトだけが書く） |

## 出所とライセンス

全文を本プロジェクトで自作した。第三者の仕様書・公開データセットの文は含まない（E1_datasets.md「日本語: 公開データなし。自作が唯一の道」に従う）。

## 作り方（`method`）

- `injected`: 欠陥の無い基準文（`role=base`、14 文）と、基準文に欠陥を 1〜2 種注入した文（`role=variant`、`base` に元の ID）
- `authored`: 基準文を持たない自作の文（欠陥あり・なしの両方）
- `real`（実文書）: まだ無い。精度ページでは「未測定」と出す（FR-06-174）

## ラベル（規則 ID）と注釈の方針

ラベルは「人が読んでその欠陥があると判断するか」で付け、検出器の挙動に合わせない（合わせると精度が過大に出る）。

| ID | 付ける条件 | 付けない例 |
|---|---|---|
| `AMBIGUOUS` | 解釈が分かれる語（速やかに・適宜・十分な・簡単に・正しく・最適な・必要に応じて・多数・定期的に・夜間・約/程度つきの近似値 など）。checks の `RD.AMBIGUOUS` と `REQ.AMBIGUOUS_TERM` をまとめて 1 つに数える | 「要約」「制約」の「約」 |
| `REQ.INCOMPLETE` | TBD・未定・検討中・調整中・別途定める・後日・XXX・??? など未決定が残る | — |
| `REQ.OPEN_ENDED` | 等・など・ほか・その他で列挙が閉じていない | 「A または B」 |
| `REQ.UNIVERSAL` | 常に・必ず・決して・いかなる など例外を認めない絶対表現 | 閉じた集合を指す「すべての利用者アカウント」 |
| `REQ.AND_OR` | 「および/または」 | 「および」単独 |
| `REQ.MEASURABILITY` | 時間・量・頻度の制約を述べているのに数値が無い（速やかに・一定期間・高速に・夜間 など。曖昧語と重なってよい） | 未決定と書いただけの文（`REQ.INCOMPLETE` のみ） |
| `REQ.MULTIPLE_REQUIREMENTS` | 1 文に独立に合否を判定できる要求が 2 つ以上ある | — |
