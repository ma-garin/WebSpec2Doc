# AutoRun 動作検証セット — 使い方と仕込み一覧

このセットは AutoRun（文書駆動モードを含む）を実機で検証するための、
**ローカル完結**の検証用サイトと参考文書です。外部サイトに依存しません。

> このファイルは手順書です。AutoRun へアップロードする参考文書は
> `画面仕様書.md` と `要件一覧.md` の 2 点のみです。

## 1. 起動

```bash
# 検証サイト（8767番）
venv/bin/python demo/demo_site.py --site-dir verify_site --port 8767

# WebSpec2Doc 本体（8766番）
WEBSPEC2DOC_PORT=8766 venv/bin/python app.py
```

検証サイト: http://127.0.0.1:8767/

## 2. 事前設定（必須）

ローカルURLは SSRF 保護で既定拒否されるため、設定画面で
**ローカル/プライベートアドレスの許可** を ON にする
（環境変数なら `WEBSPEC2DOC_ALLOW_LOCAL=1`）。

## 3. 検証手順

1. AutoRun を開き、対象URLに `http://127.0.0.1:8767/` を指定する
2. 参考文書として `画面仕様書.md` / `要件一覧.md` をアップロードする
3. モードを **文書駆動** にする
4. 選択基準を切り替えて挙動を比較する
   - `vertex_coverage`（画面網羅）
   - `edge_coverage`（遷移網羅）
   - `reached_target`（到達目標 = `P008` 相当の注文完了）
   - `prime_path`（プライムパス）
5. **バリデーション観測** を ON にして実行する
6. 17ステップの各関門で提示内容を確認・承認する

## 4. 仕込んだ仕様乖離（期待される検出結果）

検証の答え合わせに使う。**AutoRun がこれらを挙げられるかが評価軸**。

| # | 種別 | 文書の記載 | 実装 | 期待される検出 |
|---|---|---|---|---|
| D1 | 必須漏れ | 電話番号 `order_tel` は必須（REQ-006） | `required` 属性なし | 必須指定の不一致 |
| D2 | 桁数不一致 | 氏名 `order_name` は30桁 | `maxlength="20"` | 桁数の不一致 |
| D3 | 桁数不一致 | 郵便番号 `order_zip` は7桁固定（REQ-007） | `maxlength="8"`・書式検証なし | 桁数・書式の不一致 |
| D4 | 未実装画面 | P009 問い合わせ（/inquiry.html） | 画面が存在しない（404） | 文書にあるが実装にない画面 |
| D5 | 文書未記載 | 記載なし | `/campaign.html` が存在（クーポン入力あり） | 実装にあるが文書にない画面 |
| D6 | 要件未充足 | REQ-011 問い合わせ送信 | 該当画面なし | 要件のトレース切れ |

対照群（一致しているはずの項目。誤検知が出たら偽陽性）:

- メールアドレス `order_email`: 必須・100桁・メール型 → 一致
- 数量 `order_qty`: 必須・1〜99 → 一致
- パスワード `password`: 必須・32桁 → 一致

## 5. 画面と遷移

```
P001 トップ ─┬→ P002 ログイン → P003 マイページ ─┬→ P004 商品一覧 → P005 商品詳細
             │                                    └→ P006 注文入力
             └→ /campaign.html（文書未記載）

P006 注文入力 → P007 注文確認 → P008 注文完了 → P003 マイページ
P007 →（入力へ戻る）→ P006 ／ P006 →（キャンセル）→ P004
```

## 6. 検証観点チェックリスト

- [ ] 自動クロールで9画面（P009を除く8画面 + campaign）を検出できる
- [ ] 各フォームの項目・型・必須・桁数を抽出できる
- [ ] D1〜D6 を検出できる（見逃しは「未検出」として記録する）
- [ ] 対照群に誤検知が出ない
- [ ] バリデーション観測が `checkValidity` 由来のメッセージを取得できる
- [ ] 選択基準ごとにテストパス数・内容が変わる
- [ ] robots.txt の Disallow（`/admin_internal.html`）を尊重する
- [ ] 17ステップの各関門で内容が自動提示され、承認まで進める
- [ ] 実行結果ページに証跡（スクリーンショット・ログ）が残る
