# docverify_holdout — 文書検証（要件文の品質規則）用 独立評価セット

measured commit: main 261a053 ＋ 本 PR の作業ツリー（2026-10-20 計測。結果は同じディレクトリの result.json）

## 目的
要件文の品質規則（AMBIGUOUS / REQ.* の 7 ラベル）の検出精度を測る、製品実装から独立した検証用セット。
規則の調整に使った既存評価セットとは別に、未見データでの再現率・適合率・誤検出率を測るために作った。

- n = 183 文（`holdout.jsonl`、1 行 1 文、`id` は H-001 から連番・重複なし）
- 良い文（labels が空）: 70 文（38.3%）
- うち紛らわしい陰性（note が `[紛らわしい陰性]` で始まる）: 27 文
- 複数ラベル付きの文: 11 文

## ラベルの定義と判断基準
定義は ISO/IEC/IEEE 29148 と INCOSE GtWR に従う。
- AMBIGUOUS: 解釈が分かれる語（適切に・柔軟に・使いやすい・適宜・必要に応じて 等）。時間を表す曖昧語「速やかに・迅速に」は AMBIGUOUS のみとし MEASURABILITY は付けない。
- REQ.INCOMPLETE: 未決定のまま（TBD・TBA・未定・未確定・検討中・XXX・〇〇・後日決定・別途定める・調整中）。
- REQ.OPEN_ENDED: 列挙が閉じていない（A、B等 / AなどのB / Aほか / その他）。
- REQ.UNIVERSAL: 例外の無い絶対表現（すべて・全て・常に・必ず・決して・いかなる場合でも・どの〜でも・毎回・一切）。数値が付いていても「一切停止しない」等は該当。
- REQ.AND_OR: 「および/または」「及び／又は」「and/or」「もしくは/および」「かつ/または」型。
- REQ.MEASURABILITY: 合否を判定できる数値が無い量・時間・頻度（十分な・一定期間・高速に・定期的に・しばらく・数か月・大量の・多数の・頻繁に）。数字が別の箇所にあっても、その量自体に値が無ければ該当。
- REQ.MULTIPLE_REQUIREMENTS: 1 文に独立した要求が 2 つ以上（「〜し、〜する」「〜とともに〜する」「〜した上で〜し、〜する」）。

### 紛らわしい陰性の扱い（一貫基準）
- 数値を伴う「以内」「以上」「まで」は MEASURABILITY ではない（合否判定できる）。
- 「〜し、〜する」でも、前半が操作の契機・手段（ボタン押下、カードをかざす 等）で要求が後半の 1 つだけなら陰性。同じ主体が独立した 2 つの振る舞いを果たす場合は陽性。
- 固有名詞（等々力）・名詞の一部（定期預金・定期券・高速道路）・状態値のリテラル（「未定」「検討中」「その他」）は語として一致しても陰性。
- 「必ずしも〜ない」（部分否定）は UNIVERSAL ではない。
- 単なる「または」「および」（「/」付きでない）は AND_OR ではない。名詞句を並べる「とともに」は MULTIPLE ではない。
- 「毎月＋具体的な日」は UNIVERSAL ではない。

## 作成方法
作成者 1 名が、ISO/IEC/IEEE 29148 と INCOSE GtWR の規則記述だけを根拠に、業務ドメイン（EC・勤怠・医療予約・図書館・金融の振込・IoT 機器管理・行政手続き）を散らして手書きした。製品コード（src/ web/ static/js/ scripts/）および既存の評価セット（quality/docverify_eval/）は参照していない（読んでおらず検索もしていない）。製品は実行していない。文の順序は固定シードでシャッフルしている。件数の検証（JSONL 妥当性・id 重複なし・ラベル別件数）は生成スクリプトで確認し、上の表と一致させた。

## 限界
- 作成者 1 名のみで、第二ラベラーによる裁定・一致率（κ）の測定はしていない。
- 境界例（手段＋1 要求の「〜し、〜する」、MEASURABILITY と AMBIGUOUS の境界など）の判断は上記基準に依存し、別の基準では結果が変わりうる。
- 文は人工的に作ったもので、実在の要求仕様書の分布を代表しない。n が小さいため信頼区間は広い。
