# トレーサビリティ機能の要件（要約・2026-10-18）
- 規格は双方向の追跡と孤立項目の検出を求める（二次資料のみ・本文未確認）。粒度は要件 1 件単位で、直接リンクでなくても可とされる
- 商用（Jama・DOORS Next・Visure）は ID 付きアイテム前提。ID の無い文書の扱いは確認できず、QuintSpect の追跡は開発予定。ここが空白
- 日本語の要件→設計の自動リンク回復の研究は見つからない。精度は pair_v1 の trace.jsonl で自前に測る
- 構成: 安定アンカー付与 → 検索で候補 → 判定 → 人が承認（AI は承認しない）。高精度の候補ほど人が崩しやすい実証があり、根拠文を並べて見せる
- 優先順: TR-1 アンカー／TR-2 候補 2 段／TR-3 人の承認／TR-4 孤立要件・孤立設計／TR-5 指標／TR-6 suspect／TR-7 経路設定／TR-8 リンク単位の一貫性／TR-9 証跡と Excel 取り込み
- 指標（自作定義）: 前方・後方カバレッジは承認済みリンクで数え、分母と「候補のみ」件数を併記。suspect 率は別に出す
- 現行 `trace.py` は ID の正規表現の完全一致のみ。pair_v1 の基本設計書は ID を含む行が 2〜14 行と少ない
- 採点器に孤立設計・Recall@k・suspect の評価は無く、拡張が要る。suspect は第 2 版の評価データが要る
- 詳細: `G_traceability.md`。生データ: `F_raw/T1.md`〜`T4.md`
