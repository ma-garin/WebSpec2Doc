# P9 LLM4RE・NLP4RE の SLR とサーベイ（2024〜2026）

## 結論（3 行）
- LLM4RE の SLR（74 本・2023-24）は「要件の検証」への LLM 適用が主流化したと報告するが、評価は管理環境が中心で産業利用・ワークフロー統合は未達。
- NLP4RE の長期の弱点は「提案止まり・採用の証拠が乏しい」こと（Zhao 2020: 404 本）。2024 以降の SLR も同種の課題（実環境での検証不足）を挙げる。
- 未解決は、実務現場での評価、プロンプト制御性・不確実性、データセット不足、LLM 判定の過剰指摘（誤検出）、人間の監督の設計。

## 勝つための示唆
1. 産業環境での評価を示す（実顧客文書での検出率・修正採用率）。根拠: 論文 1、2 は評価が管理環境・実験室止まりで、採用証拠が乏しい。ここが空白で差別化点。
2. LLM 判定の過剰指摘・不確実性を制御する。各指摘に根拠箇所、重大度、人間の採否を付ける。根拠: 論文 4、9、11（制御性の低さ、誤検出、人間の監督の必要）。
3. 検出単独でなく、ワークフローへ統合する（インスペクションの記録、対応するテスト観点への連結、再検査）。根拠: 論文 1（統合が限定的）、論文 10（検証・評価へ労力が移る）。
4. 日本語の欠陥データセットと評価基準を自前で持つ。根拠: 論文 7、8（RE 向けデータ・ベンチマークが少ない）、論文 12（合成データで欠陥識別が伸びる可能性。単一研究）。
5. 曖昧性・完全性・矛盾を決定的に検出できる項目と、LLM に任せる項目を分ける。根拠: 論文 14（QA 用途の分類）、論文 2（detection が中心だが産業採用が弱い）。
