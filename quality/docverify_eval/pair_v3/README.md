# pair_v3 — 未見の評価セット（要件定義書⇔基本設計書 対検査）

形式・採点は `pair_v1/README.md` と同じ（`scripts/docverify_pair_eval.py --dataset quality/docverify_eval/pair_v3`）。

## 題材（6 組、全文自作）

logi（物流配送）／purchase（図書購買）／mainte（設備保全）／event（イベント受付）／ringi（社内稟議）／point（ポイント会員）

## 作り方

- 各組に 7 種の欠陥 type を全て混ぜた。用語ゆれ 3〜4 件（文字がほぼ重ならない言い換え中心＋表記ゆれ 1 件）、余分な設計 2 件（要件と語が重なるが根拠の要件が無いもの）
- 各組に「欠陥ではない言い換え」（要件を別の言葉で正しく反映した設計）を 3 件以上入れた。正解ファイルには載せていない
- ラベルは「人が読んでその欠陥があると判断するか」で付けた。行範囲は quote を含む行を機械で引いた
- 正解ファイルは生成スクリプトで作り、`--validate` は NG=0

## 独立性

- 検出エンジン（`web/services/docverify/`）と pair_v2 は、作成者が一切読んでいない。エンジンの規則に合わせた作りではない
- pair_v1 は形式の手本としてのみ参照した。題材は pair_v1・pair_v2 と重ならない
- 検出エンジンの開発・調整にこのセットを使わないこと

## 限界

- AI 1 名が作成・注釈した合成データ。注釈者間一致（Cohen's kappa）は未測定
- 実文書での精度を示すものではない
