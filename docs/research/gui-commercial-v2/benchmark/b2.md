# 商用 GUI ベンチマーク b2（GitLab / Azure DevOps / Datadog）
根拠は公式ドキュメントのみ。取得 8 回。GitLab Pajamas の empty-state / filtered-search は認証リダイレクトで取得不可。。各製品で取得できなかった観点は未確認（GitLab: 6・8・9、Azure: 6・8・9、Datadog: 1・2・8・9）
## GitLab
- [1] 左固定サイドバー。2 階層のみ、項目名は 1〜2 語、最上位の名称と位置は全プロジェクトで不変。1200px 未満は初期非表示で、オーバーレイで開く。
- [1][2] サイドバー上部の内容が group / project の文脈で切り替わる。ピン留め項目は group・project を跨いで残る。
- [4][7] MR のレビュアー別状態（レビュー待ち / 進行中 / 承認 / コメント / 変更要求）。変更要求は MR をブロックする。
- [7] 承認ウィジェットの文言が状態で変わる（Approve / Approve additionally / Revoke approval）。MR 作成者による自己承認を禁止する設定がある。
- [7] 承認数が満たされても、未解決スレッドや pipeline 失敗でマージはブロックされる。理由が 1 画面に並ぶ。
- 出典: https://design.gitlab.com/patterns/navigation ／ https://docs.gitlab.com/user/project/merge_requests/approvals/
## Azure DevOps
- [1][2] 縦サイドバーでサービス（Boards / Repos / Pipelines）を選ぶ。プロジェクト切替、パンくず、セレクタ、お気に入り、検索ボックスを備える。
- [1] 無効にしたサービスは UI から消える。表示される項目は有効なサービスだけ。
- [7] 承認とチェックはリソース側で管理者が設定し、YAML からは変更できない。承認者、承認者向け指示、自己承認の可否、タイムアウトを設定する。
- [7][4] 承認は 5 区分を決まった順で評価する。拒否で即失敗、タイムアウトでステージは skipped。承認の延期（Defer approval）で有効時刻を指定できる。
- [5][7] チェックのバイパスには管理者権限が要る。誰がバイパスしたかがチェックパネルに残る。チェックの合否ログは pipeline 画面から全文を見られる。
- 出典: https://learn.microsoft.com/en-us/azure/devops/project/navigation/?view=azure-devops ／ https://learn.microsoft.com/en-us/azure/devops/pipelines/process/approvals?view=azure-devops
## Datadog
- [3] ダッシュボードは widget 構成（timeseries / query value / top list / table など）。テンプレート変数で全 widget を一括絞り込みできる。
- [3] 時間セレクタが自動更新間隔を決める（1〜10 分は 10 秒ごと、1 週間以上は 1 時間ごと）。
- [4][5] Monitor 状態ページは「なぜ alert か」を最初に見せる。状態、種別、作成者、チーム、タグ、ミュート状態をヘッダに集約する。
- [5] 評価データ / 元データ / 遷移のグラフ切替で、alert の原因グループを特定する。クエリと通知設定も同じ画面にある。
- [7][6] ヘッダの Resolve は全 alert グループを OK に戻す。個別グループへの適用はできない。ダッシュボード一覧は検索可能。
- 出典: https://docs.datadoghq.com/dashboards/ ／ https://docs.datadoghq.com/monitors/status/
## QA の証跡・承認ツールに移植すべき要素 3 つ
1. 承認者・指示・自己承認禁止・タイムアウトを承認対象側で管理者が設定し、バイパスの実行者を履歴に残す（Azure DevOps / 観点 7）。
2. 承認ボタンの文言を状態で変え、未解決指摘や失敗など「承認数以外のマージ阻害理由」を同じ画面に並べる（GitLab / 観点 4・7）。
3. 状態ページの先頭に「なぜこの状態か」を置き、原因グループへ絞り込める証跡グラフを切り替えて見せる（Datadog / 観点 5）。
