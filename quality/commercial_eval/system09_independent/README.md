# System09（影響度分析）独立評価データ

## 目的
影響度分析（変更文から、確かめ直しが必要な要件・設計・画面・テストの項目を挙げる機能）を、製品の実装と切り離して測るための評価データ。業務ドメインを分け、変更の種類と大きさを偏らせないようにしている。

## 構成とケース数
| ドメイン | ケースファイル | 文書の接頭辞 | ID の番号帯 | ケース数 |
|---|---|---|---|---|
| 図書館 | `cases_library.json` | なし（requirements.md ほか） | REQ-001〜、DSN-001〜、SCR-001〜、TC-001〜 | 10 |
| 勤怠管理 | `cases_kintai.json` | `kintai_` | REQ-101〜、DSN-101〜、SCR-301〜、TC-101〜 | 13 |
| 病院外来予約 | `cases_hospital.json` | `hospital_` | REQ-201〜、DSN-201〜、SCR-401〜、TC-201〜 | 14 |
| 合計 | | | | 37 |

各ケースファイルは `documents`（文書の一覧と種別）、`links`（`[上位ID, 下位ID]` の組）、`cases`（`title` / `change_text` / `expected_items`）を持ち、自分のドメインの文書だけを指す。ID はドメイン間で重ならない。

- 文書は要件定義書・基本設計書・画面仕様書 2 枚・テストケースの 5 枚（図書館は同梱の `schema.sql` を除く）。
- `links` は文書本文の ID 参照から機械的に作った。要件から設計、要件からテスト、設計から画面の 3 種類。勤怠と病院は、各行末の `[REQ-xxx]` `[DSN-xxx]` の参照がそのまま `links` になる。図書館は既存のまま。

## 変更の種類（追加分 27 ケース）
値の変更、項目の追加・削除、文言の変更、計算式（割増率・金額）の変更、権限の変更、外部連携の変更を含む。確かめ直しが必要な項目が 1 件の小さい変更から、13〜15 件の大きい変更（所定労働時間の短縮・締め日の変更・予約枠の細分化など）まで置いた。追加分のうち ID を直接書いたのは 3 件で、残りは業務の言葉だけで書いている。

## 正解の作り方
- `expected_items` は、各ドメインの文書の記述を読んで人が決めた。変更の内容に直接かかわる項目と、その値や処理を引き継ぐ下流の項目（その値を使う計算、表示する画面、確かめるテスト）を含め、変更しても確かめ直す必要がない項目は含めない。
- 製品のコード（src/, web/, static/js/, scripts/）と、作成者側の評価データ（`tests/fixtures/impact_eval/`）は、作成の過程で読んでいない。製品も実行していない。形式を合わせるために読んだのは `tests/fixtures/impact_eval_indep/` のみ。
- 図書館の 10 ケースは `tests/fixtures/impact_eval_indep/cases.json` を `cases_library.json` に改名しただけで、内容は変更していない。

## 限界
- 作成者は 1 名。正解の判断は第二の評価者による裁定を受けていない（裁定なし）。境界の項目（間接的に値が変わるだけの下流項目など）は、別の人なら入れる・外すが分かれうる。
- 文書は評価用に作った小規模なもので、実際の業務文書の曖昧さ・表記ゆれ・長さは再現していない。
- ドメインは 3 つで、いずれも日本語。ケース数は 37 で、割合の差が小さい比較には足りない。
