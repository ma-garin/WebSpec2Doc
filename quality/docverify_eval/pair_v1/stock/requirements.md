# 要件定義書 倉庫在庫管理システム

## 1 目的・範囲

### 1.1 目的
架空の物流会社「北浜ロジスティクス」の第二倉庫では、在庫を紙の台帳と表計算ファイルで管理している。
本書は、この管理を専用の在庫管理システムに置き換えるために必要な要件を定める。
置き換えにより、入庫から出庫までの在庫数を一か所で正しく把握し、棚卸の手間を減らす。

### 1.2 範囲
- 対象: 入庫、出庫、在庫移動、棚卸、在庫照会、発注候補の作成
- 対象外: 会計システムとの連携、運送の手配
- 利用者: 倉庫作業者、倉庫管理者、購買担当者

### 1.3 現状の課題
- 在庫数が台帳と実物でずれ、月末の棚卸に 2 日かかっている。
- 出庫時に賞味期限の遅い商品が先に出てしまい、期限切れの廃棄が発生している。
- 発注の判断が担当者ごとの経験に依存している。

### 1.4 想定規模
- 品目数: 約 3,000 品目
- 棚番数: 約 1,500
- 1 日の入庫: 約 200 件
- 1 日の出庫: 約 400 件

## 2 用語

| 用語 | 意味 |
|---|---|
| 品目 | 在庫管理の単位となる商品。品目コードで識別する |
| 棚番 | 倉庫内の保管場所を示す番号 |
| ロット | 同一の条件で入荷した品目のまとまり |
| 入庫 | 検品を終えた品目を棚に受け入れること |
| 出庫 | 出庫指示に基づき棚から品目を払い出すこと |
| 有効在庫 | 在庫区分が良品である在庫数の合計 |
| 発注点 | 有効在庫がこの数を下回ったら発注を検討する基準数 |
| 在庫区分 | 在庫の状態を表す分類。良品、保留、不良の 3 つがある |
| 差異率 | 棚卸での差異を、システム上の在庫数で割った比率 |
| 入荷予定 | 仕入先から届く予定の品目と数量を記した情報 |
| 出庫指示 | 出庫する品目と数量を指示する情報 |
| 賞味期限 | 品質を保てる期限日。年月日で扱う |
| 倉庫管理者 | 棚卸の指示と承認を行う役割 |

## 3 機能要件

### 3.1 入庫
- **REQ-001 入庫登録**: 倉庫作業者は、入荷予定番号を指定して検品し、実際に受け入れた数量を登録できること。予定数と異なる場合は差異理由を入力すること。
  - 入庫登録が完了した時点で、該当ロットの在庫数に受け入れた数量を加算する。
- **REQ-002 棚番の指定**: 入庫登録では必ず棚番を指定すること。登録されていない棚番は指定できない。
  - 棚番は入力のほか、一覧から選んで指定できること。
- 入荷予定は、CSV ファイルから一括で取り込めること。

### 3.2 出庫
- **REQ-003 出庫登録**: 倉庫作業者は、出庫指示に対して出庫数を登録できること。出庫数は良品の在庫から引き当て、在庫が足りない場合は登録できないこと。
  - 出庫登録が完了した時点で、引き当てたロットの在庫数から出庫数を減算する。
- **REQ-010 ロット管理**: 入庫時にロット番号と賞味期限を登録すること。出庫では、賞味期限の早いロットから先に引き当てること。
  - ロット番号は英数字とし、品目ごとに重複しないこと。
- **REQ-011 期限の警告**: 賞味期限まで 30 日以内のロットを、一覧で確認できること。
  - 一覧は、賞味期限の早い順に並べる。

### 3.3 在庫の照会と区分
- **REQ-004 在庫照会**: 品目コード、棚番、在庫区分のいずれかで在庫を検索できること。
  - 検索結果には、品目コード、品目名、棚番、ロット番号、在庫区分、数量を表示する。
- **REQ-005 在庫区分**: 在庫は次の 3 区分で管理すること。

| 在庫区分 | コード | 引当 | 有効在庫に含む |
|---|---|---|---|
| 良品 | 10 | 可 | 含む |
| 保留 | 20 | 不可 | 含まない |
| 不良 | 30 | 不可 | 含まない |

- 在庫区分を不良に変更するときは、変更理由の入力を必須とすること。
- 数量は 1 以上 99,999 以下の整数で入力すること。

### 3.4 発注点
- **REQ-006 発注点の判定**: 品目の分類ごとに発注点を持ち、有効在庫が発注点を下回った品目を発注候補に挙げること。発注点と発注数量は次のとおりとする。
  - 判定は、毎日の締め処理のときと、出庫登録のときに行う。

| 品目分類 | 発注点 | 発注数量 |
|---|---|---|
| 常備品 | 100 | 500 |
| 季節品 | 50 | 200 |
| 特注品 | 0 | 発注しない |

- 発注候補の一覧は、CSV ファイルとして出力できること。

### 3.5 棚卸
- **REQ-007 棚卸**: 倉庫管理者が棚卸指示を作成し、倉庫作業者が実際の棚の数量を入力すると、システム上の在庫数との差異を算出すること。
  - 差異は、実棚数からシステム上の在庫数を引いた値とし、差異率を併せて表示する。
- **REQ-008 差異の承認**: 差異率が ±5% を超える品目は、倉庫管理者の承認がなければ在庫数に反映しないこと。
  - 承認されるまで、該当品目の在庫数は変更しない。
- 承認の操作は、倉庫管理者の役割を持つ利用者だけが行えること。

### 3.6 在庫移動と履歴
- **REQ-009 在庫移動**: 倉庫作業者は、在庫を棚番から別の棚番へ移動できること。移動元の在庫数を超える数量は移動できない。
  - 移動先の棚に同じ品目とロットの在庫がある場合は、数量を合算する。
- **REQ-012 変動履歴**: 入庫、出庫、在庫移動、棚卸による調整が行われるたびに、日時、利用者、品目、数量を履歴として残すこと。
  - 履歴は削除できないこと。
- 期間を指定して、品目ごとの受払を在庫受払表として PDF で出力できること。

## 4 非機能要件

- **REQ-013 稼働時間**: 平日の 6 時から 22 時まで利用でき、月間の稼働率は 99.5% 以上であること。
  - 計画停止は月に 1 回、日曜に行う。
- **REQ-014 バックアップ**: データは毎日 1 回バックアップし、7 世代を保存すること。
- **REQ-015 認証**: 利用者は ID とパスワードで認証すること。パスワードは 8 文字以上とする。
- **REQ-016 同時利用**: 50 ユーザーが同時に利用できること。
- 在庫照会の結果は速やかに表示すること。
- 操作画面は誰にとっても分かりやすいこと。
- 操作ログは 1 年間保存すること。

## 5 制約

- 利用者の端末は、倉庫事務所に設置した業務用パソコンとし、Web ブラウザで操作する。
- 既存の表計算ファイルの在庫データは、稼働前に 1 回だけ移行する。
- 運用開始は 2027 年 4 月とする。
- 画面の表示言語は日本語のみとする。
- 保管場所は第二倉庫の 1 拠点とする。
- 在庫データは、サーバ上のデータベースで一元管理する。
- 利用者の端末の OS は Windows とする。
