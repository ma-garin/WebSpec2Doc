# b1 商用 GUI ベンチマーク（Linear / Vercel / GitHub / LaunchDarkly）

## Linear
- [2] チームが計画・トリアージの単位。プロジェクトは成果単位、マイルストーンで細分
- [4] チームごとに順序付きステータス。list はステータスでグルーピング、board は列。新規は Triage で採否・担当・優先度を決める
- [6] 同じ作業を別の見方で見る View。表示オプション（list/board・グルーピング・サブグルーピング・並び順）と filter は別物。Cmd/Ctrl+B で切替
- [6] 個人の表示変更は自分だけに適用。「Set as default」でワークスペース既定、「Reset to default」で戻せる
- [1][9] サイドバー構成・密度は未確認（ページに記載なし）
- 出典: https://linear.app/docs/conceptual-model / https://linear.app/docs/display-options

## Vercel
- [2][1] Project > Deployments / Resources などのサイドバー。チーム・プロジェクトの二階層
- [4] 環境は Local / Preview / Production。Preview から Promote to Production、Redeploy、Rollback が操作として並ぶ
- [5] Deployment Details にビルド時間・検出フレームワーク・ログ/エラー。Resources タブで関数・静的資産を検索
- [7][10] Pro/Enterprise は deployment policy で環境別にデプロイ元を制限。Security ロールは Deployment Protection 管理。Viewer は読み取り専用で閲覧のみ
- [10] チーム/プロジェクト二層の RBAC。Contributor は明示割当が無ければプロジェクトに入れない
- 出典: https://vercel.com/docs/deployments/overview / https://vercel.com/docs/rbac/access-roles

## GitHub
- [7] レビュー状態は Comment / Approve / Request changes の 3 種。保護ブランチで必要承認数を強制
- [7] レビュー依頼は個人/チーム指定。CODEOWNERS で変更箇所の担当に自動依頼
- [5] レビューは行単位コメントと suggested change。指摘と判断が PR タイムラインに残る
- [4][5] Actions の実行はリアルタイムのグラフで進捗を表示。ジョブ/ステップ別ログを表示・検索・ダウンロード。実行時間と課金分も確認可
- [6] 実行一覧の絞り込み・注釈は取得ページに記載なし（未確認）
- 出典: https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/reviewing-changes-in-pull-requests/about-pull-request-reviews / https://docs.github.com/en/actions/monitoring-and-troubleshooting-workflows/about-monitoring-and-troubleshooting

## QA の証跡・承認ツールに移植すべき要素 3 つ
1. 承認状態を Approve / Request changes / Comment の 3 種に固定し、必要承認数を強制 + 担当自動割当（GitHub・観点 7）。指摘と判断を時系列に残す（観点 5）
2. 環境別の昇格ゲート: Preview から Production へ Promote / Rollback を明示操作に（Vercel・観点 4/7）。ロール別に操作を絞り、Viewer は読み取り専用（観点 10）
3. 個人ビューと既定ビューの分離（Set as default / Reset）と filter / 表示オプションの分離（Linear・観点 6）。一覧は list/board 切替とグルーピング
