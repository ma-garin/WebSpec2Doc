## 事例（製品ごと）

### dbt（Catalog / Explorer の lineage）
- 型: Overview から Explore Lineage でグラフ表示。ノードは種類ごとに色とアイコン。右下の Lenses で状態を重ねる。
- 良い点: Lenses の Test status は Pass/Error/Fail/Warn/Skipped/Reused のバッジと色を付け、複数テストは最悪値で表示。大きく縮小するとバッジの色だけ残る。右クリックで上流のみ・下流のみ・両方に再フォーカス。検索式 `+orders` で上流を絞れる。
- 悪い点: 既定ではテストとマクロを非表示。巨大プロジェクトは描画されないことがあり、セレクタで部分集合を指定する前提。既定レイアウトの記述は未確認。グラフと表の切り替えは無く、Resources タブの表と検索結果が別画面。
- 出典: https://docs.getdbt.com/docs/explore/explore-projects （閲覧済）

### DataHub
- 型: 公式の影響分析は Lineage タブ。上流/下流を切り替え、依存の段数を選び、結果を一覧で出す。
- 良い点: 既定は 1 段で重い検索を避ける。種別・プラットフォーム・オーナー等で絞り込み、CSV で書き出せる（検索結果の要約から）。
- 悪い点: グラフ画面の操作（強調・レイアウト）は公式 docs で確認できず。問題ノード強調も未確認。
- 出典: https://docs.datahub.com/docs/act-on-metadata/impact-analysis （検索結果の要約のみ。ページ本文は未閲覧）。lineage 機能ガイドのページは 404 または移転で未確認。

### Atlan（データリネージ）
- 型: 基点資産から左右の + で上流/下流へ展開。右下に可視度スライダ、ミニマップ、凡例、全画面、現在地へ戻るボタン。
- 良い点: 100 件超で確認ポップアップ。ホバーで種別・オーナー・利用状況・Monte Carlo/Soda の品質情報を表示。Find in canvas 検索。可視度スライダで選択した系譜の外を薄くする。品質・認定・お知らせを表示/非表示にできる。
- 悪い点: 選択ノードの上流/下流が強調されるかは記述なし。表への切り替えと問題ノードの視覚強調は未確認。影響分析は View/Download impact の別操作。
- 出典: https://docs.atlan.com/product/capabilities/lineage/how-tos/view-lineage （閲覧済）

### Datadog Service Map
- 型: ノード=サービス、辺=呼び出し集計。顧客側が左、原因になりやすいサービスが右。
- 良い点: ノードの枠を赤・黄で表示。Service Health は Watchdog 異常・ページ中のモニタ・インシデントを 1 状態に束ねる。ホバーで流れを動く線で示す。クリックで隔離表示し、1 段ずつ辿れる。チーム/アプリでグループ化。フィルタ後は経路が中抜けする箇所を折りたたみノードで表示。関連テレメトリへリンク。
- 悪い点: 数百〜数千ノードでは絞り込みに頼る。一覧への切り替えは記述なし。
- 出典: https://docs.datadoghq.com/tracing/services/services_map/ （閲覧済）

### Backstage（Software Catalog の Catalog Graph）
- 型: エンティティ関係のグラフ。ページ上部のフィルタで制御。
- 良い点: 最大深さ（1〜無限）、向き（上下左右）、種別・関係の絞り込み、関係の双方向表示の切り替え。深さ 1 と dependsOn のみ、といった初期状態を設定できる。
- 悪い点: 選択エンティティの強調、問題の強調、表への切り替えは確認できず（概念ページはグラフ UI に触れていない。検索結果の要約のみ）。
- 出典: https://backstage.io/docs/getting-started/viewing-entity-relationships/ （検索結果の要約のみ。本文は未閲覧）。https://backstage.io/docs/features/software-catalog/creating-the-catalog-graph （閲覧済。UI の記述なし）

### Nx（project graph）
- 型: `nx graph` でブラウザ表示。フォルダ単位の複合ノードと個別ノードの 2 表示。
- 良い点: フォーカス＋近接度、フォルダでグループ化、ノードの手動表示/非表示、検索。複合ノードはその場で展開できる。ツールチップで開始・終了を指定すると依存の連鎖を辿れる。辺をクリックするとその依存を生んだファイルが出る。`--affected` で影響を受けるプロジェクトを強調（色は未確認）。
- 悪い点: 循環依存の表示、グラフと一覧の同期は記述なし。
- 出典: https://nx.dev/features/explore-graph （閲覧済）。affected は https://nx.dev/nx/affected-dep-graph （検索結果の題名と要約のみ）

### Obsidian（Graph view）
- 型: 力学配置。円がノード、線がリンク。被リンクが多いほど大きい。
- 良い点: グループ＝検索語で色付け。孤立ノードの表示切替。存在しないノートへのリンクを隠す設定。ローカルグラフは開いているノートから深さ指定。矢印で向きを表示。ホバーで接続を強調。
- 悪い点: ホバー時に他を薄くするかは記述なし。規模が大きい場合の扱いは力のパラメータ調整のみ。問題という概念は無い。表との同期なし。
- 出典: https://obsidian.md/help/plugins/graph （閲覧済）

## 共通する成功パターン
1. 全体を最初から描かず、基点を決めてから上流/下流へ展開する。1 段から始める。（Atlan、DataHub、Backstage、Nx）
2. 問題は「重ねる層」として出す。状態バッジと色を切り替えで重ね、縮小しても色だけ残る。（dbt Lenses、Datadog 枠色）
3. 複数の異常は最悪値で 1 状態に束ねる。（dbt Test status、Datadog Service Health）
4. 選択時は上流のみ・下流のみ・両方を選んで再フォーカスし、範囲外を薄くする。（dbt、Atlan、Datadog）
5. 規模対策は絞り込み、深さ上限、グループ化、折りたたみの組み合わせ。（Nx、Datadog、Backstage、dbt）
6. 辺にも根拠を持たせる。辺をクリックすると原因ファイルが出る。（Nx）
7. 影響の確認と共有は一覧と書き出しで担保する。グラフは理解用、一覧は網羅用。（DataHub、Atlan）
8. 色に頼らずバッジ、アイコン、凡例を併用する。（dbt、Atlan）

## 本製品への適用案
1. 起点は「課題のある文書」にする。常設表示は全件の図でなく、課題文書とその直上の上位文書から始め、上流/下流を 1 段ずつ展開する。
2. 問題は 3 種を別々の記号で示す: 上位との食い違い=枠色、逆向き参照=赤い辺と矢印、重複=二重枠。ノードにバッジ（文言付き）を付け、色だけにしない。複数該当は最も重い 1 つを代表に出す。
3. 文書を選ぶと上位（従う先）と下位（従う側）を濃く、他は薄くする。右クリックでなく、ボタンで「上位だけ／下位だけ」を切り替える。
4. Tier1〜4 を行（層）に固定した階層配置にする（力学配置は使わない）。逆向き参照は層をまたいで上へ向かう辺として一目で分かる。
5. 同じ画面に課題一覧の表を並べ、行選択とノード選択を同期する。辺をクリックすると、食い違いの根拠（該当箇所）を示す。表は網羅確認用に CSV 書き出し可。
