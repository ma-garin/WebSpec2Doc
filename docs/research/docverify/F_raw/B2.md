# B2 国内法人が生成AI SaaSを採用するときの必須要件（2025〜2026の新規・改訂）

## 結論（3 行）
- 2025〜2026 は法・指針が動いた年。AI事業者ガイドライン(1.1→1.2系)、AI推進法とAI基本計画・適正性指針、ISMAP管理基準改定案、令和8年改正個人情報保護法。いずれも「ソフトロー中心＋調達側の要件化」で、SaaS側は証跡で示せる必要がある。
- 既知14項(E4)に加え、新規で効くのは (1)ISMAP/ISMAP-LIU登録の有無(自治体は必須化例あり) (2)AIエージェント等の新リスクへの対応明示 (3)改正個情法で変わる「統計作成・AI開発」例外の扱いの明示 (4)金融向けの運用ルール継続見直しの証跡。
- 検索は WebSearch の要約が中心で、一次資料(官公庁PDF)の本文は未確認。特に AI事業者ガイドライン第1.2版・個情法改正の条文は「未確認」扱い。

## 勝つための示唆
1. ISMAP-LIU(または同等の第三者監査)の取得計画と、外部LLM提供元のISMAP登録状況を調達書類に明記する。根拠=発見5・6(自治体で必須化例)。
2. AI事業者ガイドラインの七原則・リスクベースに対する自己適合表を同梱し、版(1.1/1.2)と対応日を明示。AIエージェント機能を持つなら新リスクの扱いを書く。根拠=発見1・2。
3. 「顧客の設計書を学習・統計作成・AI開発に使わない」を契約・設定で既定オフにし、改正個情法の例外が適用されても顧客データには適用しない旨を明記する。根拠=発見7・8(法が緩んでも顧客の機密要求は残る)。
4. 金融向けに、モデル・プロンプト・ルール変更履歴と精度の定期再評価の記録を出せるようにする(運用ルール継続見直しの証跡)。根拠=発見9・10。
5. 外部LLM送信先の国・事業者・再委託先を一覧化し、版管理して顧客監査に出せる形にする(ISMAP管理基準の事前確認の流れに合わせる)。根拠=発見4。
