# 開発速度ハーネス（現行・順守必須）

経緯・根拠・撤回済みの記述は `docs/process/speed-harness-history.md`（自動ロードされない）。
消費構造の実測は `docs/process/token-economics.md`。本ファイルは常時ロードされるため短く保つ。

## H-0. 最優先の 3 つ

1. **この作業ツリーは複数の Claude セッションが共有する。**着手前に必ず `git pull --ff-only`
   してからブランチを切る。`git add` はパスを明示する（`-A` / `commit -a` は他セッションを巻き込む）。
   `git status` に自分が触っていない変更があれば他セッションのもの。**触らない・退避しない・commit しない。**
   `git checkout .` / `git reset --hard` / `git stash` は他セッションの未コミット作業を消すため禁止。
2. **出力を減らすことが最大の節約である。**実測で cache_read 244M の実質すべてが
   自分の過去出力の再読だった（再読総量 ≒ 平均出力 × N²/2）。平均 1,312 → 400 トークンで**総消費 74% 減**。
   説明・要約・進捗報告・相槌・選択肢の列挙はすべてこの項に乗る。報告は 3 行。表は 1 個まで。
3. **CI と自己ウェイクは厳禁。**`.claude/rules/no-ci-no-wakeup.md` を参照。フックが物理的に拒否する。

## H-1. 着手前 3 行（必須出力）

```
目的: <1行>
見積: 自分 n 往復 + 委譲 m 本（≒ X 分）
検証: <何を・何周で確認するか。既定は 1 周>
```

見積は**対象を計測してから出す**（`wc -l` で行数を数える）。計測していないなら「未計測」と言う。
追及されても根拠が変わっていない限り数字を下げない。

## H-2. 環境（その場で探索しない。ここからコピーする）

```bash
# 検証用サーバ（認証オフ・ブラウザ自動オープンなし）。8765 は共有なので自分は 8766 以降を使う
kill $(lsof -ti:8766) 2>/dev/null; FLASK_TESTING=1 WEBSPEC2DOC_ALLOW_LOCAL=1 \
  WEBSPEC2DOC_AUTH_MODE=off WEBSPEC2DOC_PORT=8766 nohup venv/bin/python app.py > /tmp/ws2d.log 2>&1 &
curl -s --retry 15 --retry-delay 1 --retry-connrefused -o /dev/null -w "%{http_code}" http://127.0.0.1:8766/
```

- `FLASK_TESTING=1` を必ず付ける（付けないとユーザーのブラウザにタブが増える）。
- **8765 は共有の 1 台。**自分が起動した場合とユーザーの明示指示以外、無断で再起動しない。
  停止は `kill $(lsof -ti:<自分のポート>)`。`pkill -f "venv/bin/python app.py"` は使わない。
- **テンプレート・CSS・JS は再起動後にのみ反映される。**全部編集してから 1 回だけ再起動。
- 認証停止は `WEBSPEC2DOC_AUTH_MODE=off`（web/auth.py）。auth.db は触らない。
- Playwright MCP のスクショは `filename` に scratchpad の絶対パスを最初から指定する。

| 場面 | 標準 |
|---|---|
| サーバ起動を待つ | `curl --retry N --retry-delay 1 --retry-connrefused` |
| 一時ファイルの片付け | `mv <対象> <scratchpad>/`（削除しない） |
| コミット対象の指定 | `git add <path...>`（パス明示） |
| ファイル読み | 範囲指定（`sed -n`・Read の offset/limit）。全文読みをしない |

## H-3. UI 作業の型

1. 編集を全ファイル分まとめて行う（1 修正 → 1 確認を回さない）
2. 再起動 1 回 → 対象画面のスクショを連続で全部取る → まとめて読む
3. 直しが出たら「全修正 → 1 回検証」をもう 1 周。**上限 2 周。**3 周目が要る状態は設計不良。
4. **UI を触った変更は、コミット前に必ず** `venv/bin/python scripts/check_clipping.py http://127.0.0.1:8766` を通し（見切れ 0 件）、対象画面を**最下部まで**撮って見る。H-6 の「要求時のみ」の例外（INC-2026-003・2026-10-06 保守者指示）。
   報告は「入れたもの／入れていないもの」を分けて書く。外部へのリンクを「組み込み」と呼ばない。

**評価の前に必ず自分で操作する。**作成 → 実行 → 判断 → 完了 の主要導線を実際に通す。
スクリーンショットを見るだけの評価は評価とみなさない。最初の 1 操作で分かる欠陥を、
文言・色・余白の指摘より優先する。既存の同種画面と**レイアウト方式・入力方式・ナビ位置**を
突き合わせる（基準は `static/css/ta2.css`: `html,body{overflow:hidden}`・`grid-template-rows`・
`min-height:0`・内側だけ `overflow:auto`）。指摘は computed style・保存済み JSON・API 応答で裏を取る。

## H-4. 委譲（既定は「自分でやる」）

旧「複数並列起動を必須」は撤回した。損益分岐は実測で次のとおり。

    委譲が得 ⟺ (自分の文脈に載る量) × (残りターン数) > サブエージェントの総消費

サブエージェント 1 本の実測は 57k〜90k トークン。**取り込み量が 10k トークン未満、
またはセッション終盤なら、自分でやるほうが安い。**委譲するのは、大量の外部情報を
序盤に取り込む調査など、この式を満たす場合に限る。

委譲するときは:
- 1 本 = 1 ファイル・1 目的。担当ファイル以外を編集させない。
- 環境情報（URL 一覧・API 一覧・既知不具合・禁止事項）をプロンプトに同梱し「再調査禁止」と明記する。
- ツール実行上限を明示し、**90 秒で打ち切る**（生存確認をしない）。
- **報告本文を返させない。**成果物をファイルに書かせ、返答は 1 語にする
  （返答は自分の文脈に入り、以後の全ターンで再読される）。
- 作った本人に検証させない。検証系は「壊れている箇所を探せ」で出す。

## H-5. 進捗はステータスラインに任せる

**本文での途中報告を禁止する。**1 分超の見込み作業は開始時に見積を 1 行だけ書き、同じ bash に
`python3 .claude/hooks/progress.py start "<タスク名>" <見積秒>` を連結する。以後、完了まで
ユーザー向けの本文を書かない。ステップ境界は `progress.py step` を既存コマンドに連結するだけ。
完了時に `progress.py done` を連結し、3 行以内で報告する。詳細はファイルに置く。

## H-6. ゲートとコミット

- **pytest / make test / verify-ui / lint はユーザーが要求した時だけ実行する。**
  コミットは `--no-verify` で直行。無断のゲート実行は `.claude/hooks/block-gates.py` が拒否する。
- 手順は一直線: `git pull --ff-only` → ブランチを切る → `git add <path...>` →
  `commit --no-verify` → push → PR 作成 → マージ（作成とマージは別コマンド）。
- **検証を省いた箇所は「未実行」「未検証」と明記して納品する。**黙って省くのとは別物。

## H-7. 違反時

見積の 1.5 倍を超えたら、原因 1 行を `docs/process/speed-harness-history.md` の実測欄に追記する。
超過が 2 回続けて同方向に出たら、工程ではなく見積の式を疑う。
ゲート（破壊操作の確認・pre-commit）は削らない。
