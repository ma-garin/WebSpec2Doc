# テスト観点生成の正解データ

## 目的
製品が画面から生成する「テスト観点」が、QA の専門家が必要とする観点をどれだけ網羅しているかを測る独立した正解データ。製品の実装とは無関係に作った。

## 構成
- `site/`：静的サイト（`index.html` と `v01.html`〜`v23.html`）。外部 CDN なし
- `expected.json`：画面ごとの必須観点（カテゴリ ID）と根拠（notes）

## 画面数
n = 23（必須観点の延べ数 101、1 画面あたり 1〜8 個）

## カテゴリ別の件数
| ID | 名称 | 出現画面数 |
|---|---|---|
| `normal` | 正常 | 22 |
| `abnormal` | 異常値の入力 | 5 |
| `boundary` | 境界値 | 12 |
| `required` | 必須 | 14 |
| `format` | 形式 | 9 |
| `state_transition` | 状態遷移 | 5 |
| `permission` | 権限 | 4 |
| `error` | エラーの表示と回復 | 10 |
| `api` | API 連携 | 14 |
| `persistence` | 保存と再表示 | 6 |

## 正解の作り方
- 画面仕様（HTML 属性と画面上の説明文）から、QA の観点で人が決めた
- 製品コード（src/, web/, static/js/）は参照していない。製品も実行していない
- `required_viewpoints` はその画面で必ず要る観点だけに絞り、過剰には付けていない
- 簡単な画面（1〜2 観点）と複雑な画面（5 観点以上）を混在させた

## 限界
- 作成者は 1 名で、裁定（第三者による合意）は行っていない
- 画面からカテゴリへの対応づけ自体が主観を含む
- 表現の違いは評価側でカテゴリ ID に寄せる前提で、ここでは ID のみを使う
