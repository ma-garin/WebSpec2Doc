# 学校 出欠・成績管理システム 基本設計書

## 1 概要

### 1.1 設計方針

本書は、要件定義書に示した出欠・成績管理システムの基本設計を定める。
利用者は校内の端末のブラウザから操作する Web アプリケーションとして構成する。
要件との対応を示すため、該当する箇所に要件 ID を併記する。要件 ID を持たない要件は、内容で対応を示す。

### 1.2 構成

- 画面層: ブラウザ上で動作する画面。教員用、教務用、保護者用に分ける。
- 業務層: 出欠管理、成績管理、通知表出力の各機能を提供する。
- データ層: 関係データベースに出欠・成績・在籍の情報を保存する。
- 認証: 学校の統合認証基盤と連携し、利用者の役割（教員、教務主任、事務職員、保護者）を判定する。

| SC02 | 欠課時数登録画面 | 教科担当教員 | REQ-003 |
| SC03 | 連続欠席一覧画面 | 教務主任 | REQ-004 |

### 2.2 画面の仕様

- SC01 は、学級の生徒を座席表の順に一覧し、生徒ごとに出欠区分を選択させる。初期値は出席とする。
- SC01 の下部に「一括登録」ボタンを置き、押下で学級全員の出欠を一度に保存する。
- SC01 は、警告対象の生徒の行に警告マークを表示する。
- SC02 は、授業の日付・時限・教科を選択し、欠課した生徒と時間数を入力させる。
- SC03 は、欠席が連続3日に達した生徒を、学級・氏名・連続日数とともに表示する。
- SC04 は、生徒ごとの得点入力欄と、CSV ファイルの取り込みボタンを備える。範囲外の得点は入力欄の下に赤字で示す。
- SC05 は、自動算出した評定を表示し、手動修正の際は理由の入力欄を必須として表示する。確定済みの評定は編集不可の表示とする。
- SC06 は、生徒を選択して通知表を PDF で出力する。出力前に内容のプレビューを表示する。
- SC07 は、保護者が自分の子の出欠状況と評定を表示する。他の生徒は選択肢に出さない。
- SC08 は、学級ごと・月ごとの出席率を表で表示する。
- 全画面の共通として、画面右上に利用者名とログアウトボタンを置く。

## 3 機能設計

### 3.1 出欠管理機能

- 出欠登録（REQ-001）: 担任教員は、授業日ごとに自学級の全生徒の出欠を登録する。他学級の生徒は登録できない。
- 出欠区分（REQ-002）: 出欠区分は、出席、欠席、遅刻、早退、公欠、忌引の6種とし、データ設計のコード値で管理する。
- 遅刻の換算: 遅刻が3回に達した場合、欠席1回として欠課時数の集計に換算する。
- 欠課時数の登録（REQ-003）: 教科担当教員は、授業ごとに欠課した生徒と欠課時数を登録する。
- 登録内容の修正: 出欠登録の修正は、登録日から30日以内であれば担任教員が行える。30日を超える修正は教務主任の承認を要する。
- 連続欠席の抽出（REQ-004）: 毎日6時に、欠席が連続3日に達した生徒を抽出し、教務主任が連続欠席一覧画面で確認できるようにする。
- 警告対象の判定（REQ-011）: 欠課時数が年間の総授業時数の3分の1を超えた生徒を警告対象とし、出欠登録画面に警告マークを表示する。
- 出席率の集計（REQ-013）: 学級ごとの出席率を月次で集計し、出席率集計画面に一覧で表示する。

### 3.2 成績管理機能

- 得点入力: 教科担当教員は、定期テストの得点を生徒ごとに入力する。得点は0以上100以下の整数で、範囲外は保存せずエラーを返す。
- CSV 取込（REQ-006）: 得点を CSV ファイルから取り込む。形式は外部インタフェースに定める。
- 評定の換算: 点数を評定へ換算する規則は、データ設計の換算表に従う。
- 評定の自動算出（REQ-007）: 2回の定期テスト得点の平均を求め、換算表に当てはめて学期末評定を自動算出する。
- 評定の手動修正（REQ-008）: 教科担当教員は、自動算出した評定を手動で修正できる。修正時は理由の入力を必須とし、空欄では保存しない。
- 評定の確定: 評定を確定した後は、教科担当教員は変更できない。確定後の変更は教務主任のみが行える。
- 席次の算出: 学級内の席次を算出し、保護者閲覧画面に各教科の席次として表示する。

### 3.3 通知表出力機能

- 通知表の出力（REQ-009）: 担任教員は、生徒ごとの通知表を PDF で出力する。
- 記載項目（REQ-010）: 学期末評定、欠課時数、出欠区分ごとの回数を記載する。
- 帳票名: 出力した PDF の表題は「レポートカード」とし、学期名と生徒氏名を付す。
- 欠課時数の記載: 欠時数は教科ごとの時間数と合計を記載する。

### 3.4 閲覧・在籍管理機能

- 保護者の閲覧（REQ-012）: 保護者は、自分の子の出欠状況と評定を保護者閲覧画面で閲覧する。出欠登録の内容は、登録後に閲覧画面へ反映する。
- 閲覧範囲の制限: 保護者は、登録された自分の子以外の生徒の情報を閲覧できない。範囲外の生徒番号を指定した要求は拒否する。
- 在籍情報の管理: 事務職員は、生徒の転出入に応じて、在籍情報を登録・変更する。

### 3.5 権限表

| 役割 | 出欠登録 | 評定の入力 | 確定後の変更 |

## 5 外部インタフェース

### 5.1 CSV 取込

- 文字コードは UTF-8、1行目はヘッダとする。
- 列は、生徒番号、教科コード、試験種別、得点の順とする。
- 1ファイルの上限は1000行とする。誤りのある行は一覧で示し、その行は取り込まない。

### 5.2 PDF 出力

- 用紙は A4 縦とし、1生徒につき1ファイルを出力する。

### 5.3 統合認証

- 学校の統合認証基盤と SAML で連携する。利用者の役割は認証応答の属性から取得する。

## 6 非機能設計

- 性能（REQ-014）: 1学級40名の出欠は1回の処理で一括保存し、操作から3秒以内に完了させる。出欠テーブルに生徒番号と授業日の索引を設ける。
- 可用性（REQ-015）: 授業日の7時から18時の間は利用できるようにし、月間稼働率99.5%以上を目標とする。稼働状況は常時監視する。
- セッション管理: 無操作の状態が60分続いた場合、自動的にログアウトする。
- 監査（REQ-016）: 出欠と成績の変更履歴を、変更者・日時・変更前後の値とともに5年間保存する。
- 操作性: 全画面を共通の部品と配置で構成し、出欠登録画面の並びは紙の出席簿に合わせる。
- バックアップ（REQ-017）: データを日次でバックアップし、30日分を保存する。
