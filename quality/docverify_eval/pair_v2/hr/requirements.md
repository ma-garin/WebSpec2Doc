# 人事評価システム 要件定義書

## 1. 目的・範囲

### 1.1 目的

本書は、社内の人事評価業務のうち目標設定と期末評価を電子化する「人事評価システム」の要件を定める。
紙とスプレッドシートで行っている目標の登録・承認・評価の流れを一本化し、評価の抜け漏れと集計作業を減らすことを目的とする。

### 1.2 範囲

- 対象: 正社員約800名の目標設定、自己評価、評価者評価、最終承認、結果通知
- 対象外: 給与・賞与の計算、昇格判定、採用、360度評価
- 評価は半期ごと（上期・下期）に実施する
- 利用は社内の端末からの接続に限り、社外からの接続は対象としない

### 1.3 利用者

- 被評価者: 評価を受ける社員
- 評価者: 被評価者の直属の上長
- 承認者: 評価者の上長（部長職）
- 人事担当者: 制度の運用と集計を担う人事部門の担当者

## 2. 用語

| 用語 | 意味 |
|---|---|
| 評価期間 | 目標設定と評価の対象となる半期（上期または下期） |
| 目標 | 被評価者が評価期間に達成を目指す個別の成果項目 |
| ウェイト | 目標ごとの重み。百分率で表す |
| 被評価者 | 評価を受ける社員 |
| 評価者 | 被評価者の目標を承認し、期末に評価する直属の上長 |
| 承認者 | 評価者の評価結果を最終承認する部長職 |
| 総合評価ランク | 目標ごとの評価から算出する最終的な評価区分（S・A・B・C・D） |
| 差戻し | 提出された内容を修正のため提出者へ戻すこと |

## 3. 機能要件

### 3.1 目標設定

- REQ-001: 被評価者は、評価期間の開始日から14日以内に、目標を3件以上5件以下登録できること。
  - 補足: 目標ごとに名称と内容を入力する。

- REQ-002: 被評価者は、目標ごとにウェイトを整数で設定できること。1評価期間の目標のウェイト合計は100%でなければならない。
  - 補足: 合計が100%でない場合は提出できない。

- REQ-003: 被評価者は、登録した目標を評価者へ提出できること。提出後は被評価者が編集できないこと。

- REQ-004: 評価者は、提出された目標を承認または差戻しできること。差戻しの場合はコメントの入力を必須とする。
  - 補足: 差戻された目標は被評価者が修正して再提出できる。

人事担当者は、評価期間ごとに目標登録の締切日と評価の締切日を設定できること。上期は4月1日から9月30日、下期は10月1日から翌年3月31日とする。

- REQ-005: 目標の承認後に変更が必要になった場合、被評価者は変更申請を出せること。評価者が承認した時点で変更が反映される。

評価者は、自分が担当する被評価者の目標の提出状況を一覧で確認できること。

### 3.2 期末評価

- REQ-006: 被評価者は、自己評価として目標ごとに1から5の5段階の点数とコメントを入力できること。

- REQ-007: 評価者は、被評価者の自己評価を確認したうえで、目標ごとに1から5の5段階の点数とコメントを入力できること。

- REQ-008: システムは、評価者の点数とウェイトから加重平均を算出し、総合評価ランクを自動で判定すること。ランクの基準は下表のとおりとする。

| 総合評価ランク | 加重平均 |
|---|---|
| S | 4.5以上 |
| A | 3.5以上4.5未満 |
| B | 2.5以上3.5未満 |
| C | 1.5以上2.5未満 |
| D | 1.5未満 |

評価の締切日を過ぎた評価は、人事担当者が解除しない限り編集できないこと。

- REQ-009: 承認者は、評価者の評価結果を確認し、最終承認または差戻しできること。
  - 補足: 差戻しの場合は評価者へ戻り、評価者が再度評価を提出する。

- REQ-010: 評価結果は、最終承認の後、被評価者へ速やかに通知すること。

- REQ-011: 評価者は、通知後の面談について、実施日と要旨を記録できること。

- REQ-012: 被評価者は、評価結果の通知から7日以内に、結果に対する異議を申し立てられること。申立ての内容は人事担当者が確認する。
  - 補足: 申立ての受付状況は被評価者が確認できる。

### 3.3 照会・運用

- REQ-013: 被評価者は、過去5期分の評価結果（総合評価ランクと目標ごとの点数）を照会できること。

人事担当者は、提出期限の3営業日前に、未提出の被評価者と評価者へ催促メールを送信できること。

人事担当者は、評価結果をCSVファイルで出力できること。

人事担当者は、組織変更があった場合に、被評価者の評価者を変更できること。

人事担当者は、目標と評価の一覧を、部署・評価期間・状態で絞り込めること。

## 4. 非機能要件

- REQ-014: 一覧画面の表示は、同時利用者300名の条件で3秒以内に完了すること。

- REQ-015: 稼働時間は平日の7時から22時とし、この時間帯の稼働率は99.5%以上であること。

- REQ-016: 評価データは、本人・担当の評価者・承認者・人事担当者だけが閲覧できること。通信はTLS1.2以上で暗号化すること。

評価の登録・変更・承認の操作ログを3年間保存すること。

画面は誰にとっても分かりやすく、使いやすいこと。

データのバックアップを毎日1回取得し、5世代を保持すること。

## 5. 制約

- 認証は既存の社内認証基盤（SSO）を利用し、独自のパスワードは持たない
- 社員情報は人事システムの社員マスタを正とし、本システムでは更新しない
- 稼働環境は国内のクラウドとする
- 本システムの利用開始は、次の上期の開始日までとする
- 評価データは、退職後も3年間は削除しない
- 画面は日本語のみとし、多言語対応は行わない
- 利用端末はPCのブラウザとし、スマートフォン専用の画面は作らない
- 本システムで扱う評価の対象は、正社員に限る
