## 事例（製品ごと）

### Jama Connect（Word/Excel Import）
- 画面の型: 取り込みウィザード。ファイル選択 → 範囲指定 → フィールド対応付け → 表の扱い選択。事前に Word 側で見出しスタイルとキーワードを整える。
- 良い点: 見出し階層が項目の入れ子になる。表を「1 行 1 項目」か「1 表 1 項目」か選べる。事前に「必要な情報の置き場（フィールド）を決める」手順を勧めている。
- 悪い点: 取り込み前に Word を整える作業が要る。目次は取り込めない。プレビュー・検証・完了表示の記述は確認できなかった（未確認）。

### Polarion（Import Wizard / Excel・Word インポート）
- 画面の型: Excel 列を作業項目のフィールドに対応付ける取り込み。Word は段落スタイルで項目・属性を判別する。
- 良い点: 検索結果の要約によると、スタイルで型を自動判別する考え方（Word）。複数値フィールドの対応可否を明記。
- 悪い点: 公式の手順ページ本文は取得できなかった（リダイレクト先が目次のみ）。ウィザードの画面構成・エラー表示は未確認。古い Word Import UI 拡張は非推奨で、大きい画像に問題があると記載。

### Microsoft Purview / SharePoint Syntex（自動分類・人の確認）
- 画面の型: 分類器が一致した文書の一覧 → 文書を開き「文脈の要約」タブで一致箇所を見て「Match / Not a match」を選ぶ。ラベル適用は、まず適用せず結果だけ出す「シミュレーション」で確認してから有効化。
- 良い点: 一覧の概要に「一致数・不一致数・フィードバック済み数」を出す。判断を取り消す「Withdraw feedback」がある。本適用前に試走できる。
- 悪い点: 確認は管理者向けの探索画面で、一般利用者の取り込み導線ではない。カスタム分類器の再学習は不可（作り直し）。シミュレーションは 1 サイトあたり約 100 ファイルの標本（第三者記事。未検証）。Syntex の確信度の閾値・確認フローは Microsoft 公式では確認できず、第三者ブログの記述のみ。
- 出典: https://learn.microsoft.com/en-us/purview/data-classification-increase-accuracy （見た）／ https://practical365.com/hands-on-sharepoint-syntex-part-2/ （検索要約のみ）／ https://mc.merill.net/message/RM560707 （検索要約のみ。ロードマップ項目で開発中）

### Box AI（メタデータ抽出の確認 UI）
- 画面の型: プレビュー画面右のメタデータパネルに抽出値を並べ、各値に確信度（低/高）を併記。低確信度の項目に目印。
- 良い点: 低確信度だけ目印が付き、全項目を確認しなくてよい。「Accept」で即保存、編集すると「Edited」表示。値の根拠位置（bounding box）を持つ。
- 悪い点: 閾値の数値は非公開。既定は無効で、AI ユニットを追加消費。記事間で「score」と「level」の表記が揺れ、Box Extract ページでは「Coming soon」表記の検索結果もあり、提供状況は未確認。API の確信度は保存されず応答のみ。
- 出典: https://support.box.com/hc/en-us/articles/50863269944595-Confidence-scores-and-human-in-the-loop-review-for-Box-Preview （見た）／ https://developer.box.com/guides/metadata/confidence-level （検索要約のみ）

### Notion（Import）
- 画面の型: 取り込み元（アプリ/ファイル形式）選択 → 対象選択 → 保存先選択 → 必要なら列の対応付け → 開始。設定の Import 画面に「進行中/完了」タブ。
- 良い点: 入口が 3 つ（設定・スラッシュ・ページ内メニュー）。保存先を取り込み時に選べる。進行中/完了のタブで時間・状態・サイズを出す。制限（サイズ・件数）が明文化。
- 悪い点: 種類の格付けは無く、形式変換が中心。書式・コメント等は引き継がれず取り込み後の手直しが前提。失敗時は「形式を変える・分割する」といった一般的な助言で、原因別の表示は記述なし。
- 出典: https://www.notion.com/help/import-data-into-notion （見た）

### Google Drive（アップロードと整理）
- 画面の型: 「新規 → ファイルのアップロード」またはドラッグ＆ドロップで対象フォルダへ。分類はフォルダ配置が中心。
- 良い点: 入口が最短（ドラッグ＆ドロップ）。同名は改版扱い、「両方残す」も選べる。
- 悪い点: 公式ページに進捗表示・エラー文・再試行の記述なし（未確認）。種類や格付けを付ける仕組みは取り込み時に無い。

## 共通する成功パターン

1. 最初の 1 操作はファイルを渡すこと。ドロップ/選択を先頭に置く（Google Drive、Notion、Jama）。
2. 設定は「見出し/スタイル/表」という文書の既存構造を手掛かりに自動判別し、ユーザーに対応表を書かせない（Jama、Polarion）。
3. 取り込み前に「どの項目が必要か」を決めさせる（Jama の事前計画の勧め）。後から再取り込みを減らす。
4. AI の結果は全件でなく低確信度だけ目印を付けて人に見せる（Box）。確信度の高い項目の確認は省ける。
5. 人の操作は「承認」「編集」「不一致」の少数に絞り、押した結果を状態表示する（Box の Accepted/Edited、Purview の Match/Not a match）。
6. 本適用の前に試走して結果だけ見せる（Purview のシミュレーション）。取り消し操作を用意する（Withdraw feedback）。
7. 進行中/完了を一覧で再訪できる場所に残す（Notion）。一覧の先頭に一致数・不一致数などの集計を出す（Purview）。
8. 制限（サイズ・件数）と失敗時の次の行動を文面で明示する（Notion）。

## 本製品への適用案

1. 最初の画面は「文書をここに置く」だけ。置いた直後に AI が Tier1〜4（方針／決まりごと／仕様／メモ）の候補を付け、利用者は候補を見て直す。種別選択を先に聞かない（根拠: 1・2）。
2. 格付けの確認は低確信度のみ強調。各行に「候補 Tier・確信度（低/高の 2 段階）・根拠の文」を出し、操作は「合っている／直す」の 2 つに限る。高確信度は一括で確定できる（根拠: 4・5。Box 型。閾値は自前で決める必要がある）。
3. 登録前に試走表示を置く。「この内訳で登録します（Tier1: n 件…）」を見せ、確定後に検査へ進む。確定後の取り消し/再格付けも残す（根拠: 6。Purview 型）。
4. 取り込み一覧に進行状況（取り込み中・格付け待ち・検査中・完了）と集計（要確認 n 件）を残す。強調表示は確定後に課題のある文書だけに出し、一覧に戻って再訪できるようにする（根拠: 7）。
5. 空状態・失敗は次の行動を 1 行添える（例: 読めない形式は「対応形式の一覧」と「再アップロード」）。対応形式とサイズ上限を最初の画面に書く（根拠: 8）。
