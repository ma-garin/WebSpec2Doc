P3-3 Drift Check as Code（見積 0.5日）

狙い: 既存の --ci 機能が画面から見えていない。履歴・差分タブから 1 クリックでコピーできるようにする。

案 — 履歴・差分タブの末尾に追加
CI に組み込む

定期実行して、仕様が変わったらパイプラインを止める。差分があると exit code 1 で終了する。 

- name: 仕様ドリフト検知
  run: |
    python src/main.py --url https://example.com \
      --output output/example.com --ci
  # --ci は --compare --fail-on-drift を含み、
  # 機械可読サマリを stdout へ出す

出力の読み方: drift_detected が true のとき exit 1。 サマリは output/<domain>/drift_summary.json にも残る。

決めたいこと案
置き場所履歴・差分タブ（#rp-history）の末尾。差分を見た直後が「自動化したい」と思う瞬間のため
形式の切替GitHub Actions / シェル の2種。他CIは要望が出てから足す
URL・出力先表示中のドメインを埋め込む（コピーしてそのまま動く）
実装範囲UI のみ。--ci は src/main.py:177 に実装済みで変更不要

P2-5 テスト実行結果を設計へ還元（見積 1.5日・P2-4 依存）

狙い: 「設計したが検証していない」を画面上で区別する。

案 — 画面別設計の条件行に結果バッジ
Noテスト条件由来結果
1メールアドレスが未入力のとき、エラーを表示するemail検証済み
2メールアドレスが 255 文字を超えるとき、送信できないemail失敗
3パスワードが 8 文字未満のとき、エラーを表示するpassword未実行
4同意チェックが未選択のとき、送信できないagree対応なし

「対応なし」は、この条件が生成された時点で condition_id が無かったもの。 再生成すると紐付く。「失敗」と区別するため別のバッジにする。

契約変更の承認をお願いします。 条件とテストケースは現状独立に生成されており、両者を結ぶ安定 ID が無い。 P2-4 では「画面＋由来した要素」で近似したが、実行結果の紐付けには不十分。
  • web/services/screen_test_design.py の条件に condition_id を付与する
  • testcase_table_store 側に 由来 condition_id を保存する
  • 既存 JSON には ID が無い → 「対応なし」表示にして、再生成で付与（後方互換を壊さない）
決めたいこと案
バッジの区分検証済み / 失敗 / 未実行 / 対応なし の4種
「対応なし」を出す理由ID 未付与を「未実行」に混ぜると、実行し忘れなのか紐付け漏れなのか区別できない
結果の出所既存の testcases/run_result.json（save_run_result が書く）
受入1件実行 → 該当条件行に結果が反映（Playwright 実機）
