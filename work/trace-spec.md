# トレーサビリティ画面 実装仕様（System 06 / #setcheck）

## 目的
いまの #setcheck 画面（templates/docverify/_r3.html・static/js/docverify-r3.js・static/css/docverify-r3.css）を、商用品質の 1 画面に作り直す。既存 API（web/routes/doc_verify_r3.py）とデータはそのまま使う。API・Python は変更しない。

## 見本
static/mock/system06/sidebar/index.html の案 4（上段の流れ図）と案 3（直すべきことの一覧）。この 2 つを縦に組み合わせる。見本の CSS の値（余白・角丸・色の意味）を踏襲。

## 画面構成（上から）
1. ヘッダー行: 左に結論 1 文（例「要件 8 件のうち 3 件にテストがありません。孤立 2 件・矛盾候補 1 件を確認してください」。データから生成）、右に主ボタン「検査を実行」・副ボタン「Excel で出力」（既存 xlsx 出力）・「文書を追加」。
2. 文書の流れ図: 要件 → 設計 → テスト の 3 カード（版・件数・取り込み日時・「差し替え」）、矢印上にカバー率（％、大きく）と欠落件数（赤）。未登録の種別はカードを破線にし「この種別の文書を登録」ボタン。
3. 直すべきことの一覧（主役）: 左に種別フィルタ（設計なし／テストなし／孤立／矛盾候補／重複候補、件数付きチェック）、右に課題カード（種別ピル・対象 ID・根拠の本文抜粋・根拠（どの規則/どの語が一致したか）・確信度があれば表示・アクションボタン）。矛盾/重複候補は既存の判定 API（「矛盾」「重複」「問題なし」）をボタンに割り当てる。
4. 「すべてのつながりを見る」: 折りたたみで既存の追跡表（要件・設計・テスト 3 列、欠落セルは赤い「なし」）。ID 書式の選択もここ。
5. 「規則と組織の語彙」ブロックはこの画面から外さず、最下部の折りたたみ「検査の設定」に移す（検証観点画面は別セッション担当なので移設しない）。
